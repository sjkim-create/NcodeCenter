## 1. 기능 개요

**App Key = 계정과 연동되는 키.** 온라인 편집툴(Caster U)·폼솔루션·SDK에서 사용하며, **계정(ID/PWD)과 SOBP 범위를 한 번에 발급**한다. 계정이 없으면 발급할 수 없으므로, 신규 고객사는 이 화면에서 계정 등록과 키 발급을 한 흐름으로 처리한다.

발급할 때 **사용처(연동 서비스)** 를 지정한다. 계정은 **그 서비스에서만 로그인**되며, 각 서비스는 자기 계정만 인증·관리한다.

| 항목 | 내용 |
|---|---|
| 권한 | STAFF / ADMIN |
| 진입 | `TKT-01` 좌측 발급 메뉴 [계정 + App Key] |
| 선행 조건 | 고객사가 `MEM-01`에 등록되어 있고 `SOB-02`로 SOBP를 할당받았을 것 |
| N Key와의 차이 | N Key는 계정 불필요(오프라인). **App Key는 계정 필수(온라인·SDK)** |

## 2. 화면 흐름 (Flow)

```
TKT-01 발급 메뉴 [계정 + App Key]
   └─▶ TKT-03
         ① 계정 ─ 회사(고객사) 선택
         │        ├─ 기존 계정 있음 ─▶ 계정 선택
         │        └─ 기존 계정 없음 ─▶ 신규 계정 입력(ID·PWD·NAME·ADDR·HOMEPAGE)
         ② 할당된 SOBP 범위 선택   ─(범위 없음)─▶ SOB-02 로 이동해 할당
         ③ 발급 조건(사용처·만료) 입력
         └─ [계정 등록 + App Key 발급] / [App Key 발급]
                  └─▶ 발급 결과(계정 ID·PWD·App Key) 표시
                  └─▶ 서비스 DB 목록에 계정·키 추가
                  └─▶ TKT-04 발급 목록 기록 · LOG-01 활동 로그 기록
```

## 3. 정책

| 정책 | 이 화면에서의 적용 |
|---|---|
| `P-15` 티켓 = N Key / App Key | **App Key = 계정 연동 키.** 계정 없이는 발급 불가 |
| `P-05` 무겹침 | 키는 **이미 할당된 SOBP 범위**에만 연결된다. 범위를 직접 타이핑하지 않는다 |
| `P-02` 코드 종류 N/G | PatternType은 선택한 범위에서 자동 결정 |
| `PC-002` 내부 직원 전용 | 고객이 직접 계정을 만들지 않는다. **직원이 대신 등록**한다 |
| `P-13` 사용 서비스 | 계정·App Key는 **사용처(연동 서비스)** 를 갖는다. 계정은 그 서비스에서만 로그인되고, 다른 서비스에서는 인증되지 않는다 |
| 요구사항 #1 | 만료일(또는 무제한)로 기간 제한 |

## 4. 사용법

화면은 **카드 한 장** 안에 ① 계정 → ② 할당된 SOBP 범위 → ③ 발급 조건 이 위에서 아래로 이어진다.
맨 아래에 **서비스 DB · 계정 & App Key** 목록이 붙는다.

### 4.1 ① 계정

회사(고객사)를 선택하면 **그 고객사에 이미 등록된 계정이 있는지에 따라 화면이 자동으로 갈린다.**

| 계정 칸 상태 | 화면 | 화면 번호 |
|---|---|---|
| 고객사 미선택 | 회색으로 **고객사를 먼저 선택** | S1 |
| 등록된 계정 없음 | 초록으로 **등록된 계정 없음 → 신규 등록** · 아래에 계정 입력 항목이 나온다 | S2 |
| 등록된 계정 있음 | 계정 목록에서 선택 · 신규 입력 항목은 숨겨진다 | S3 |
| 목록에서 **＋ 신규 계정 등록** 선택 | 계정 입력 항목이 다시 나온다 | S4 |

**고객사를 고르면 함께 일어나는 일**

| 항목 | 동작 |
|---|---|
| ADDR(주소) | 고객사 주소가 **자동 입력**된다(수정 가능) |
| 계정 | 등록된 계정이 있으면 **첫 계정이 자동 선택**, 없으면 신규 등록 모드 |
| SOBP 범위 · 발급 결과 | 초기화된다 |

**계정 입력 항목** (신규일 때만)

| 항목 | 필수 | 규칙 |
|---|---|---|
| 회사정보(고객사) | ✔ | `MEM-01` 등록 고객사 |
| NAME(담당자/사용자명) | — | |
| ID (EMAIL) | ✔ | **이메일 형식**이어야 한다. 이미 등록된 ID는 쓸 수 없다 |
| PWD | ✔ | 비밀번호를 요청하지 않는 고객사(SDK)는 **[임의 생성]** 으로 자동 생성 |
| ADDR(주소) | — | 고객사 주소가 자동 입력되며 수정 가능 |
| HOMEPAGE | — | |

### 4.2 ② 할당된 SOBP 범위 (S5 · S6)

고객사가 할당받은 범위 목록에서 하나를 선택한다. 목록은 **접혀 있고 클릭하면 펼쳐지며**, 범위마다 **순번 + S · O · B · P 칩**으로 보여준다. 선택한 항목은 강조되고 `✓` 가 붙는다. (`TKT-01`과 같은 방식)

선택 결과가 키에 연결될 **Section · Owner · Book 범위 · Page 범위 · PatternType**이 된다. 범위를 고르기 전에는 **발급 버튼이 비활성**이다.

| 상황 | 화면 | 화면 번호 |
|---|---|---|
| 고객사 미선택 | **고객사를 먼저 선택하세요.** | S1 |
| 할당 범위 없음 | **이 고객사에 할당된 SOBP 범위가 없습니다.** → `SOB-02`에서 할당 | S6 |
| 목록 펼침 | 순번 + S/O/B/P 칩 · 선택 항목에 `✓` | S5 |

### 4.3 ③ 발급 조건

| 항목 | 필수 | 규칙 | 화면 |
|---|---|---|---|
| 사용처 (연동 서비스) | ✔ | **CasterN**(Caster U 웹 편집툴 · 계정 로그인) / **폼솔루션**(폼솔루션 서비스 · 계정 로그인) / **SDK 연동**(id/pwd + SOBP 직접 사용). 기본값 **CasterN** | S7 |
| 만료일(기간) | — | 기본은 **무제한**이며 이때 날짜 입력은 흐리게 잠긴다. 체크를 풀면 달력으로 날짜를 고른다 | S8 |

> 계정은 **선택한 서비스에서만 로그인**된다. 서비스는 자기 계정만 관리·인증한다. `P-13`

### 4.4 발급 (S9)

버튼 라벨은 상황에 따라 바뀐다 — 신규 계정이면 **[계정 등록 + App Key 발급]**, 기존 계정이면 **[App Key 발급]**. 범위를 고르기 전에는 눌리지 않는다.

발급이 끝나면 결과 영역에 **계정 ID · PWD · App Key**가 표시되고, **[전체 복사]** 로 세 값을 한 번에 복사해 고객사에 전달할 수 있다. 신규 계정이었다면 입력 항목이 비워지고 **방금 만든 계정이 선택 상태**가 된다.

### 4.5 서비스 DB · 계정 & App Key (S11)

화면 하단에서 선택한 고객사의 **계정별 App Key 목록**을 확인·정리한다. 제목 옆에 **{고객사} (계정 {n})** 이 함께 표시된다.

| 줄 | 표시 항목 |
|---|---|
| 계정 | 고객사명 · **ID** · NAME · **사용처 배지** · **App Key {n} 배지** · [삭제] |
| App Key | 키 앞부분 · **{코드종류} S{n}/O{n}/B{시작}~{끝} 배지** · 사용처 · **유효 {기한}** · 생성 일시 · [키 삭제] |

| 동작 | 결과 | 화면 |
|---|---|---|
| 사용처 배지 | 이 계정이 로그인할 수 있는 서비스. 값이 없는 과거 계정은 **미지정**(빨강)으로 표시된다 | S11 |
| 계정 [삭제] | 확인창 → 계정과 **연동된 App Key가 함께 삭제**된다 | S12 |
| 키 [키 삭제] | 해당 App Key만 삭제(확인창 없음) | S11 |

| 목록이 빌 때 | 문구 | 화면 |
|---|---|---|
| 고객사 미선택 | **고객사를 선택하세요.** | S1 |
| 계정 없음 | **{고객사}에 등록된 계정이 없습니다.** | S2 |

## 7. 미결 · 협의

- [ ] **비밀번호 전달 방식** — 현재 화면 표시·복사. 메일 발송 등 안전한 전달 경로 필요 여부
- [ ] **키 회수(폐기)** — 삭제 외에 "정지/만료 처리" 상태가 필요한지
- [ ] 계정 1개에 App Key 여러 개를 허용하는 현재 방식의 **상한** 필요 여부
- [ ] **사용처 변경**(예: CasterN → 폼솔루션) 절차 — 현재는 계정 재등록. 변경 시 기존 App Key 처리 방식 확정 필요
- [ ] 서비스 측 **인증 연동 방식** — 서비스가 계정·App Key를 조회하는 API 규격 (개발팀 협의)
- [ ] 사용처가 없는 **기존 계정(미지정)** 의 일괄 지정 방법
