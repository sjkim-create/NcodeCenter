## 1. 기능 개요

`TKT-03` 계정 목록에서 열리는 **두 화면**이다.

| 화면 | 주소 | 하는 일 |
|---|---|---|
| **계정 등록** | `/tickets/account/new` | ① 계정 정보 → ② 사용처·권한 → ③ App Key(선택) 를 입력하고 **[계정 추가]** |
| **계정 상세·수정** | `/tickets/account/{email}` | ①② 를 고쳐 **[저장]**, ③에서 이 계정의 **App Key 발급·삭제** |

| 항목 | 내용 |
|---|---|
| 권한 | STAFF / ADMIN |
| 진입 | `TKT-03` 의 **[＋ 계정 추가]** / **ID(email)·[상세]** |
| 선행 조건 | 고객사가 `MEM-01`에 등록. **App Key까지 발급하려면** `SOB-02`로 SOBP를 할당받았을 것 |

> **App Key 발급은 선택이다.** 계정만 등록해 두고, 키는 나중에 상세 화면에서 붙일 수 있다 `PC-031`.

## 2. 화면 흐름 (Flow)

```
TKT-03 계정 목록
   ├─ [＋ 계정 추가] ─▶ TKT-06 등록
   │      ① 계정 정보(고객사·NAME·ID·PWD·ADDR·HOMEPAGE)
   │      ② 사용처(연동 서비스) + CasterN 권한 7종
   │      ③ App Key 발급 (선택) ─(체크)─▶ 할당된 SOBP 범위 + 만료일
   │                                    └─(범위 없음)─▶ SOB-02 로 이동해 할당
   │      └─ [계정 추가] ─▶ TKT-03 목록에 노출 (+체크 시 App Key 동시 발급)
   │
   └─ ID(email)·[상세] ─▶ TKT-06 상세·수정
          ├─ [저장]          ─▶ 계정 정보·사용처·권한 반영
          ├─ [App Key 발급]  ─▶ 키 생성 → 서비스 DB 등록 → TKT-04 · LOG-01 기록
          ├─ [키 삭제]       ─▶ 해당 App Key만 삭제(확인창 없음)
          └─ [계정 삭제] ─(확인창)─▶ 계정 + 연동 App Key 삭제 → TKT-03
```

## 3. 정책

| 정책 | 이 화면에서의 적용 |
|---|---|
| `PC-031` 계정 화면 분리 · 권한 | 등록·수정을 목록에서 분리. **CasterN 권한 7종**을 계정마다 지정. **App Key 발급은 선택** |
| `PC-029` 고객사당 계정 수 | 제한 없음. ID(email)만 전체에서 **유일** |
| `PC-002` 내부 직원 전용 | 고객이 직접 만들지 않고 **직원이 대신 등록**한다 |
| `P-13` 사용 서비스 | 계정은 **선택한 서비스에서만 로그인**된다. 사용처를 바꾸면 연동 App Key의 사용처도 함께 바뀐다 |
| `P-05` 무겹침 | App Key는 **이미 할당된 SOBP 범위**에만 연결된다. 범위를 직접 타이핑하지 않는다 |
| `P-02` 코드 종류 N/G | PatternType은 선택한 범위에서 자동 결정 |

## 4. 사용법

### 4.1 ① 계정 정보 (S1)

| 항목 | 필수 | 규칙 | 수정 화면 |
|---|---|---|---|
| 회사정보(고객사) | ✔ | `MEM-01` 등록 고객사. 고르면 **ADDR이 자동 입력**된다 | **잠금**(변경 불가) |
| NAME(담당자/사용자명) | — | | 수정 가능 |
| ID (EMAIL) | ✔ | **이메일 형식** · 이미 등록된 ID는 쓸 수 없다 | **잠금**(키 연동 기준값) |
| PWD | ✔ | 비밀번호를 요청하지 않는 고객사(SDK)는 **[임의 생성]** 으로 10자리 자동 생성 | 수정 가능 |
| ADDR(주소) | — | 고객사 주소 자동 입력 · 수정 가능 | 수정 가능 |
| HOMEPAGE | — | | 수정 가능 |

### 4.2 ② 사용처 · 권한 (S2 · S3 · S4)

| 항목 | 필수 | 규칙 | 화면 |
|---|---|---|---|
| 사용처(연동 서비스) | ✔ | **CasterN**(기본) / **폼솔루션** / **SDK 연동** | S1 |
| CasterN 권한 | — | 아래 **7종**을 **개별 또는 모두** 선택. 기본값은 **모두 선택(7/7)** | S2 · S3 |

**CasterN 사용자 권한 7종** `PC-031`

| # | 권한 | 설명 |
|---|---|---|
| 1 | 프로젝트 생성 | 편집 프로젝트를 새로 만든다 |
| 2 | 심볼 편집 | 심볼(코드 영역) 편집 |
| 3 | 리소스 편집 | 음원·이미지 등 리소스 편집 |
| 4 | Ncode PDF 내보내기 | Ncode가 입혀진 PDF 출력 |
| 5 | NCP2 내보내기 | NCP2 파일 내보내기 |
| 6 | App용 패키지 내보내기 | App에서 쓰는 패키지 내보내기 |
| 7 | App 페이지 설정 | App 페이지 구성·설정 |

| 동작 | 결과 | 화면 |
|---|---|---|
| 권한 카드 클릭 | 개별 on/off · 선택된 카드는 파랗게 강조 | S3 |
| [모두 선택] / [모두 해제] | 7개 일괄 · 선택 수에 따라 라벨이 바뀐다 | S2 |
| 선택 수 표시 | **선택 {n} / 7** | S2 |
| 사용처 ≠ CasterN | 권한 칸이 안내로 잠긴다 — **사용처가 CasterN 일 때만 권한을 지정합니다.** 저장 시 권한은 비워진다 | S4 |
| 권한 0개 저장 | 허용. 목록에는 **미지정**(빨강)으로 표시된다 | S2 |

### 4.3 ③ App Key 발급 — 선택 (S5)

등록 화면에서는 **[이 계정에 App Key도 함께 발급합니다]** 체크박스로 켠다. 체크하면 **할당된 SOBP 범위**와 **만료일**이 나온다.

| 항목 | 규칙 |
|---|---|
| 할당된 SOBP 범위 | 접힘/펼침 목록에서 하나 선택. 순번 + **S · O · B · P 칩**, 선택 항목에 `✓`. 범위 없으면 `SOB-02`에서 할당 |
| 만료일(기간) | 기본 **무제한**(날짜 잠김). 체크를 풀면 달력으로 지정 |
| 미체크 시 | **계정만** 등록된다. 키는 상세 화면에서 나중에 발급 |

### 4.4 [계정 추가] (S1 · S5 · S6)

버튼을 누르면 계정이 등록되고 **`TKT-03` 목록으로 돌아간다**. App Key를 함께 발급했다면 계정 등록과 키 발급이 **한 번에** 처리되고 `TKT-04` 발급 목록·`LOG-01` 활동 로그에 기록된다.

### 4.5 상세 · 수정 (S7)

| 영역 | 내용 |
|---|---|
| 머리말 | **계정 상세 · 수정** + ID(email) + 고객사 배지 + **[목록]** |
| ① 계정 정보 | ID·고객사는 잠금, 나머지는 수정 |
| ② 사용처 · 권한 | 사용처 변경 시 **연동된 App Key의 사용처도 함께** 바뀐다 |
| [저장] | **계정 정보가 저장되었습니다.** |
| [계정 삭제] | 확인창 → 계정 + 연동 App Key 삭제 → `TKT-03` |
| ③ App Key | 이 계정의 키 목록(키 앞부분 · 코드 범위 배지 · 사용처 · 유효 기한 · 생성 일시 · [키 삭제])과 **[App Key 발급]** |

### 4.6 상세 — App Key 발급 (S8)

범위를 고르고 **[App Key 발급]**(범위 선택 전에는 비활성) → 결과 영역에 **계정 ID · PWD · App Key** 가 나오고 **[전체 복사]** 로 세 값을 한 번에 복사한다. 키는 아래 목록에 줄로 추가된다.
