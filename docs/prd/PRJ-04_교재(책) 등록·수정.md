## 1. 기능 개요

교재(책) 1권의 **편집 내역과 정산 근거를 입력**하는 화면. **등록과 수정이 같은 화면**이며 진입 방법으로 모드가 갈린다.

| 진입 | 모드 | 주소 | 화면 제목 |
|---|---|---|---|
| `PRJ-03`의 **[＋ 교재(책) 추가]** | 등록 | `/projects/editing/{owner}/book/new?c={고객사}` | 교재(책) 추가 |
| `PRJ-03`의 **교재 행 클릭** | 수정 | `/projects/editing/{owner}/book/{idx}?c={고객사}` | 교재(책) 편집 수정 |

> **주소의 `?c={고객사}`** `PC-045` — **owner 번호는 여러 고객사가 함께 쓸 수 있다**(공유·커먼 코드, 같은 번호를 쓰는 별개 고객사). owner 만으로 찾으면 **다른 고객사의 교재**가 열리므로 고객사명을 함께 넘긴다. 기본 좌표(S/O)와 교재 목록·저장 위치가 모두 이 고객사 기준으로 정해진다.

> **모달이 아니라 별도 페이지**다. 이 화면에서는 편집 상세의 **목록·요약·필터를 감추고** 이 폼만 보여준다. 다만 **고객사 머리말은 유지**되어 어느 고객사의 교재인지 맥락이 남는다.

여기서 입력한 **페이지 수와 심볼·기능 수량이 곧 청구액**이 되므로, 편집팀 작업 기록이자 정산 입력 화면이다.

> **교재 = 내부 편집 기록** `PC-283` — 내부 편집팀이 한 작업의 편집량 · 심볼 수 · 단가 등 **작업 · 정산 정보를 집계하는 관리 기록**이다. 서비스 티켓(서비스 이용 권한)의 하위 항목이 아니며, 마스터 계정이 고객사 코드로 **대행 편집**한 경우에도 교재를 남기되 서비스 티켓을 따로 만들지 않는다. 교재는 casterN 연동으로 **자동으로 만들어지고 갱신**된다(§4.11).

| 항목 | 내용 |
|---|---|
| 권한 | STAFF / ADMIN |
| 대상 단위 | 교재(책) 1권 = S/O/B 좌표 1개 |

## 2. 화면 흐름 (Flow)

```
PRJ-03
  ├─ [＋ 교재(책) 추가] ─▶ PRJ-04 (등록)
  └─ 교재 행 클릭 ───────▶ PRJ-04 (수정)
                              ├─ 진행 상태 변경(완료 ⇄ 진행중)
                              ├─ [교재 삭제] ─ 확인 ─▶ PRJ-03 목록에서 제거
                              ├─ [목록] ────────────▶ PRJ-03 (입력값 저장 안 함)
                              └─ [저장] ────────────▶ PRJ-03 (목록·집계·청구액 갱신)
                                        └─▶ LOG-01 (등록=교재 추가 / 수정=교재 작업)
                                        └─▶ 공유 코드면 SOB-01 지도에 사용 고객사·편집 상태 반영
```

## 4. 사용법

### 4.1 진행 상태

| 상태 | 의미 |
|---|---|
| 진행중 | 편집 작업 중 (기본값) |
| 완료 | 작업 종료 — **내용 잠금** |
| 보류 | 중단·대기 |

- **완료로 바꾸려면 ncp2 최종수정 날짜가 있어야 한다.** 이 날짜는 casterN 에서 ncp2 를 내보내면 자동으로 채워진다 `PC-282`.
- 완료를 해제하면 그때의 ncp2 최종수정 날짜가 **이력으로 보관**되고(해제 시각·해제자 포함), 화면에서 확인할 수 있다.

### 4.3.1 casterN 연동 (자동) `PC-282` `PC-284`

**기본 정보 바로 아래** 묶음이다. 제목 옆에 **자동** 표시와 **ⓘ** 가 있고, 모든 칸이 **읽기 전용**이다(입력할 수 없다).

| 항목 | 채워지는 때 | 값 |
|---|---|---|
| 프로젝트명 (.nproj) | casterN 에서 **프로젝트를 저장**할 때 | 저장한 **.nproj 파일명** |
| ncp2 파일명 | casterN 에서 **ncp2 를 내보낼** 때 | 내보내기 때 **지정한 실제 파일명** — **갱신 판단 기준**(§4.11) |
| ncp2 파일 크기(byte) | ncp2 를 **저장 · 수정할 때마다** | 그 시점의 크기로 **계속 갱신** — 서버 저장 용량 파악용 |
| ncp2 최종수정 (완료 필수) | ncp2 를 **저장 · 수정할 때마다** | **파일의 수정일**로 계속 갱신(전달 가능 여부는 연동 개발과 확인) · **완료 처리의 선행 조건** |
| 편집 유형 | 교재가 처음 만들어질 때 | **유입 경로** — `casterN 마스터 계정` / `Resource Studio` `PC-284` |
| 최초 등록일 | 교재가 처음 만들어질 때 | **교재 생성 요청이 처음 들어온 날짜** — 옛 **발급일자(Ncode 발급일)** 를 대체한다 `PC-284`. 이후 전송에서 바뀌지 않는다 |

- 값이 아직 없으면 그 칸에 **미연동**.
- 칸이 좁아 값이 잘리면 마우스를 올려 전체를 본다.
- **ⓘ** 를 누르면 그 아래 말풍선: *casterN 에서 프로젝트를 저장하면 .nproj 파일명이 프로젝트명으로, ncp2 를 내보내면 그때 지정한 파일명이 ncp2 파일명으로 채워집니다. 같은 코드 · 같은 ncp2 파일명으로 다시 들어오면 이 교재가 최신 값으로 바뀝니다. 이 화면에서 고칠 수 없습니다.*
- 옛 수기 교재(이관분)의 발급일자 값은 **최초 등록일로 옮겨 보인다**.

### 4.4 심볼·기능 수량 (정산 근거)

**소리펜과 필기펜 입력 칸이 좌·우로 함께** 표시되지만, **[타입]이 정하는 쪽만 입력한다** `PC-091`. 각 항목은 **수량 × 단가**로 계산된다. (S1 · S8)

| 타입 | 소리펜 심볼 입력 | 필기펜 심볼 입력 |

| **필기펜** | **잠김** | **활성** |

- 잠긴 묶음은 **타입을 바꾸면 열린다**. 값은 지워지지 않는다.

- **편집·기능비(심볼)는 두 묶음을 합산**한다 — 옛 장부에 반대편 묶음으로 기록된 심볼이 있어 그대로 청구에 반영한다.

### 4.11 casterN 연동 규칙 — 수집 · 갱신 · 등록 실패 `PC-283` `PC-284` `PC-287`

교재는 casterN(과 Resource Studio)에서 **자동으로 들어와 만들어지고 갱신**된다. 이 화면은 들어온 교재를 확인하고 사람이 정하는 값(교재명 · 편집 방식 · 단가 · 할인 · 진행 상태 · 메모 등)을 채운다.

**① 수집 범위** `PC-283`

| 대상 | 수집 |
|---|---|
| casterN **마스터 계정**으로 한 작업 | ✔ |
| **Resource Studio** 에서 한 내부 편집 | ✔ |
| 고객사가 **자기 계정으로 직접 편집**한 작업 | ✕ — 내부 편집 실적이 아니다 |

**② 같은 교재 판단 · 갱신** `PC-284`

| 들어온 작업 | 처리 |
|---|---|
| **코드(S/O/B) + ncp2 파일명**이 기존 교재와 같다 | **그 교재를 최신 값으로 갱신** — 페이지 · 심볼 등을 고쳐 다시 보낸 경우 |
| 코드는 같고 ncp2 파일명이 다르다 | **별도 교재**로 만든다 — 같은 코드의 다른 작업(`PC-110`) |
| 처음 들어온 코드 · 파일명 | 새 교재 |

- ncp2 파일명은 공백 · 대소문자 · `.ncp2` 차이를 같은 파일로 본다.
- **NCP2 가 없는 필기펜 작업**의 같은 교재 판단 기준은 **미정**(§7).
- 회의 중 「같은 파일명 등록 거부」 안도 나왔으나, **기존 프로젝트를 고쳐 다시 보내는 작업을 지원하려고 갱신으로 정했다**.

**③ 항목별 연동 · 덮어쓰기** `PC-284`

| 항목 | 처음 만들 때 | 다시 전송될 때 |
|---|---|---|
| 교재명 | NPROJ 타이틀 → 없으면 NPROJ 파일명 | **유지**(여기서 고친 값) |
| 프로젝트명 · ncp2 파일명 · ncp2 파일 크기 · ncp2 최종수정 | 연동 값 | **연동 값으로 갱신** |
| 편집 유형 · 최초 등록일 | 연동 값(유입 경로 · 첫 요청 날짜) | 유지 |
| Start Page · Total Page | NPROJ 시작 페이지 · 프로젝트 페이지 수 | **연동 값으로 덮어쓴다** — 여기서 고친 값은 바뀐다(담당 결정) |
| 심볼 · 기능 수량 | 파일을 읽어 채운다 | **연동 값으로 덮어쓴다** |
| 펜 모델 · 발급인 | 공란(확인할 수 없으면) | 유지 |
| 편집 방식 · 단가 · 할인 · 진행 상태 · 업무 메모 · 산출물 | 비어 있음 / 단가는 **고객사 단가 → 없으면 기본 단가** `PC-027` | 유지 |

**④ 할당 범위 밖 코드 = 등록 실패** `PC-287`

casterN 에서 저장 · 내보내기로 교재가 들어올 때, **교재 코드(S/O/B)가 고객사의 SOBP 할당 범위 안인지** 확인한다.

| 조건 | 처리 |
|---|---|
| 코드가 어느 고객사의 SOBP 할당 범위 안이다 | 그 고객사의 교재로 등록 · 갱신 — **공용 코드는 그 Book 에 서비스 티켓을 받은 하위 고객사, 티켓이 없으면 상위 고객사** `PC-291` |
| 코드가 **어느 고객사의 할당 범위에도 없다** — Owner · Book 이 할당 밖 | **등록하지 않는다**(교재를 만들지 않는다). 실패를 casterN 에 돌려준다 |

- casterN 은 실패를 받으면 **알림창**으로 작업한 사람에게 확인을 요청한다 — *NcodeCenter 에 교재를 등록하지 못했습니다. S{s}/O{o}/B{b} 는 고객사에 할당된 코드 범위가 아닙니다. 코드(S/O/B)를 확인한 뒤 다시 저장하세요.*
- casterN 의 **파일 저장 · 내보내기 자체는 막지 않는다** — NcodeCenter 등록만 실패한다. 코드를 고쳐 다시 저장 · 내보내면 다시 등록을 시도한다.
- 실패 기록을 NcodeCenter 에도 남길지(활동 로그 등)는 **미정**(§7).
- 교재 소유 · 서비스 티켓의 교재 검사 · 기존 공용 코드 교재의 티켓 자동 발급은 `MEM-02` §4.11 `PC-291` `PC-292`.
