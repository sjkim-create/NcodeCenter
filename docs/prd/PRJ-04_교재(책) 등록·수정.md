## 1. 기능 개요

교재(책) 1권의 **편집 내역과 정산 근거를 입력**하는 화면. **등록과 수정이 같은 화면**이며 진입 방법으로 모드가 갈린다.

| 진입 | 모드 | 주소 | 화면 제목 |
|---|---|---|---|
| `PRJ-03`의 **[＋ 교재(책) 추가]** | 등록 | `/projects/editing/{owner}/book/new?c={고객사}` | 교재(책) 추가 |
| `PRJ-03`의 **교재 행 클릭** | 수정 | `/projects/editing/{owner}/book/{idx}?c={고객사}` | 교재(책) 편집 수정 |

> **주소의 `?c={고객사}`** `PC-045` — **owner 번호는 여러 고객사가 함께 쓸 수 있다**(공유·커먼 코드, 같은 번호를 쓰는 별개 고객사). owner 만으로 찾으면 **다른 고객사의 교재**가 열리므로 고객사명을 함께 넘긴다. 기본 좌표(S/O)와 교재 목록·저장 위치가 모두 이 고객사 기준으로 정해진다.

> **모달이 아니라 별도 페이지**다. 이 화면에서는 편집 상세의 **목록·요약·필터를 감추고** 이 폼만 보여준다. 다만 **고객사 머리말은 유지**되어 어느 고객사의 교재인지 맥락이 남는다.

여기서 입력한 **페이지 수와 심볼·기능 수량이 곧 청구액**이 되므로, 편집팀 작업 기록이자 정산 입력 화면이다.

| 항목 | 내용 |
|---|---|
| 권한 | STAFF / ADMIN |
| 대상 단위 | 교재(책) 1권 = S/O/B 좌표 1개 |

## 2. 화면 흐름 (Flow)

```
PRJ-03
  ├─ [＋ 교재(책) 추가] ─▶ PRJ-04 (등록)
  └─ 교재 행 클릭 ───────▶ PRJ-04 (수정)
                              ├─ 진행 상태 변경(완료 ⇄ 진행중)
                              ├─ [교재 삭제] ─ 확인 ─▶ PRJ-03 목록에서 제거
                              ├─ [목록] ────────────▶ PRJ-03 (입력값 저장 안 함)
                              └─ [저장] ────────────▶ PRJ-03 (목록·집계·청구액 갱신)
                                        └─▶ LOG-01 (등록=교재 추가 / 수정=교재 작업)
                                        └─▶ 공유 코드면 SOB-01 지도에 사용 고객사·편집 상태 반영
```

## 4. 사용법

### 4.1 진행 상태

| 상태 | 의미 |
|---|---|
| 진행중 | 편집 작업 중 (기본값) |
| 완료 | 작업 종료 — **내용 잠금** |
| 보류 | 중단·대기 |

- **완료로 바꾸려면 ncp2 최종수정 날짜가 입력돼 있어야 한다.**
- 완료를 해제하면 그때의 ncp2 최종수정 날짜가 **이력으로 보관**되고(해제 시각·해제자 포함), 화면에서 확인할 수 있다.

### 4.2 코드 좌표 · 사용 고객사

| 항목 | 필수 | 규칙 |
|---|---|---|
| 할당된 S / O | ✔ | **등록 모드**에서 할당된 S/O가 여러 개면 선택. **수정 모드에서는 변경 불가** |
| Book | ✔ | **사용 가능한 번호**에서 선택 |
| 코드 종류 | ✔ | **Book 다음**에 배치 `PC-054` · PDS2 · PDS3 · PDS4 · OID `PC-052` |
| 사용 고객사 | 공유 코드일 때 ✔ | 공유(커먼) 코드 Owner인 경우에만 표시·필수. 후보는 **그 커먼 코드를 체크한 고객사**만 나온다 |

**좌표 목록에는 코드 종류를 넣지 않는다** `PC-083`.

| | |
|---|---|
| 보이는 것 | `S3 / O25` — 좌표만. 공유 코드면 뒤에 **· 공유** |
| 왜 뺐나 | 할당 원장(479건)이 **종류 미상**이라 좌표마다 **N·G 두 줄**로 잡혔다. 같은 코드가 두 번 나와 고르기 불편했다 |
| 종류는 어디서 | 바로 뒤의 **[코드 종류]** 에서 고른다 `PC-054` — 좌표 할당에서는 정하지 않는다 `PC-051` |
| 좌표를 바꾸면 | **고른 종류는 그대로 유지**된다. 그 좌표에서 쓸 수 없는 종류면 첫 값으로 맞춰지고 Book 목록이 다시 계산된다 |
| 수정 모드 | 좌표는 **읽기 전용**이고 종류 배지도 붙이지 않는다 — [코드 종류] 칸에 이미 보인다 |

묶음 색과 안내문이 코드 성격에 따라 갈린다. (S1 · S6)

| 코드 | 배지 | 안내 |
|---|---|---|
| 전용 | **전용 코드 · {고객사}** | *이 S/O는 {고객사} 전용입니다. 별도 고객사 입력이 필요 없습니다.* |
| 공유 | **공유 코드 · 여러 고객사 사용** | *여러 고객사가 Book 번호만 나눠 쓰는 코드입니다 — {커먼코드} 를 체크한 고객사만 후보로 나옵니다.* |
| 공유·후보 없음 | — | *후보 없음 — 고객사 관리에서 {커먼코드} 를 체크하세요.* |

```
교재명 · ncp2 파일명 · ncp2 파일 크기(byte)
발급인 · 펜 모델
타입 · 편집 방식
Start Page · Total Page · 발급일자 · ncp2 최종수정
```
| 편집 방식 | — | **[타입] 바로 옆**에 둔다 `PC-087` · 여러 개 선택 가능(추가/삭제) · **고른 타입의 항목만** 후보로 나온다 |

**편집 방식은 타입을 따라간다** `PC-087`

| 타입 | 후보 |
|---|---|
| **소리펜** | `기능 없음` + **`소리펜_*` 12종** — 기본 · 멀티터치 · 멀티언어 · 그룹재생(0x02) · 슬롯전환(0x20) · 게임 · 영상호출 · LED(핀덴카) · 녹음재생 · 기타 기능 · 프롬프트 · 발음평가 |
| **필기펜** | `기능 없음` + **`필기펜_*` 7종** — 공유 · 플래너 연동 · URL 링크 연동 · gif 연동 · PDF 연동 · MP3 연동 · 기타 기능 |

- **`기능 없음`은 양쪽 공통**이다.
- **타입을 바꾸면** 그 타입에 없는 편집 방식은 **자동으로 떨어진다**.
- 삭제한 항목 `PC-087` — `KEP_ICT(필기펜)` · `교원구몬_내공100` (타입에서 교원구몬/KEP 를 뺀 것과 같은 정리 `PC-086`)

### 4.4 심볼·기능 수량 (정산 근거)

**소리펜과 필기펜 입력 칸이 좌·우로 함께** 표시되지만, **[타입]이 정하는 쪽만 입력한다** `PC-091`. 각 항목은 **수량 × 단가**로 계산된다. (S1 · S8)

| 타입 | 소리펜 심볼 입력 | 필기펜 심볼 입력 |
|---|---|---|
| **소리펜** | **활성** | **잠김** (흐리게 · 제목에 `잠김` 배지) |
| **필기펜** | **잠김** | **활성** |

- 잠긴 묶음은 **타입을 바꾸면 열린다**. 값은 지워지지 않는다.
- **[Ncode 적용 수]와 적용비는 활성 펜 기준**이다 — 두 펜의 [Ncode 적용] 을 더하지 않는다.
- **편집·기능비(심볼)는 두 묶음을 합산**한다 — 옛 장부에 반대편 묶음으로 기록된 심볼이 있어 그대로 청구에 반영한다.

| 블록 | 칸 수 | 입력 항목 |
|---|---|---|
| **소리펜 심볼 입력** (좌·넓음) | **15** | **Ncode 적용** `PC-085` · Ncode 편집(기본) · Compound 2·3·4·5·6·7·8언어 · 슬롯전환 · 그룹재생 · 게임 · 프롬프트 편집 · RAG 데이터 업로드 · 4도 Ncode 출력 |
| **필기펜 심볼 입력** (우) | **4** | **Ncode 적용** `PC-085` · 기본 편집 · Custom · 노트서버 업로드 `PC-084` |

**적용 비용은 [Ncode 적용] 입력 수량으로 계산한다** `PC-085`

| | |
|---|---|
| 적용비 | (소리펜 [Ncode 적용] × 소리펜 단가) + (필기펜 [Ncode 적용] × 필기펜 단가) |
| `Total Page` | **직접 입력** · **목록의 페이지 항목**에 반영된다 `PC-089`. **청구액과는 무관** — 옛 방식(Total Page × 단가)은 폐기했다 |

> `Total Page` 와 `Ncode 적용` 은 **서로 물리지 않는다** `PC-089`. 쓰임이 다르기 때문이다 — 앞은 **목록에 보여 줄 페이지 수**, 뒤는 **적용비를 매길 수량**이다.

**어디에 무엇이 보이나** `PC-090`

| 자리 | 항목 | 값 |
|---|---|---|
| 기본 정보 | `Total Page` | 직접 입력 → **목록의 페이지 항목** |
| 정산(청구액) 합산 줄 | **`Ncode 적용 수`** | 소리펜 [Ncode 적용] + 필기펜 [Ncode 적용] — **적용비 기준값** |

> 정산 영역에는 **Total Page 가 나오지 않는다** — 청구액과 무관하기 때문이다.
| 심볼 합계 | **[Ncode 적용] 수량은 빼고** 센다 — 페이지 수이지 심볼이 아니다 |

> 기존 교재는 정본 재생성 때 **Total Page 값을 [Ncode 적용] 으로 옮겨 담아**(5,586건) 청구액이 그대로 유지된다. 이후에는 담당자가 이 칸을 직접 고친다.

전사 기본 단가(원)

| 소리펜 | 단가 | 필기펜 | 단가 |
|---|---|---|---|
| Ncode 적용 (페이지) | 500 | Ncode 적용 (페이지) | 500 |
| Ncode 편집(기본) | 1,000 | **기본 편집** | 1,000 |
| Compound 2 / 3 / 4언어 | 1,300 / 1,600 / 1,900 | Custom | **1,500** |
| Compound 5 / 6 / 7 / 8언어 | 2,200 / 2,500 / 2,800 / 3,100 | 노트서버 업로드 | 10,000 |
| 슬롯전환 / 그룹재생 | 3,000 / 5,000 | | |
| 게임 / 프롬프트 / RAG | 각 50,000 | | |
| 4도 Ncode 출력 (페이지) | 1,000 | | |

> **필기펜에서 뺀 항목** `PC-084` — `action 변경 편집` · `교원구몬/KEP` 는 쓰지 않아 삭제했다.
> 교재의 **타입** 셀렉트(소리펜 / 필기펜 / 교원구몬·KEP)는 단가 항목이 아니라 **그대로 둔다**.
> 페이지 단위 **Ncode 적용**은 Total Page로 자동 계산되므로 별도 수량을 입력하지 않는다.
> 단가 값의 정본은 정책(`P-16`)이며, 고객사별 단가는 `MEM-02`에서 지정한다.

### 4.6 정산 (교재 단위 조정)

**적용 단가** — 이 교재에 적용된 단가가 배지로 표시된다.

| 표시 | 의미 |
|---|---|
| **등록 시 단가 ({날짜})** | 저장 시점의 고객사 단가로 **고정**된 상태. 이후 고객사 단가가 바뀌어도 이 교재는 그대로 |
| **고객사 단가 / 기본 단가** | 아직 고정 전(신규 교재 또는 단가 이력이 없는 구 교재). **저장하면 현재 단가로 고정**된다 |
| **⚠ 고객사 단가 변경됨 — 현재 단가로 갱신** | 고정된 단가와 현재 고객사 단가가 다를 때만 표시. 누르면 확인 후 **이 교재만** 현재 단가로 다시 계산한다 |

| 항목 | 규칙 |
|---|---|
| 할인율(%) | 합계(할인 전) 기준 |
| 추가 할인액(₩) | 정액 차감 |
| 할인 사유 | 예) 재작업분 · 물량 협의 |
| [할인 초기화] | 할인 없음으로 되돌린다 |

산출 근거가 **적용비(페이지) → 편집·기능비 → 합계(할인 전) → 할인율 → 추가 할인액 → 청구액** 순으로 표시된다.
