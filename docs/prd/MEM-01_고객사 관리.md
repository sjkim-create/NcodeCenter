## 1. 기능 개요

코드를 발급받는 **업체(고객사) 마스터**. 사업자·계좌·서류·편집 단가·업무 이력을 한곳에서 관리한다. **모든 코드 발급과 티켓 발급의 선행 조건**이 되는 화면으로, 여기에 등록되지 않은 업체에는 코드를 할당할 수 없다.

| 항목 | 내용 |
|---|---|
| 권한 | STAFF / ADMIN (ADMIN 권장 — §7 협의) |
| 진입 | 좌측 메뉴 [고객사 관리] |
| 성격 | 목록 · 검색 · 등록/수정/삭제 |
| 등록·수정 화면 | `MEM-02` |

## 2. 화면 흐름 (Flow)

```
좌측 메뉴 [고객사 관리]
   └─▶ MEM-01
         ├─ 🔔 가입 승인 요청 카드 ─▶ (클릭) 모달 ─ [승인 → 고객사 등록] ─▶ 고객사 등록(최근순 상단)
         │                                          └─▶ [계정·App Key 발급 →] TKT-02 (고객사·이메일 프리필)
         ├─ 구분 필터(전체/상위/하위/단독) · 검색 · 정렬(최근순/가나다)
         ├─ [＋ 고객사 등록] ─▶ MEM-02 (등록 모드)
         ├─ 행 클릭 ──────────▶ MEM-02 상세·수정 (업무요청 메모 포함)
         ├─ 행 [삭제] ─ 이름 입력 확인 ─▶ 프로젝트·코드 reset 후 목록 갱신
         └─ [초기화] ─ 확인 ─▶ 엑셀 시드로 복원
```

| `P-12` 공통(커먼) 코드 | 커먼 코드 보유·사용 여부를 목록에서 확인한다 |

| `PC-116` 고객 온보딩 = 승인 후 이용 | 고객이 우리 **서비스(CasterN 등)에 SSO 로그인**한 기록이 **가입 승인 요청**으로 들어온다. 직원이 **승인해야** 고객사로 등록되고, 그 뒤 `TKT-02`에서 계정·App Key(권한)를 발급받아 **비로소 이용**할 수 있다(승인 전에는 불가) |

| `P-07` SO 공유 불가 | 고객사 = 코드 식별 축이므로, **같은 업체를 중복 등록하지 않는다**(승인 시 같은 이름이 있으면 신규 등록 대신 **연결**한다) |

## 4. 사용법

### 4.1 상단 · 검색 · 필터

맨 위에 화면 설명과 규모가 함께 나온다 — *업체(고객사) 마스터 · 사업자/계좌/서류/업무 원장. 행을 클릭하면 수정 화면으로 이동합니다. 고객사 {n}곳 · 프로젝트 {n}건*

| 요소 | 동작 | 화면 |
|---|---|---|
| 검색 | **업체명·담당자·사업자번호 검색**. 입력하면 `×` 가 나타난다 | S3 |
| [초기화] | 확인 후 엑셀 시드 상태로 복원 | S8 |
| [＋ 고객사 등록] | `MEM-02` 등록 모드 | S9 |
| 구분 필터 | `전체` / `상위 고객사` / `하위 고객사` / `단독 고객사` — **알약 버튼**에 각 건수가 함께 표시된다 | S2 |
| 검색·필터 중 | 필터 줄 앞에 **검색 {n}건 ·** 이 붙는다 | S2 · S3 |
| 정렬 | 기본 **최근순**(createdAt 내림차순 — 새로 등록·승인한 고객사가 위) `PC-119`. **업체명** 헤더 클릭으로 최근순 → 가나다 오름 ▲ → 내림 ▼ 순환 | S1 |
| 페이지네이션 | `전체 {n}건 중 {a}~{b} 표시` + **건수 선택**(25 / 50 / 100 / 200 / 500 / 전체 보기) + `«` `‹` 번호 `›` `»` + `{현재}/{전체}` | S1 |

### 4.2 목록 항목

No · 업체명 · 담당자 / 연락처 · 사업자번호 · 은행 / 계좌 · 커먼 코드 · 편집 단가 · 주소 · 서류 · 업무 · 작업

| 열 | 설명 |
|---|---|
| 업체명 | 이름 + **구분 배지**(상위 고객사 / 하위 고객사 / 단독) + 종료 시 **종료** 배지 |
| 커먼 코드 | 보유(상위)는 **코드 배지**, 사용(하위)은 **↳코드** 로 구분해 표시. 없으면 `-` |
| 편집 단가 | 전용 단가가 있으면 **전용 {n}항목**, 없으면 **기본** |
| 서류 | 등록된 관련 서류 수 |
| 업무 | 업무 원장(요청/처리/메모) 기록 수 |
| 작업 | [삭제] — 행 클릭과 별개로 동작한다 |

**행을 클릭하면 `MEM-02` 수정 화면**이 열린다.

| 목록이 빌 때 | 문구 | 화면 |
|---|---|---|
| 검색 결과 없음 | **"{검색어}" 검색 결과가 없습니다.** | S3 |
| 등록된 고객사 없음 | **등록된 고객사가 없습니다.** | S3 |

### 4.3 구분 (계층)

| 구분 | 뜻 |
|---|---|
| **상위 고객사** | 공통(커먼)코드를 **보유**한 대표 고객사 — 하위 고객사가 이 코드를 함께 쓴다 |
| **하위 고객사** | 공통(커먼)코드를 **사용**하는 고객사. 귀속 대표사가 툴팁에 표시된다 |
| **단독** | 자체 코드만 쓰는 고객사(상위·하위 관계 없음) |

### 4.4 프로젝트 종료 업체 (S4)

`MEM-02` 에서 **사업 종료**로 바꾼 고객사는 목록에서 **흐리게** 표시되고 이름 옆에 **종료** 배지가 붙는다(툴팁 = 종료 사유·이관 메모). **코드 발급 이력은 그대로 남는다.**

> **종료 ≠ 삭제** — 종료는 이력을 보존하고, 삭제는 코드를 회수(reset)한다.

### 4.5 삭제 (S5 · S6 · S7)

행의 **[삭제]** → 경고 모달 **⚠ 고객사 삭제 — 신중히 확인하세요**.

모달의 경고 3줄

- 삭제 업체는 **3~4년 뒤 재연락되는 경우가 많습니다.** 정말 삭제가 필요한지 재확인하세요.
- 이 고객사의 **프로젝트 {n}건 / 발급 코드 {n}건이 reset**됩니다(회수).
- 서류·업무 원장 기록도 함께 삭제되며, **되돌릴 수 없습니다.**

확인을 위해 **업체명을 정확히 입력**해야 하며, 일치하기 전에는 **[삭제 확정 (코드 reset)]** 이 눌리지 않는다.

### 4.6 가입 승인 요청 (고객 온보딩) `PC-116` `PC-119` (S10 · S11 · S12)

**SSO 로그인은 우리 서비스(CasterN·폼솔루션) 사용자**가 그 서비스에서 하는 것이다(NcodeCenter 콘솔 로그인이 아니다 `PC-122`). 어떤 사용자가 **그 서비스에 처음 SSO 로그인하는 경우**, 그 로그인 기록이 **가입 승인 신청**이 되어 NcodeCenter [고객사 관리]로 들어온다. (로그인 기록은 별도 서버가 관리하며, 프로토타입에서는 목업 피드로 대신한다.) 콘솔(내부 직원)과 분리된 **고객의 서비스 이용 신청** 층위다.

| 요소 | 동작 | 화면 |
|---|---|---|
| 🔔 **가입 승인 요청 {n}건** 카드 | 목록 상단에 **건수만** 표시(인라인 목록 아님). 클릭하면 모달 | S10 |
| 사이드바 [고객사 관리] 배지 · 상단 🔔 | 대기 건수 배지 | S10 |
| 승인 모달 | 요청 목록 — 각 건에 **서비스 · 회사 · SSO 이메일 · 로그인 정보** + **[승인 → 고객사 등록] / [거절]** | S11 |
| [승인 → 고객사 등록] | 고객사로 등록(같은 이름 있으면 **연결**). 승인된 요청은 목록에서 사라진다 | S12 |
| [거절] | confirm 후 요청 제거 | S11 |
| 승인 완료 | 상단 초록 카드 **{회사} 승인 완료** + **[계정·App Key 발급 →]**(`TKT-02` · 고객사·이메일 프리필). 등록 고객사는 **최근순 상단** | S12 |

> **승인 이후에 이용 가능** — 승인 전에는 고객사 등록도, 계정/App Key(권한) 발급도 되지 않는다. 승인 → 고객사 등록 → `TKT-02`에서 계정·권한 발급의 순서다 `PC-116`.
