## 1. 기능 개요

코드를 발급받는 **업체(고객사) 마스터**. 사업자·계좌·서류·편집 단가·업무 이력을 한곳에서 관리한다. **모든 코드 발급과 티켓 발급의 선행 조건**이 되는 화면으로, 여기에 등록되지 않은 업체에는 코드를 할당할 수 없다.

| 항목 | 내용 |
|---|---|
| 권한 | STAFF / ADMIN (ADMIN 권장 — §7 협의) |
| 진입 | 좌측 메뉴 [고객사 관리] |
| 성격 | 목록 · 검색 · 등록/수정/삭제 |
| 등록·수정 화면 | `MEM-02` |

---

## 2. 화면 흐름 (Flow)

```
좌측 메뉴 [고객사 관리]
   └─▶ MEM-01
         ├─ 구분 필터(전체/상위/하위/단독) · 검색
         ├─ [＋ 고객사 등록] ─▶ MEM-02 (등록 모드)
         ├─ 행 클릭 ──────────▶ MEM-02 상세·수정 (업무요청 메모 포함)
         ├─ 행 [삭제] ─ 이름 입력 확인 ─▶ 프로젝트·코드 reset 후 목록 갱신
         └─ [초기화] ─ 확인 ─▶ 엑셀 시드로 복원
```

## 3. 정책

| 정책 | 이 화면에서의 적용 |
|---|---|
| `P-11` 고객사 계층 3분류 | **상위(공통코드 보유) / 하위(공통코드 사용) / 단독** 으로 구분해 필터한다. 하위 고객사도 **정식 회사 레코드**로 목록에 함께 표시된다 |
| `P-12` 공통(커먼) 코드 | 커먼 코드 보유·사용 여부를 목록에서 확인한다 |
| `P-16` 편집 단가 | 고객사별 편집 단가 지정 여부를 목록에서 확인하고, 지정은 `MEM-02`에서 한다 |
| `PC-002` 내부 직원 전용 | 고객이 직접 가입하지 않는다. **직원이 등록**한다 |
| `P-07` SO 공유 불가 | 고객사 = 코드 식별 축이므로, **같은 업체를 중복 등록하지 않는다**(중복 등록 시 코드 소유가 갈라진다) |

## 4. 사용법

### 4.1 상단 · 검색 · 필터

맨 위에 화면 설명과 규모가 함께 나온다 — *업체(고객사) 마스터 · 사업자/계좌/서류/업무 원장. 행을 클릭하면 수정 화면으로 이동합니다. 고객사 {n}곳 · 프로젝트 {n}건*

| 요소 | 동작 | 화면 |
|---|---|---|
| 검색 | **업체명·담당자·사업자번호 검색**. 입력하면 `×` 가 나타난다 | S3 |
| [초기화] | 확인 후 엑셀 시드 상태로 복원 | S8 |
| [＋ 고객사 등록] | `MEM-02` 등록 모드 | S9 |
| 구분 필터 | `전체` / `상위 고객사` / `하위 고객사` / `단독 고객사` — **알약 버튼**에 각 건수가 함께 표시된다 | S2 |
| 검색·필터 중 | 필터 줄 앞에 **검색 {n}건 ·** 이 붙는다 | S2 · S3 |
| 정렬 | **업체명** 열만 정렬 가능. 클릭하면 가나다 오름/내림이 바뀐다. 기본은 **오름차순 ▲** | S1 |
| 페이지네이션 | `전체 {n}건 중 {a}~{b} 표시` + **건수 선택**(25 / 50 / 100 / 200 / 500 / 전체 보기) + `«` `‹` 번호 `›` `»` + `{현재}/{전체}` | S1 |

### 4.2 목록 항목

No · 업체명 · 담당자 / 연락처 · 사업자번호 · 은행 / 계좌 · 커먼 코드 · 편집 단가 · 주소 · 서류 · 업무 · 작업

| 열 | 설명 |
|---|---|
| 업체명 | 이름 + **구분 배지**(상위 고객사 / 하위 고객사 / 단독) + 종료 시 **종료** 배지 |
| 커먼 코드 | 보유(상위)는 **코드 배지**, 사용(하위)은 **↳코드** 로 구분해 표시. 없으면 `-` |
| 편집 단가 | 전용 단가가 있으면 **전용 {n}항목**, 없으면 **기본** |
| 서류 | 등록된 관련 서류 수 |
| 업무 | 업무 원장(요청/처리/메모) 기록 수 |
| 작업 | [삭제] — 행 클릭과 별개로 동작한다 |

**행을 클릭하면 `MEM-02` 수정 화면**이 열린다.

| 목록이 빌 때 | 문구 | 화면 |
|---|---|---|
| 검색 결과 없음 | **"{검색어}" 검색 결과가 없습니다.** | S3 |
| 등록된 고객사 없음 | **등록된 고객사가 없습니다.** | S3 |

### 4.3 구분 (계층)

| 구분 | 뜻 |
|---|---|
| **상위 고객사** | 공통(커먼)코드를 **보유**한 대표 고객사 — 하위 고객사가 이 코드를 함께 쓴다 |
| **하위 고객사** | 공통(커먼)코드를 **사용**하는 고객사. 귀속 대표사가 툴팁에 표시된다 |
| **단독** | 자체 코드만 쓰는 고객사(상위·하위 관계 없음) |

### 4.4 프로젝트 종료 업체 (S4)

`MEM-02` 에서 **사업 종료**로 바꾼 고객사는 목록에서 **흐리게** 표시되고 이름 옆에 **종료** 배지가 붙는다(툴팁 = 종료 사유·이관 메모). **코드 발급 이력은 그대로 남는다.**

> **종료 ≠ 삭제** — 종료는 이력을 보존하고, 삭제는 코드를 회수(reset)한다.

### 4.5 삭제 (S5 · S6 · S7)

행의 **[삭제]** → 경고 모달 **⚠ 고객사 삭제 — 신중히 확인하세요**.

모달의 경고 3줄

- 삭제 업체는 **3~4년 뒤 재연락되는 경우가 많습니다.** 정말 삭제가 필요한지 재확인하세요.
- 이 고객사의 **프로젝트 {n}건 / 발급 코드 {n}건이 reset**됩니다(회수).
- 서류·업무 원장 기록도 함께 삭제되며, **되돌릴 수 없습니다.**

확인을 위해 **업체명을 정확히 입력**해야 하며, 일치하기 전에는 **[삭제 확정 (코드 reset)]** 이 눌리지 않는다.
