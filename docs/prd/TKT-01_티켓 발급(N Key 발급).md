## 1. 기능 개요

**티켓 = 고객사가 이미 할당받은 SOBP 코드를 실제로 쓸 수 있게 하는 사용 허가**다. 티켓 발급 화면은 3개 발급 메뉴를 담는 컨테이너이며, 진입 시 **N Key 발급**이 기본으로 열린다.

**N Key** = 물리 키. 오프라인 편집툴(Caster lite)에서 쓰며 **계정이 필요 없다.** 발급하면 티켓 파일이 zip으로 내려받아진다.

| 항목 | 내용 |
|---|---|
| 권한 | STAFF / ADMIN |
| 진입 | 좌측 메뉴 [티켓 발급] |
| 하위 메뉴 | `TKT-01` N Key(기본) · `TKT-03` 계정+App Key · `TKT-04` 발급 목록 및 정산 |
| 선행 조건 | 고객사가 **`MEM-01`에 등록**되어 있고, **`SOB-02`로 SOBP를 할당**받았어야 한다 |

> **고객사 선택값은 3개 메뉴가 공유한다.** N Key에서 고객사를 고른 뒤 `TKT-03`으로 옮겨도 그대로 유지된다.

## 2. 화면 흐름 (Flow)

```
좌측 메뉴 [티켓 발급]
   └─▶ TKT-01 (기본 = N Key 발급)
          │
          ├─ 고객사 선택 ─▶ 할당된 SOBP 범위 선택 ─▶ 발급 조건 입력
          │        │
          │        └─(할당 범위 없음)─▶ SOB-02 직접 코드 할당으로 먼저 할당
          │        └─(미등록 고객사)──▶ MEM-02 고객사 등록
          │
          ├─ [🔍 Key 정보 확인] ─▶ TKT-02 (모달) ─ 닫기 ─▶ TKT-01 복귀
          │
          └─ [Key 생성] ─▶ zip 다운로드 + 발급 이력 기록
                              └─▶ TKT-04 발급 목록 및 정산에서 확인
                              └─▶ LOG-01 활동 로그 자동 기록(티켓 발급)

발급 메뉴 전환: TKT-01 ⇄ TKT-03 ⇄ TKT-04 (고객사 선택 유지)
```

## 3. 정책

| 정책 | 이 화면에서의 적용 |
|---|---|
| `P-15` 티켓 = N Key / App Key | **N Key = 물리 키(오프라인·계정 불필요)**. 계정 연동이 필요하면 `TKT-03` |
| `P-01` SOBP | 티켓은 Section·Owner·Book·Page 범위로 발급된다 |
| `P-05` 무겹침 | 티켓은 **이미 할당된 범위 안에서만** 발급된다. 할당 범위를 넘는 Book·Page는 입력할 수 없다 |
| `P-12` 공통(커먼) 코드 | 공통코드 보유 고객사는 **사용 고객사(하위 고객사)를 반드시 지정**해야 발급된다. 지정값은 티켓 정보와 파일명에 포함된다 |
| `P-02` 코드 종류 N/G | PatternType은 할당 범위에 따라 자동 결정된다(Ncode_PDS3 / Ncode_PDS2). 사용자가 직접 고르지 않는다 |
| 요구사항 #1 | 사용 기한(ValidUntilTime)으로 기간 제한, Book·Page 볼륨으로 수량 제한 |

## 4. 사용법

### 4.1 발급 메뉴 (컨테이너 공통 요소)

| 요소 | 동작 |
|---|---|
| 좌측 발급 메뉴 3개 | `N Key` / `계정 + App Key` / `발급 목록 · 정산`. 클릭하면 우측 영역이 해당 화면으로 바뀐다. 발급 목록에는 **누적 발급 건수**가 함께 표시된다 |
| 키 종류 안내 | `N Key = 물리 키 · 계정 불필요` / `App Key = id/pwd + SOBP · 계정 연동` |
| 고객사 선택 상태 | 메뉴를 바꿔도 유지 |

### 4.2 N Key 발급 — 단계

1. **회사이름(고객사)** 을 선택한다.
2. **할당된 SOBP 범위**를 선택한다. 선택하면 **Section · Owner · Book 범위 · PatternType이 자동 입력**된다.
   - 공통코드 보유 고객사면 **사용 고객사** 선택 항목이 함께 나타난다.
3. **Start Book / Book 볼륨 / Start Page / Page 볼륨**을 입력한다. 각 항목에는 선택한 범위 기준의 허용 최대값이 함께 표시된다.
4. **ValidUntilTime(사용 기한)** 을 지정하거나 **무제한**을 체크한다.
5. 필요하면 **Separate each book**을 체크한다.
6. (선택) **[🔍 Key 정보 확인]** 으로 지금 입력값이 티켓에 어떻게 들어가는지 미리 본다 → `TKT-02`
7. **[Key 생성]** — 검증을 통과하면 zip 파일이 다운로드되고 발급 이력이 기록된다.

### 4.3 입력 항목 · 검증

| 항목 | 필수 | 입력 방식 | 규칙 |
|---|---|---|---|
| 회사이름(고객사) | ✔ | 선택 | `MEM-01`에 등록된 고객사만 |
| 사용 고객사 | 조건부 ✔ | 선택 | **공통코드 보유 고객사일 때만** 표시·필수 |
| 할당된 SOBP 범위 | ✔ | 선택 | 고객사가 할당받은 범위 목록. 없으면 발급 불가 |
| Start Book | ✔ | 숫자 | 선택 범위의 `bookStart ~ bookEnd` 안 |
| Book 볼륨(권) | ✔ | 숫자 | `1 ~ (범위 끝 − Start Book + 1)` |
| Start Page | ✔ | 선택 | 기본 1 |
| Page 볼륨 | ✔ | 숫자 | 1 이상, Section별 페이지 상한 이내 |
| ValidUntilTime | ✔ | 달력 또는 6자리 | `YYMMDD` 6자리. **무제한** 체크 시 `99999999`로 발급 |
| IssuedTime | — | 자동 | 발급일 고정값 |
| PatternType | — | 자동 | 범위에 따라 `Ncode_PDS3` / `Ncode_PDS2` |
| TicketVersion | — | 자동 | `1` |
| Separate each book | — | 체크 | 체크: **북코드별 개별 티켓** / 해제: **1개 티켓에 병합** |

### 4.4 TKT-02 · Key 정보 확인 (모달)

발급될(또는 발급된) 티켓의 항목을 **key · value 표**로 확인한다.

| 요소 | 동작 |
|---|---|
| [현재 입력값] | 화면에 입력한 값 기준으로 표시. 아직 생성 전임을 함께 안내 |
| [📂 Key 불러오기] | 내려받은 티켓 `.json` 파일을 선택해 내용 확인. 파일명이 함께 표시된다 |
| 항목 검색 | key·value에 포함된 문자열로 행을 거른다 |
| [표 복사] | 표 전체를 클립보드로 복사 |
| [닫기] | 모달을 닫고 원래 화면으로 복귀 |

> **진입점 2곳** — ① 이 화면의 [🔍 Key 정보 확인](생성 전 입력값 기준) ② `TKT-04` 발급 목록 행의 [Key 정보](이미 발급된 티켓의 저장값 기준). **모달 구성은 동일하고 표시 데이터만 다르다.**

### 4.5 Key 생성 결과

| 항목 | 내용 |
|---|---|
| 다운로드 | 티켓이 **폴더 형태의 zip 1개**로 내려받아진다 |
| 파일명 | `Ticket_{고객사}[_{사용고객사}]_S{Section}O{Owner}_B{시작}[-{끝}].zip` |
| Separate each book 체크 | zip 안에 **Book 하나당 파일 1개**(각 1권) |
| 해제 | zip 안에 **병합 티켓 파일 1개** |
| 사용 안내(화면 고정 문구) | Key 생성 시 티켓이 zip 파일(폴더 형태)로 다운로드됩니다. 다운로드 폴더에서 zip의 압축을 풀어 그 폴더째 nproj 폴더 또는 내 PC > 문서 > NeoLAB > CodeTickets(C:\Users\Documents\NeoLab\CodeTickets)에 넣은 뒤 Caster lite에서 사용합니다. |
| 이력 | `TKT-04` 발급 목록에 1건 추가 · `LOG-01`에 **티켓 발급**으로 기록 |

## 5. 상태별 변화 · 메시지

### 5.1 발급 전 상태

| 상태 | 화면 |
|---|---|
| 고객사 미선택 | SOBP 범위 항목에 **고객사를 먼저 선택하세요.** 안내. [Key 생성] 비활성 |
| 할당 범위 없음 | 범위 목록이 비어 있고 [Key 생성] 비활성 → `SOB-02`에서 할당 필요 |
| 범위 선택 완료 | Section·Owner·PatternType 자동 입력, [Key 생성] 활성 |

### 5.2 검증 실패 메시지 (인라인)

| 상황 | 문구 |
|---|---|
| 고객사 미선택 | **고객사를 선택하세요.** |
| 공통코드인데 사용 고객사 미선택 | **공통코드 회사입니다. 사용 고객사를 선택하세요.** |
| 할당 범위 없음 | **이 고객사에 할당된 SOBP 범위가 없습니다.** |
| Start Book이 범위 밖 | **Start Book은 {시작}~{끝} 범위여야 합니다.** |
| Book 볼륨 초과 | **Book 볼륨은 1~{최대}권이어야 합니다. (B{시작}~B{끝})** |
| Page 볼륨 오류 | **Page 볼륨은 1 이상이어야 합니다.** |
| 사용 기한 형식 오류 | **ValidUntilTime은 6자리(YYMMDD)이거나 무제한이어야 합니다.** |

### 5.3 성공 메시지

| 상황 | 문구 |
|---|---|
| 병합 발급 | **Key 생성됨 · 티켓 1장(병합) · B{시작}~{끝} — zip({파일명}.zip)으로 다운로드됩니다.** |
| 개별 발급 | **Key 생성됨 · 티켓 {n}개(개별 파일) · B{시작}~{끝} — zip({파일명}.zip)으로 다운로드됩니다.** |

### 5.4 TKT-02 모달 메시지

| 상황 | 문구 |
|---|---|
| 티켓 파일이 아닌 JSON 선택 | **JSON 형식의 티켓 파일이 아닙니다. Key 생성으로 내려받은 .json 파일을 선택하세요.** |
| 파일 미선택 상태 | **키 파일을 선택하세요.** |
| 표시할 항목 없음 | **표시할 항목이 없습니다.** |
