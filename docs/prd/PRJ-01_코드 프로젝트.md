## 1. 기능 개요

**고객사별로 어떤 코드(SOBP)를 얼마나 발급받았는지**를 조회·검색하는 화면. 코드 발급 자체는 `SOB-02`에서 이뤄지므로 **이 화면에는 프로젝트 등록 기능이 없다**(조회·검색 전용). 발급된 코드의 사용 서비스·공유 여부·편집 연결을 확인하는 용도다.

| 항목 | 내용 |
|---|---|
| 권한 | STAFF / ADMIN |
| 진입 | 좌측 메뉴 [코드 ▸ 코드 프로젝트] |
| 성격 | **VIEW 용도 · 조회·검색 전용** (등록 · 수정 · 삭제 없음 `PC-164`) · 코드 회수 기능 없음 `PC-165` |
| 범위 | **전 서비스 공통** — 사용 서비스 필터로 casterN·폼솔루션·서비스없음 코드를 모두 조회한다. 그래서 특정 서비스 그룹이 아닌 [코드] 그룹에 둔다 |
| 구성 | **3단** — 좌: 고객사 · 가운데: 프로젝트 · 우: 발급 구성 (§4) |

## 2. 화면 흐름 (Flow)

```
[코드 ▸ 코드 프로젝트]
   └─▶ PRJ-01
         ├─ 고객사 검색 · 사용 서비스 필터 ─▶ 좌측 목록 축소
         ├─ 고객사 선택 ─▶ 우측 프로젝트 상세
         │     └─ [✏️ 편집 →] ────────────▶ PRJ-02 (해당 owner의 편집 프로젝트)
         └─ 코드 신규 발급이 필요하면 ──────▶ SOB-01 → SOB-02
```

## 4. 사용법

화면은 **3단**이다 — 좌 **고객사** / 가운데 **프로젝트** / 우 **발급 구성**.

### 4.1 상단 요약 (S1)

`고객사 {n} · 프로젝트 {n} · 발급 코드 {n} · 실등록 {n}` 이 **현재 필터 기준**으로 표시되고, 끝에 범위 안내가 붙는다 — 필터가 걸리면 **· 필터 적용 (전체 {n}곳 / {n}건)**, 아니면 **· 할당된 코드를 업체·서비스별로 조회 (발급은 [Ncode 예약·할당])**. 우측에 **[초기화]**.

### 4.2 좌측 — 고객사 (S1 · S3 · S7 · S9)

필터가 **3중**으로 걸린다. 어느 하나를 바꾸면 **선택한 프로젝트가 해제**된다.

| 요소 | 값 | 화면 |
|---|---|---|
| 코드 종류 | **셀렉트 박스** `PC-301` — `전체 코드 종류` / `PDS2 (Gcode)` / `PDS3 (Ncode)` / `PDS4 (S-code)` / `OID`, 항목마다 **(고객사 수)** — 그 종류 코드를 가진 고객사 수(편집 여부 · 사용 서비스 거르기를 따른다. 전체 = 모든 고객사). 좌표(SOBP)의 속성 기준 `PC-032`. 옛 **IDS(A) = OID 동일** `PC-035`. 고르면 프로젝트 선택 해제 | S3 |
| 구분 | `전체` / `편집` / `코드발급` | S3 |
| 사용 서비스 | 드롭다운 · 기본 **사용 서비스 · 전체** | S1 |
| 고객사 검색 | 업체명으로 검색. `×` 로 해제 | S7 |

**필터를 걸면 그 조건에 맞는 프로젝트가 있는 고객사만** 목록에 남는다. 정렬은 **업체명 가나다순**.

옛 확장 언어 슬롯 고객사(「Common 추가 언어 슬롯-964~983」 · 「Cake-984~1003」 — 할당 코드가 모두 다른 고객사 확장 언어 그룹의 확장 Owner)는 **목록에 나오지 않고**, 그 프로젝트는 **그룹 고객사(Common-21 · Cake-1009)의 프로젝트 목록 안에** 그룹 코드로 보인다 — **가운데 프로젝트 목록에는 기본 코드 프로젝트(+ OID 프로젝트)만** 남고, 그 고객사의 나머지 코드는 모두 기본 코드 프로젝트의 발급 SOBP 내역(§4.4)에서 본다 — 확장 슬롯으로 아직 고르지 않은 코드도 여기 모여 「전용 코드인지 언어 확장 코드인지」를 한곳에서 가린다 `PC-353` `PC-354` · 기본 코드를 아직 정하지 않은 그룹은 확장 · 역할 미지정 코드만 뺀다 — 고객사 관리(`PC-330`) · 편집 프로젝트(`PC-344`)와 같은 기준 · 할당 데이터는 그대로 `PC-351`. 이때 **슬롯 고객사 이름은 어디에도 내지 않는다** — 카드 · 상세 제목은 **「{그룹 고객사} 코드발급」**, 상세의 고객사 태그도 그룹 고객사 `PC-352`.

| 카드 표시 | 내용 |
|---|---|
| 1줄 | 업체명 + 사업 종료 시 **종료** 배지(툴팁에 사유·이관 메모) |
| 2줄 | 사용 서비스 요약(없으면 **SDK 연동** `PC-053`) · `코드 {n}` · 보유 **코드 종류 배지**(PDS2 · PDS3 · PDS4 · OID) |

목록이 비면 **결과 없음**. (S7)

### 4.3 가운데 — 프로젝트 (S1 · S2 · S9)

제목은 `프로젝트 · {고객사} ({n})`. 목록은 **Owner 오름차순**(같은 Owner 면 Section · 프로젝트명 순 · 발급이 없는 프로젝트는 맨 뒤) `PC-350`.

| 카드 표시 | 내용 |
|---|---|
| 1줄 | 프로젝트명 |
| 2줄 | **코드 종류 + S · O 칩** (최대 4개, 넘으면 `+{n}`). 발급이 없으면 **미발급** · 확장 언어 그룹 Owner 면 O 칩 옆 **[기본] / [확장 {k}]**(툴팁 *{그룹} 기본 Owner · 슬롯 1~4* / *{그룹} · 기본 O{n} 의 확장 언어 {k} · 슬롯 {a}~{b}*) `PC-350` · 역할 미지정 칩은 없앴다 `PC-357` |
| 3줄 | 사용 서비스 태그 · **편집** 태그 · **공유** 태그 |
| 4줄 | `발급 {n}코드 · {n}블록` |

프로젝트가 없으면 **이 고객사의 프로젝트가 없습니다.**

### 4.4 우측 — 발급 구성 (S2 · S9)

프로젝트를 고르기 전에는 안내만 나온다 — *{고객사} — 가운데에서 프로젝트를 선택하면 **어떤 코드가 어떻게 발급되었는지**(SOBP 블록·발급일·코드 수) 확인할 수 있습니다.* (S1)

| 표시 | 내용 |
|---|---|
| 머리 | 프로젝트명 · 고객사 태그 · **코드 종류 + S/O 칩** · 사용 서비스 · **공유 코드** · 등급(폼솔루션만) · **✏️ 편집** |
| ✏️ 편집 | 편집 실적이 있으면 심볼 수와 함께 표시. 클릭 시 `PRJ-02` 로 이동. 실적이 다른 owner에 귀속된 예외는 **✏️ 편집 → {귀속 대상}** |
| 발급 요약 4종 | **발급 코드(B×P)** · **실등록 페이지** · **편집 심볼** · **코드 종류** |
| 발급 SOBP 내역 | 순번 · **S/O/B/P 칩** · 발급일 · `{n}권 × {n}p = {n}` · 실등록이 있으면 **실등록 {n}p**. **조회 전용** |
| 확장 언어 코드 `PC-353` `PC-357` | 그룹은 **기본 코드마다** 있다. 프로젝트 목록에서는 **확장 코드 프로젝트만** 빼고(기본 코드 · 그룹 밖 전용 코드 · OID 는 그대로), 그룹의 **기본 코드** 프로젝트(OID 제외)를 고르면 발급 SOBP 내역에 **그 그룹의 확장 코드**(슬롯 고객사로 할당된 확장 코드 포함)가 확장 순서대로 이어서 나온다 — 줄마다 S/O/B/P 칩 뒤 **[기본] / [확장 {k}]** 칩 · 발급 요약 4종은 기본 코드 프로젝트 값 그대로 · `PC-354` 의 「나머지 코드 전부를 기본 코드 안에」는 바꿨다(그룹 밖 코드는 자기 프로젝트로) |
| 발급 내역 없음 | **발급 내역이 없습니다. (미발급)** |

> 사용 서비스가 없는 고객사(**SDK 연동**)는 프로젝트 카드 · 상세에 **서비스 태그를 붙이지 않는다**. (S8)

### 4.5 사용 고객사(하위) — 공통코드 대장일 때 (S4)

공통(커먼) 코드 프로젝트에는 **사용 고객사 목록**이 표시된다 — *공통(커먼)코드를 함께 쓰는 고객사 · 편집/티켓은 이 대장으로 진행.*

| 요소 | 동작 |
|---|---|
| 하위 고객사 검색 | 이름으로 거른다. 우측에 `표시 수 / 전체 수` |
| 고객사 칩 클릭 | 그 고객사가 **실제로 쓰는 SOBP(Book 단위)와 페이지 합계**를 표시 — *{고객사} 사용 SOBP {n}권 · {p}p · 이 대장 코드 {라벨} 내에서 이 고객사가 쓰는 Book*, 줄마다 S/O/B 칩 · 교재명 · 페이지. 기록이 없으면 *이 고객사의 개별 Book 사용 기록이 없습니다. (대장 코드 {라벨} 공유)*. 다시 누르면 해제 |
| **신규** 배지 | 시드 데이터가 아니라 사용자가 등록한 사용 고객사 |
| 사용 고객사 없음 | **등록된 사용 고객사가 없습니다.** |
