## 1. 기능 개요

**App Key 를 발급하는 화면**이다. 「**고객사 | App Key 계정 | 계정 상세**」 3단 한 화면에서 고객사를 고르고, 그 고객사의 App Key 계정을 만들고, 계정마다 App Key 와 코드 범위(=티켓)를 발급한다.

**App Key 의 용도** `PC-245` — **Ncode SDK** 를 쓰는 고객사와 **Caster U** 를 쓰는 고객에게 준다. Caster U 는 **계정이 필요**하다 — 계정을 만들면 App Key 가 생기고, [권한] 탭에서 **Caster U 권한**을 설정해 두면 그 계정 · App Key 로 Caster U 를 쓸 수 있다.

| 티켓 | 쓰는 곳 · 쓰는 사람 | 계정 | 발급 · 지정 화면 |
|---|---|---|---|
| **App Key** (계정 소속 티켓) | **Ncode SDK** 를 쓰는 고객사 · **Caster U** 를 쓰는 고객 — App Key 에 **권한(Caster U 권한 20항목)** 을 설정해 발급하면 그 계정으로 Caster U 를 쓸 수 있다 | **필요** — 계정을 만들면 App Key 자동 생성(1계정 1키) · 티켓은 계정마다 여러 개 | `TKT-01` App Key 관리 |
| **N Key** (.nkey 파일) | **Caster Lite**(오프라인 편집툴) 사용자 — 프로필 **LEGACY**. **CasterN 을 오프라인으로 쓰는 경우**에는 프로필 **HYBRID** + CasterN 권한 6개로 발급 | 필요 없음(파일 키) | `TKT-02` N Key 관리 |
| **서비스 티켓** | **casterN · 폼솔루션** 서비스(온라인) 사용 고객사 — 사용자에게 주는 키가 아니라 고객사 계정과 매칭해 서비스 사용을 승인하는 기준(§6.6) | 고객사의 서비스 계정과 매칭 | `MEM-02` 고객사 관리 ▸ 서비스 티켓 |

| 항목 | 내용 |
|---|---|
| 권한 | STAFF / ADMIN |
| 진입 | 좌측 메뉴 **[티켓 발급] ▸ [App Key 관리 (계정 발급)]** (`/tickets/account`) |
| 고객사 | **고객사 관리(`MEM-01`) 고객사를 불러온다** — 여기서 고객사를 등록하지 않는다 `PC-153` |
| 계정 | **App Key 계정** — 계정과 App Key 가 매칭되는 개념(계정당 App Key 1개) |
| 과거 자료 | 개발팀 **Caster_계정_퍼미션_티켓.xlsx** 의 계정 15건(대장) — 고객사명으로 고객사 관리 고객사에 잇는다 |
| 짝 화면 | `TKT-02` N Key 관리 — 같은 3단 · 같은 UI 조각 `PC-154` |

> **App Key 계정 ≠ 서비스 계정.** App Key 계정은 *계정과 App Key 를 매칭*하는 발급 단위이고, 고객사 관리(`MEM-02`)의 **서비스 계정**은 *고객사가 서비스 권한(CasterN 등)을 갖게 하는* 계정이다. 두 계정은 서로의 목록에 나오지 않는다 `PC-128` `PC-153`.

### 4.4 App Key 발급 · 티켓 발급 `PC-208`

**App Key** — 계정을 만들 때 **자동 생성**(1계정 1키, 영문 소문자 · 숫자 29자 예 `32b019140790385d8cb6fa32d9b81`). [계정 정보]에 키 값 · [복사] · 생성일, 이전 정책으로 2개면 둘 다(S8) `PC-210`.

**티켓**([티켓 발급] 탭) — **App Key 를 먼저 발급한 계정에만**(없으면 S17). 아래 항목으로 발급한다.

| 항목 | 규칙 |
|---|---|
| 발급 범위 (Caster 대장 이력 · SOBP 할당) | 이 고객사의 Caster 대장 범위 + **고객사 관리에서 할당한 SOBP**. 고르면 Section·Owner·Book·Code Type 이 채워진다. 없으면 **이 고객사의 발급 범위가 없습니다.** (S10) |

| 발급 항목 `PC-264` | 티켓 주인(계정 ID · 자동) · **Code Type**(발급 범위 따름) · Section · **Owner 시작 · Owner 개수**(폼의 **Owner Size** — 범위가 아니면 **1** · 고정 칸 `PC-265`) · Start Book · Book 볼륨 · Start Page · Page 볼륨 · **기한** · Info. Ticket Name · 사용기간 시작 · Ticket Version 은 이 화면 기록용 |
| 배치 | 발급 범위(맨 위) → 구간 사용 현황 → 2열 짝 묶음 **코드 구간**(Start Book · Book 볼륨 / Start Page · Page 볼륨) · **티켓 속성**(Ticket Name / Code Type · Owner Size · Info `PC-265`) · **기간 · 버전**(사용기간 시작 · 끝 / Ticket Version) — N Key 발급과 같은 모양 `PC-223`. Ticket Type 은 없다(N Key 코드 재사용 전용 `PC-259`) |
