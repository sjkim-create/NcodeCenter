## 1. 기능 개요

모든 화면이 공유하는 **로그인·권한·역할·공통 목록/필터/검색 패턴·메시지 규칙**을 정의한다. 각 화면 PRD는 여기서 정의한 규칙을 반복 기술하지 않고 참조한다.

| 항목 | 내용 |
|---|---|
| 대상 사용자 | 네오랩 **내부 직원 전용** (외부 고객 접근 없음 — `P-10`) |
| 역할 | **ADMIN** / **STAFF** 2종 |
| 포함 화면 | 로그인, 개인정보 수정(헤더 모달), 좌측 메뉴·상단바 |
| 적용 범위 | 전 화면 |

## 2. 화면 흐름 (Flow)

```
[비로그인] ──▶ 로그인 화면
                 │  ├ [처음 방문하셨나요? 승인 요청 →] ─▶ 승인 요청 화면(이름 · 회사 이메일) ─▶ ADMIN 이 MEM-03 에서 승인 ─▶ 로그인 가능
                 │  데모 로그인(관리자) 또는 회사 등록계정 로그인 성공 (ncc_demo 쿠키)
                 ▼
              DSH-01 대시보드 (기본 진입 화면)
                 │
                 ├─ 좌측 메뉴 ─▶ TKT-01 / TKT-02 / SOB-01 / PRJ-01 / PRJ-02 / PRJ-06
                 │              MEM-01 / LOG-01(ADMIN) / INF-01
                 ├─ 상단 계정 ─▶ 개인정보 수정(모달) → 저장 → 원래 화면 유지
                 └─ 로그아웃 ──▶ 로그인 화면
```

- 미로그인 상태로 화면 경로에 접근하면 **로그인 화면으로 이동**한다.
- 로그아웃 진행 중에는 화면 셸 대신 전환 화면을 보여준다(비로그인 잔상 방지).

## 3. 정책

| 정책 | 이 문서에서의 적용 |
|---|---|
| `P-10`·`PC-122` 콘솔 로그인 = 회사 계정 | **NcodeCenter 콘솔 로그인은 회사 계정(내부 직원) 만** 한다. **SSO 는 콘솔 로그인 방식이 아니다.** (프로토타입은 데모 버튼을 편의로 제공하나, 모델상 콘솔 로그인 수단은 회사 계정이다.) **처음 쓰는 직원은 로그인 화면의 [첫 방문 — 승인 요청]으로 요청하고, ADMIN 이 승인해야 로그인할 수 있다** `PC-299` |
| `PC-116`·`PC-122` 고객 온보딩 = 서비스 SSO → 승인 후 이용 | 콘솔과 **분리된 서비스(외부) 층위** — **SSO 로그인은 우리 서비스(CasterN·폼솔루션) 사용자**가 그 서비스에서 하는 것이고, **처음 로그인하는 경우 = 승인 요청**이 NcodeCenter [고객사 관리]로 들어온다. 직원이 **승인해야** 고객사 등록·계정/App Key 발급으로 **이용**할 수 있다(승인 전 불가). 상세는 `MEM-01` §4.6 |
| `PC-002` 행위자 모델 | Customer 역할 폐기. 콘솔 역할은 ADMIN/STAFF 2종 |
| `P-04` 코드 상태 | 전 화면에서 코드 상태는 **할당됨(발급) / 미발급** 2가지로만 표기. "예약/사용중" 용어 사용 금지 |
| 용어 기준 | 코드 좌표는 **SOBP**(Section–Owner–Book–Page). 한글 "부분" 등 대체어 사용 금지 |

### 3.1 역할·권한

| 역할 | 부여 방식 | 권한 |
|---|---|---|
| **ADMIN** | 직원 계정(`MEM-03`)에서 ADMIN 으로 지정한 직원 | 전 화면 — **활동 로그(`LOG-01`) · 직원 계정(`MEM-03`) 포함** |
| **STAFF** | 첫 방문 승인 요청을 ADMIN 이 승인하거나, ADMIN 이 직원 계정에서 직접 등록하면 부여 `PC-299` `PC-309` | `LOG-01` · `MEM-03` 을 제외한 전 화면(고객사 · 코드 할당 · 편집 · 키 발급 · 정산 모두 가능) |

> `LOG-01`(활동 로그)은 **메뉴를 숨기지 않는다.** 메뉴에 **ADMIN** 배지가 붙고, STAFF 가 들어가면 그 화면에서 **🔒 접근 권한이 없습니다 / 활동 로그는 관리자(ADMIN) 계정만 열람할 수 있습니다.** 로 막힌다. (S10)

- 콘솔 로그인은 현재 **회사 등록계정(이메일/비번) + 데모 로그인(관리자 즉시 입장)** 이다 `PC-116`. 실 SSO(Google) 도메인 검증은 **보류**(코드만 잔존).
- 역할은 **직원 명단** 기준으로 부여한다(데모 로그인은 관리자). 처음 쓰는 내부 직원은 **ADMIN 승인 후** 로그인한다(`PC-299` · `MEM-03`). 고객의 서비스 이용 승인은 따로 *고객 온보딩*(`MEM-01` §4.6)이다.

## 4. 사용법

### 4.1 로그인

**NcodeCenter 콘솔 로그인은 회사 계정(내부 직원) 로그인이다** `PC-122`. **SSO 는 콘솔 로그인 방식이 아니다** — SSO 는 우리 *서비스*(CasterN·폼솔루션) 사용자가 그 서비스에서 하는 로그인이고, 그 **첫 로그인이 승인 요청**이 되어 `MEM-01`로 들어온다(콘솔과 분리된 층위). 로그인하면 `ncc_demo` 세션 쿠키가 서고, 미들웨어는 그 쿠키로 라우트를 보호한다.

| 방식 | 절차 | 화면 |
|---|---|---|
| **회사 계정 로그인** | 이메일 + 비밀번호 입력 후 Enter 또는 [로그인] → `DSH-01` (모델상 콘솔 로그인 수단) | S1 · S5 |
| **첫 방문 — 승인 요청** | 로그인 카드 아래 **[처음 방문하셨나요? 승인 요청 →]** → 따로 입력 화면(이름 · 회사 이메일) → [승인 요청]. 승인 전에는 로그인할 수 없다 `PC-299` | S15 |
| **🧪 데모로 들어가기 (관리자)** | *프로토타입 편의* — Google/비번 없이 관리자로 즉시 입장(주로 `/companies`). 실제 데이터 아님 · 시연용(제품 모델 아님) | S2 |

> 안내 문구 — *프로토타입 — **데모**로 바로 들어가거나, 회사 계정으로 로그인하세요. (내부 직원 전용)*
> ⚠ **SSO 는 콘솔이 아니라 서비스(CasterN·폼솔루션)에서** 쓰인다. 서비스 첫 SSO 로그인 → 승인 신청(`MEM-01` §4.6).

입력 항목 (회사 등록 계정)

| 항목 | 필수 | 규칙 |
|---|---|---|
| 이메일 | ✔ | 회사 등록 계정 (`name@neolab.net`) |
| 비밀번호 | ✔ | 초기값 = 이메일. Enter로 제출 · [로그인 계정 기억] 체크 시 이메일 자동 채움 |

입력 항목 (첫 방문 — 승인 요청) `PC-299`

| 항목 | 필수 | 규칙 |
|---|---|---|
| 이름 | ✔ | 표시 이름. 화면을 열면 이 칸에 커서 |
| 회사 이메일 | ✔ | 회사 도메인(`@neolab.net`)만. 이미 등록된 계정 · 승인 대기 중인 계정은 요청할 수 없다 |

- [승인 요청] 또는 Enter → 요청이 `MEM-03` 직원 계정의 **승인 요청**에 나타나고, ADMIN 의 좌측 메뉴 [직원 계정] 옆에 대기 건수가 붙는다. 역할은 STAFF · 부서 미지정으로 요청된다.
- 보낸 뒤에는 두 칸이 잠기고 [← 로그인으로]만 남는다. 거절된 이메일은 다시 요청할 수 있다.
- 승인되면 그 이메일로 로그인한다(초기 비밀번호 = 이메일).
- 제목 옆 ⓘ — 승인 요청 절차 안내.

### 4.2 개인정보 수정 (상단 계정 → 모달) (S7 · S8)

| 항목 | 필수 | 규칙 |
|---|---|---|
| 이름 | ✔ | 표시 이름 |
| 이메일 | — | **읽기 전용** (변경 불가) |
| 새 비밀번호 | — | **변경할 때만 입력**. 비워두면 기존 비밀번호 유지 |

저장하면 모달이 닫히고 **직전 화면이 그대로 유지**된다(화면 이동 없음).

### 4.3 앱 셸 (S6 · S9 · S10 · S11)

로그인하면 **좌측 메뉴 + 상단 바** 구조의 앱 셸 안에서 모든 화면이 열린다.

| 요소 | 동작 | 화면 |
|---|---|---|
| 좌측 메뉴 | 그룹별로 접었다 펼 수 있다. **현재 화면이 속한 그룹은 항상 펼쳐진다** | S6 |
| 메뉴 접기 **«** | 사이드바가 **아이콘 레일**로 줄어든다 | S9 |
| 레일 펼치기 **»** · 로고 | 사이드바를 다시 편다 | S9 |
| 상단 계정 | 누르면 **개인정보수정 / 로그아웃** 메뉴가 열린다 | S7 |
| 로그아웃 | **로그아웃 중…** 전환 화면을 거쳐 로그인 화면으로 | S11 |
| STAFF 로그인 | 메뉴 구성은 같고 **활동 로그**에 **ADMIN** 배지가 붙는다 | S10 |

### 4.4 좌측 메뉴 ↔ 화면코드

| 그룹 | 메뉴 | 화면code |
|---|---|---|
| — | 대시보드 | `DSH-01` |
| 코드 | SOBP 맵 | `SOB-01` |
| 코드 | 코드 프로젝트 (전 서비스 공통) | `PRJ-01` |
| 티켓 발급 | App Key 관리 (계정 발급) | `TKT-01` |
| 티켓 발급 | N Key 관리 | `TKT-02` |
| 서비스 관리 ▸ CasterN 서비스 관리 | 편집 프로젝트 | `PRJ-02` |
| 서비스 관리 ▸ CasterN 서비스 관리 | PUI 코드 (페이퍼) | `PRJ-06` |
| 서비스 관리 | 폼솔루션 (**예정**) | `SVC-01` |
| 멤버 관리 | 고객사 관리 | `MEM-01` |
| 멤버 관리 | 활동 로그 ★ADMIN | `LOG-01` |
| 멤버 관리 | 직원 계정 ★ADMIN `PC-297` | `MEM-03` |
| 정보 | 코드 관리 정보 | `INF-01` (하위 탭 `INF-04` OID 관리대장) |
| 정보 | 브랜드(CI) · Ncode Center 동작 흐름 | (내부 참조 · PRD 없음) |

사이드바 전체는 접기/펼치기가 가능하며, 접은 상태에서도 각 메뉴로 이동할 수 있다.

**하위 메뉴가 있는 항목**(예: CasterN 서비스 관리)은 **항목을 누르면 하위 메뉴가 접혔다 펼쳐진다.**

| 동작 | 결과 |
|---|---|
| 하위가 있는 항목 클릭 | 하위 메뉴 접기 ⇄ 펼치기 (화면 이동 없음). 오른쪽 표식 `▾`(펼침) / `▸`(접힘) |
| 기본 상태 | 펼침 |
| 하위 화면에 머무는 동안 | 접어도 **펼친 상태가 유지**된다(현재 위치를 잃지 않도록) |
| 하위 메뉴 클릭 | 해당 화면으로 이동 |

**서비스 관리 그룹의 확장 규칙** — NcodeCenter는 사내에서 **Ncode를 쓰는 모든 서비스**의 프로젝트 현황(집계·상태)을 관리한다.
서비스별로 관리 메뉴를 두며, 화면이 아직 없는 서비스는 **예정** 표시와 함께 안내 화면(`/services/{key}`)으로 연결된다.
서비스 추가는 `SOB-02`의 **사용 서비스** 항목과 짝을 이룬다 — 그 서비스로 지정된 코드가 해당 관리 메뉴의 집계 대상이 된다.

### 4.5 공통 목록·필터·검색 패턴 (S14)

전 화면이 아래 패턴을 공유한다. 각 화면 PRD는 **이 화면에만 있는 필터**만 기술한다.

| 패턴 | 동작 |
|---|---|
| **검색 입력** | 입력 즉시 목록이 걸러진다. 입력값이 있으면 `×`(지우기) 버튼이 나타나고, 누르면 검색어가 비워지며 전체 목록으로 복귀 |
| **칩 필터** | 클릭 = 단일 선택(토글 아님). 다시 전체를 보려면 `전체` 칩을 선택 |
| **좌·우 2단 구성** | 좌측 목록에서 항목을 선택하면 우측에 상세가 표시된다. 미선택 시 우측에 안내 문구 표시 |
| **페이지네이션** | `«`(처음) `‹`(이전) `›`(다음) `»`(마지막). 첫/마지막 페이지에서 해당 버튼 비활성 |
| **필터·검색 변경 시** | 목록은 1페이지로 되돌아간다 |
| **초기화 버튼** | 화면 데이터를 시드 상태로 되돌린다. 실행 전 확인창을 띄운다 |
