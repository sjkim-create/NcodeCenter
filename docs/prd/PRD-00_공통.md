## 1. 기능 개요

모든 화면이 공유하는 **로그인·권한·역할·공통 목록/필터/검색 패턴·메시지 규칙**을 정의한다. 각 화면 PRD는 여기서 정의한 규칙을 반복 기술하지 않고 참조한다.

| 항목 | 내용 |
|---|---|
| 대상 사용자 | 네오랩 **내부 직원 전용** (외부 고객 접근 없음 — `P-10`) |
| 역할 | **ADMIN** / **STAFF** 2종 |
| 포함 화면 | 로그인, 개인정보 수정(헤더 모달), 좌측 메뉴·상단바 |
| 적용 범위 | 전 화면 |

## 2. 화면 흐름 (Flow)

```
[비로그인] ──▶ 로그인 화면
                 │  회사 계정(Google) 로그인 성공
                 ▼
              DSH-01 대시보드 (기본 진입 화면)
                 │
                 ├─ 좌측 메뉴 ─▶ TKT-01 / SOB-01 / PRJ-01 / PRJ-02 / PRJ-06
                 │              MEM-01 / LOG-01(ADMIN) / INF-01
                 ├─ 상단 계정 ─▶ 개인정보 수정(모달) → 저장 → 원래 화면 유지
                 └─ 로그아웃 ──▶ 로그인 화면
```

- 미로그인 상태로 화면 경로에 접근하면 **로그인 화면으로 이동**한다.
- 로그아웃 진행 중에는 화면 셸 대신 전환 화면을 보여준다(비로그인 잔상 방지).

## 3. 정책

| 정책 | 이 문서에서의 적용 |
|---|---|
| `P-10` 내부 직원 전용 | 외부 고객 가입·요청 절차 없음. 계정은 회사 도메인 계정만 |
| `PC-002` 행위자 모델 | Customer 역할 폐기. 역할은 ADMIN/STAFF 2종 |
| `P-04` 코드 상태 | 전 화면에서 코드 상태는 **할당됨(발급) / 미발급** 2가지로만 표기. "예약/사용중" 용어 사용 금지 |
| 용어 기준 | 코드 좌표는 **SOBP**(Section–Owner–Book–Page). 한글 "부분" 등 대체어 사용 금지 |

### 3.1 역할·권한

| 역할 | 부여 방식 | 권한 |
|---|---|---|
| **ADMIN** | 직원 명단에 ADMIN으로 등록된 계정 | 전 화면 |
| **STAFF** | 회사 도메인 계정으로 로그인하면 자동 부여(명단에 없는 경우 포함) | `LOG-01` 을 제외한 전 화면 |

> `LOG-01`(활동 로그)은 **메뉴를 숨기지 않는다.** 메뉴에 **ADMIN** 배지가 붙고, STAFF 가 들어가면 그 화면에서 **🔒 접근 권한이 없습니다 / 활동 로그는 관리자(ADMIN) 계정만 열람할 수 있습니다.** 로 막힌다. (S10)

- 회사 도메인(`@neolab.net`) 계정만 로그인할 수 있다. 도메인 검증은 로그인 시 서버에서 재확인한다.
- 명단에 없는 회사 계정은 **STAFF로 자동 등록**되어 바로 사용할 수 있다(별도 승인 절차 없음).

## 4. 사용법

### 4.1 로그인

로그인 화면은 **환경 설정에 따라 둘 중 하나만** 나온다.

| 방식 | 조건 | 절차 | 화면 |
|---|---|---|---|
| **회사 Google 계정(SSO)** | OAuth 자격증명이 설정된 환경 | **[회사 Google 계정으로 로그인]** → 회사 계정 선택 → 성공 시 `DSH-01` | S2 |
| **회사 등록 계정(로컬)** | SSO 미설정 환경 | 이메일 + 비밀번호 입력 후 Enter 또는 [로그인] | S1 · S5 |

> SSO 환경에서는 **세션당 1회** 자동 로그인이 시도된다(취소 시 반복하지 않는다).
> 안내 문구도 갈린다 — SSO: *회사 **Google 계정**으로 로그인하세요. **@neolab.net** 계정이면 승인 없이 바로 이용할 수 있습니다.* / 로컬: *회사에 **등록된 계정**으로 로그인하세요. (내부 직원 전용 · **@neolab.net**)*

입력 항목

| 항목 | 필수 | 규칙 |
|---|---|---|
| 이메일 | ✔ | 회사 도메인 계정 (`name@neolab.net`) |
| 비밀번호 | ✔(로컬 로그인만) | 초기값 = 이메일. Enter로 제출 |

### 4.2 개인정보 수정 (상단 계정 → 모달) (S7 · S8)

| 항목 | 필수 | 규칙 |
|---|---|---|
| 이름 | ✔ | 표시 이름 |
| 이메일 | — | **읽기 전용** (변경 불가) |
| 새 비밀번호 | — | **변경할 때만 입력**. 비워두면 기존 비밀번호 유지 |

저장하면 모달이 닫히고 **직전 화면이 그대로 유지**된다(화면 이동 없음).

### 4.3 앱 셸 (S6 · S9 · S10 · S11)

로그인하면 **좌측 메뉴 + 상단 바** 구조의 앱 셸 안에서 모든 화면이 열린다.

| 요소 | 동작 | 화면 |
|---|---|---|
| 좌측 메뉴 | 그룹별로 접었다 펼 수 있다. **현재 화면이 속한 그룹은 항상 펼쳐진다** | S6 |
| 메뉴 접기 **«** | 사이드바가 **아이콘 레일**로 줄어든다 | S9 |
| 레일 펼치기 **»** · 로고 | 사이드바를 다시 편다 | S9 |
| 상단 계정 | 누르면 **개인정보수정 / 로그아웃** 메뉴가 열린다 | S7 |
| 로그아웃 | **로그아웃 중…** 전환 화면을 거쳐 로그인 화면으로 | S11 |
| STAFF 로그인 | 메뉴 구성은 같고 **활동 로그**에 **ADMIN** 배지가 붙는다 | S10 |

### 4.4 좌측 메뉴 ↔ 화면코드

| 그룹 | 메뉴 | 화면code |
|---|---|---|
| — | 대시보드 | `DSH-01` |
| 코드 | 티켓 발급 | `TKT-01` (하위 `TKT-03`·`TKT-04`) |
| 코드 | SOBP 맵 | `SOB-01` |
| 코드 | 코드 프로젝트 (전 서비스 공통) | `PRJ-01` |
| 서비스 관리 ▸ CasterN 서비스 관리 | 편집 프로젝트 | `PRJ-02` |
| 서비스 관리 ▸ CasterN 서비스 관리 | PUI 코드 (피지컬) | `PRJ-06` |
| 서비스 관리 | 폼솔루션 (**예정**) | `SVC-01` |
| 멤버 관리 | 고객사 관리 | `MEM-01` |
| 멤버 관리 | 활동 로그 ★ADMIN | `LOG-01` |
| 정보 | Ncode 정보 | `INF-01` |
| 정보 | 브랜드(CI) · DB 구조 | (내부 참조 · PRD 없음) |

사이드바 전체는 접기/펼치기가 가능하며, 접은 상태에서도 각 메뉴로 이동할 수 있다.

**하위 메뉴가 있는 항목**(예: CasterN 서비스 관리)은 **항목을 누르면 하위 메뉴가 접혔다 펼쳐진다.**

| 동작 | 결과 |
|---|---|
| 하위가 있는 항목 클릭 | 하위 메뉴 접기 ⇄ 펼치기 (화면 이동 없음). 오른쪽 표식 `▾`(펼침) / `▸`(접힘) |
| 기본 상태 | 펼침 |
| 하위 화면에 머무는 동안 | 접어도 **펼친 상태가 유지**된다(현재 위치를 잃지 않도록) |
| 하위 메뉴 클릭 | 해당 화면으로 이동 |

**서비스 관리 그룹의 확장 규칙** — NcodeCenter는 사내에서 **Ncode를 쓰는 모든 서비스**의 프로젝트 현황(집계·상태)을 관리한다.
서비스별로 관리 메뉴를 두며, 화면이 아직 없는 서비스는 **예정** 표시와 함께 안내 화면(`/services/{key}`)으로 연결된다.
서비스 추가는 `SOB-02`의 **사용 서비스** 항목과 짝을 이룬다 — 그 서비스로 지정된 코드가 해당 관리 메뉴의 집계 대상이 된다.

### 4.5 공통 목록·필터·검색 패턴 (S14)

전 화면이 아래 패턴을 공유한다. 각 화면 PRD는 **이 화면에만 있는 필터**만 기술한다.

| 패턴 | 동작 |
|---|---|
| **검색 입력** | 입력 즉시 목록이 걸러진다. 입력값이 있으면 `×`(지우기) 버튼이 나타나고, 누르면 검색어가 비워지며 전체 목록으로 복귀 |
| **칩 필터** | 클릭 = 단일 선택(토글 아님). 다시 전체를 보려면 `전체` 칩을 선택 |
| **좌·우 2단 구성** | 좌측 목록에서 항목을 선택하면 우측에 상세가 표시된다. 미선택 시 우측에 안내 문구 표시 |
| **페이지네이션** | `«`(처음) `‹`(이전) `›`(다음) `»`(마지막). 첫/마지막 페이지에서 해당 버튼 비활성 |
| **필터·검색 변경 시** | 목록은 1페이지로 되돌아간다 |
| **초기화 버튼** | 화면 데이터를 시드 상태로 되돌린다. 실행 전 확인창을 띄운다 |

### 4.6 활동 로그 자동 기록

아래 행위는 사용자가 별도 조작하지 않아도 **`LOG-01`에 자동 기록**된다.

| 활동 종류 | 발생 화면 |
|---|---|
| 고객사 관리 | `MEM-02` |
| 코드 할당(등록) | `SOB-02` |
| 프로젝트 등록 | `PRJ-01` |
| 티켓 발급 | `TKT-01` · `TKT-03` · `TKT-05` |
| 교재 추가 | `PRJ-04` (신규) |
| 교재 작업 | `PRJ-04` (수정) |
| 로그인 · 로그아웃 | 로그인 화면 |

## 5. 상태별 변화 · 메시지

### 5.1 로그인

| 상황 | 노출 방식 | 문구 | 화면 |
|---|---|---|---|
| 회사 도메인이 아닌 계정 | 인라인 | **회사 계정(@neolab.net)만 로그인할 수 있습니다.** | S3 |
| Google 로그인 실패 | 인라인 | **Google 로그인 중 오류가 발생했습니다. 다시 시도하세요.** | S4 |
| 로컬 로그인 성공 | 인라인 | **{이름}({역할})으로 로그인** → `DSH-01` | S5 |

### 5.2 공통 저장 실패

| 상황 | 노출 방식 | 문구 | 화면 |
|---|---|---|---|
| 브라우저 저장 공간 부족 | 상단 알림 | **⚠ 브라우저 저장 공간이 가득 차 저장하지 못했습니다. 다른 사이트 데이터를 정리한 뒤 다시 저장하세요.** | S12 |
| 할당 저장 실패(`SOB-02`) | 확인창 | **⚠ 할당이 저장되지 않았습니다.** + 실패 사유 | S12 |

### 5.3 메시지 노출 규칙

| 종류 | 사용 기준 | 화면 |
|---|---|---|
| **상단 알림(토스트)** | 저장·삭제 성공 등 결과 통보. 화면 이동 없음 | S12 |
| **인라인 메시지** | 입력 폼의 검증 실패. 해당 폼 안에 표시 | S3 · S4 |
| **확인창** | 되돌릴 수 없는 동작 실행 전 (삭제·초기화) | S13 |
| **이름 입력 확인** | **고객사·프로젝트 삭제**는 대상 이름을 직접 입력해야 [삭제 확정]이 활성화된다 | S13 |
