## 1. 기능 개요

**고객사 관리에서 지정한 사용 서비스**를 기준으로, 그 서비스가 쓰는 고객사를 모아 보는 **조회 전용** 목록이다 `PC-076`.

| 항목 | 내용 |
|---|---|
| 목적 | 서비스 담당자가 **자기 서비스의 고객사만** 골라 본다 |
| 대상 | **casterN 을 제외한** 서비스 — 현재는 **폼솔루션** |
| 기준 | `MEM-02` 고객사 등록·수정 ▸ **사용 서비스** `PC-076` |
| 성격 | **조회 전용** — 고객사 추가·서비스 변경을 여기서 하지 않는다 |

**casterN 은 이 화면을 쓰지 않는다.** 편집량·정산까지 함께 봐야 해서 `PRJ-02` 편집 프로젝트가 그 역할을 한다.

| 사용 서비스 | 그 고객사가 나타나는 화면 | 현재 |
|---|---|---|
| casterN | `PRJ-02` 편집 프로젝트 | 70곳 |
| 폼솔루션 | **이 화면** | 0곳 (서비스 개발 전) |
| *(지정 없음)* | 없음 — SDK 연동(코드만 할당) | 나머지 |

## 2. 화면 흐름 (Flow)

```
사이드바 [폼솔루션 서비스 관리] ─▶ SVC-01 (/services/formsolution)
   │
   ├─ [코드 프로젝트] ─▶ PRJ-01 (그 고객사로 검색)
   ├─ [SOBP 맵] ──────▶ SOB-01
   └─ 지정된 고객사 없음 ─▶ 안내 → MEM-02 에서 사용 서비스 체크
```

## 3. 정책

| 정책 | 이 화면에서의 적용 |
|---|---|
| `PC-076` 사용 서비스 = 고객사 속성 | 목록 기준은 **고객사의 사용 서비스**다. 좌표(SOBP)별 지정이 아니다 — 옛 기준 `PC-057` 은 좌표에 붙어 있어 실제 고객사와 어긋났다 |
| `PC-076` 지정 위치 | 바꾸려면 **`MEM-02` ▸ 사용 서비스** 로 간다. 이 화면과 SOBP 맵은 **읽기만** 한다 |
| 조회 전용 | 고객사를 새로 만들거나 코드를 할당하지 않는다 (`MEM-02` · `SOB-02` 담당) |
| casterN 분리 | casterN 고객사는 `PRJ-02` 가 맡는다 — 이 화면에 중복해서 싣지 않는다 |

## 4. 사용법

### 4.1 목록 (S1)

| 열 | 표시 |
|---|---|
| 고객사 | 사용 서비스에 이 서비스가 체크된 고객사 · **가나다순** |
| 할당 좌표 (S/O) | 코드 종류 배지 + **S · O** 칩 · **최대 6건**, 넘으면 `외 {n}건` |
| 코드 프로젝트 | 그 고객사의 코드 프로젝트 건수 |
| 발급 규모 | 발급 코드 수 합계 |
| (작업) | **[코드 프로젝트]** → `PRJ-01` · **[SOBP 맵]** → `SOB-01` |

머리말에 **{n}곳** 배지와 *"고객사 관리에서 사용 서비스 = {서비스} 로 지정한 고객사입니다"* 안내가 붙는다.

### 4.2 지정된 고객사 없음 (S2)

폼솔루션은 서비스 개발 전이라 **0곳**이다. 빈 카드에서 어디서 지정하는지 알려 준다.

> **아직 이 서비스로 지정된 고객사가 없습니다.**
> **고객사 관리 ▸ 사용 서비스** 에서 **폼솔루션** 를 체크하면 여기에 나옵니다 `PC-076`.

### 4.3 casterN 고객사는 여기 나오지 않는다 (S3)

casterN 으로 지정된 고객사는 이 목록이 아니라 **[편집 프로젝트](`PRJ-02`)** 에서 다룬다 — 편집량·정산까지 함께 봐야 하기 때문이다.

| 고객사의 사용 서비스 | 나타나는 화면 |
|---|---|
| casterN | `PRJ-02` 편집 프로젝트 (70곳) |
| 폼솔루션 | **이 화면** (0곳) |
| *(지정 없음)* | 어느 화면에도 나오지 않는다 — SDK 연동(코드만 할당) |
