## 1. 기능 개요

**이 콘솔(NcodeCenter)을 쓰는 내부 직원**을 보고 관리하는 화면이다. 직원 이름은 N Key 발급의 **담당자**(`PC-296`)와 활동 로그의 **직원**으로 쓰인다.

| 항목 | 내용 |
|---|---|
| 권한 | **ADMIN 전용** — 메뉴가 ADMIN 에게만 보이고, STAFF 가 주소로 들어와도 본문 대신 🔒 안내 |
| 진입 | 좌측 메뉴 **[멤버 관리] ▸ [직원 계정]** (`/staff`) |
| 등록 | **승인 요청 → ADMIN 승인** `PC-299` — 처음 쓰는 직원이 로그인 화면 **[첫 방문 — 승인 요청]**에서 이름 · 회사 이메일로 요청하면, 이 화면 **승인 요청**에 나타난다. ADMIN 이 [승인]하면 **STAFF · 사용 중 · 부서 미지정**으로 명단에 들어가고 그 이메일로 로그인할 수 있다(초기 비밀번호 = 이메일). 승인 전에는 로그인할 수 없다. 미리 넣어 둔 직원 명단에 있는 사람은 승인 없이 명단의 역할로 등록돼 있다. **ADMIN 이 직접 등록**도 할 수 있다 — 직원 표 머리 **[＋ 직원 등록]** `PC-309` |
| 삭제 | **없음** — 그만둔 직원은 「사용 중지」(활동 로그 · 담당자 기록이 이름을 쓰므로 지우지 않는다) |
| 기록 | 승인 요청 · 승인 · 거절, 이름 · 부서 · 역할 · 사용 여부를 바꾸면 활동 로그(접속)에 남는다 |

### 역할 차이

| 역할 | 쓸 수 있는 메뉴 |
|---|---|
| **ADMIN** | 모든 메뉴 + **활동 로그**(`LOG-01`) · **직원 계정**(이 화면) |
| **STAFF** | 고객사 관리 · 코드 할당 · 편집 · App Key / N Key 발급 · 정산 등 **업무 메뉴 전부**. 활동 로그 · 직원 계정은 보이지 않는다 |

관리자(ADMIN)는 **한 명 이상** 있어야 한다.

## 2. 화면 흐름 (Flow)

```
로그인 화면 [첫 방문 — 승인 요청] ─▶ 이름 · 회사 이메일 ─▶ 승인 요청(대기)
   └ 좌측 메뉴 [직원 계정] 옆 대기 건수 n (ADMIN)
좌측 메뉴 [멤버 관리] ▸ [직원 계정] (ADMIN)
   └─▶ MEM-03  상태 칩 · 검색 · [🔔 승인 요청 n건](있을 때만 → 모달) · 직원 표
          ├ 승인 모달 [승인] ─▶ 명단에 STAFF 로 들어감 · 로그인 가능 · LOG-01
          ├ 승인 모달 [거절] ─▶ 확인창 ─▶ 요청에서 빠짐 · LOG-01 (다시 요청할 수 있음)
          ├ 이름 칸 고침 ─▶ 벗어나거나 Enter 면 저장 · LOG-01
          ├ 부서 · 역할 고름 ─▶ 바로 저장 · LOG-01
          └ [사용 중] / [사용 중지] 누름 ─▶ 바로 바뀜 · LOG-01
STAFF 가 /staff 로 들어옴 ─▶ 🔒 접근 권한이 없습니다
```

## 3. 정책

| 정책 | 이 화면에서의 적용 |
|---|---|
| `P-10` · `PC-122` 콘솔 로그인 = 회사 계정 | 직원 = 회사 계정(@neolab.net)으로 로그인하는 내부 직원. 이메일 = 로그인 계정이라 고칠 수 없다 |
| `PC-299` 승인 후 사용 | 처음 쓰는 직원은 승인 요청 → ADMIN 승인 후 로그인. 승인 대기 · 거절 · 미등록 계정은 로그인할 수 없다. 삭제하지 않는다(`PC-297` 자동 등록 · `PC-298` 승인 없음은 폐기) |
| `PC-309` 직접 등록 | ADMIN 은 승인 요청 없이 [＋ 직원 등록]으로 바로 등록할 수 있다(사용 중 · 초기 비밀번호 = 이메일). 같은 이메일의 대기 승인 요청은 승인으로 닫힌다 |
| `PC-297` 이름 유지 | 이 화면에서 고친 이름 · 부서 · 역할 · 사용 여부는 다시 로그인해도 바뀌지 않는다(이름은 비어 있을 때만 회사 프로필 값) |
| `PC-297` 사용 중지 | 사용 중지한 직원은 로그인할 수 없다 — 회사 계정으로 들어와도 콘솔에 들이지 않는다 |
| `PC-297` 관리자 1명 이상 | 마지막 ADMIN 은 STAFF 로 바꾸거나 사용 중지할 수 없다. 로그인한 내 계정은 사용 중지할 수 없다 |

## 4. 사용법

### 4.1 화면 구성

| 영역 | 내용 | 화면 |
|---|---|---|
| 승인 요청 `PC-299` `PC-303` | **대기 요청이 있을 때만** 직원 표 머리 오른쪽에 **[🔔 승인 요청 n건]** — 누르면 바로 **승인 모달**. 모달 = 한 줄에 **이름 · 이메일 · 요청 일시**(년월일 시:분) · **[승인] [거절]**(고객사 관리 승인 모달과 같은 모양). 처리한 줄은 사라지고, 모달 위에 초록 줄 **✅ {이름} 승인 — STAFF 로 직원 명단에 들어갔습니다.** / **거절 — {이름}** | S5 |
| [＋ 직원 등록] `PC-309` | 직원 표 머리 오른쪽(승인 요청 버튼 옆). 누르면 **직원 등록 모달** — **이름 * · 회사 이메일(로그인 계정) * · 부서(기본 미지정) · 역할(기본 STAFF)** · [취소] [등록]. 이름 칸에 커서, Enter 로도 등록. 등록하면 모달이 닫히고 명단에 **사용 중**으로 들어간다(초기 비밀번호 = 이메일) | S6 |
| 머리 줄 | 「직원 계정」 · ⓘ(직원 계정이란 — 승인 요청 · 사용 중지 안내) · 상태 칩 **[전체 n] [사용 중] [사용 중지 n]** · 검색(이름 · 이메일 · 부서) | S1 · S2 |
| 직원 표 | 이름 · 이메일 (로그인 계정) · 부서 · 역할 ⓘ · 상태. **정렬**: 이름 · 부서 · 역할 · 상태 머리를 누르면 그 순서(▲ / ▼ · 다시 누르면 반대 · 기본 이름순 · 부서 미지정은 끝 · 역할은 ADMIN → STAFF · 상태는 사용 중 → 사용 중지 · 같으면 이름순). **줄 고정**: 순서는 머리를 누를 때만 다시 정하므로 사용 중지 · 역할 · 이름 · 부서를 바꿔도 줄이 그 자리에 머문다. 사용 중지 줄은 흐리게 | S1 |
| 역할 ⓘ | 역할 머리의 ⓘ — ADMIN · STAFF 차이(1장 「역할 차이」) | S1 |

### 4.2 항목

| 항목 | 입력 | 규칙 | 화면 |
|---|---|---|---|
| 이름 | 표에서 바로 고침 | 칸을 벗어나거나 **Enter** 면 저장, **Esc** 는 되돌림. 비우면 저장하지 않고 원래 이름으로. 내 계정에는 「나」 표시 | S1 · S3 |
| 이메일 (로그인 계정) | 보기 전용 | 로그인한 회사 계정 그대로 — 고칠 수 없다 | S1 |
| 부서 | 선택 | **국내사업팀 · 해외사업팀 · 서비스기획팀 · SW개발팀 · 펌웨어개발팀 · 개발품질팀 · 재무회계팀** `PC-305`. 처음 등록 때는 미지정. 예전 이름(국내사업부 · 해외사업부 · 펌웨어 팀)으로 저장된 직원은 새 이름으로 바뀐다 | S1 |
| 역할 | 선택 | ADMIN / STAFF — 고르면 바로 저장. 마지막 ADMIN 은 STAFF 로 못 바꾼다 | S1 · S3 |
| 상태 | 누름 | **사용 중 ↔ 사용 중지**. 내 계정 · 마지막 ADMIN 은 사용 중지할 수 없다 | S1 · S3 |
| 승인 요청 [승인] | 누름 | 확인 없이 바로 — 명단에 STAFF · 사용 중 · 부서 미지정으로 들어간다. 부서 · 역할은 승인한 뒤 표에서 고친다 | S5 |
| 승인 요청 [거절] | 누름 | 확인창 **{이름}({이메일}) 의 승인 요청을 거절할까요?** → 요청에서 빠진다. 그 이메일은 다시 요청할 수 있다 | S5 |
