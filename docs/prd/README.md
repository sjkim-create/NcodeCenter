# NcodeCenter PRD

> IA(메뉴구조도) `NcodeCenter_001_IA_001` v2.0 기준. **1 화면코드 = 1 PRD 파일**(보조 화면은 부모 PRD의 섹션).
> 파일명 규칙: `{화면code}_{화면명}.md`

## 작성 규칙

1. **디자인 스펙을 쓰지 않는다** — 색상·간격·폰트·배치·모달 폭 등 시각 명세 제외. 정본은 디자인/구현.
2. **DB 구조를 쓰지 않는다** — 테이블·컬럼·스키마는 [DB 구조](../NcodeCenter-DB.md).
3. **정책은 참조만 한다** — 정책 원문은 [정책 정의서](../NcodeCenter-정책정의서.md)(`P-NN`)·[운영 정책](../NcodeCenter-Operations-Policy.md)(`PC-NNN`). PRD는 "이 화면에 어떻게 적용되는가"만.
4. **화면 간 이동은 화면코드로 명시한다** — "저장 후 목록으로" ✕ → "저장 후 `MEM-01`로 복귀" ○.
5. **안내·에러 메시지는 전문을 적는다** — "에러 표시" ✕ → 실제 문구 ○.

| 6 | 연결 화면 |
| 7 | 미결 · 협의 |

### 서비스 관리 (예정, PRD 미작성)

NcodeCenter는 사내에서 Ncode를 쓰는 **모든 서비스**의 프로젝트 현황을 관리한다. 현재 화면이 있는 서비스는 CasterN뿐이며, 나머지는 안내(예정) 화면만 있다.

| 화면code | 서비스 관리 메뉴 | 경로 | 상태 |
|---|---|---|---|
| — | **CasterN 서비스 관리** | 편집 프로젝트 · PUI 코드 | ✅ PRD 작성 |
| — | (전 서비스 공통) | **코드 프로젝트** = [코드] 그룹 — 사용 서비스 필터로 전 서비스 조회 | ✅ PRD 작성 |
| SVC-01 | 폼솔루션 서비스 관리 | `/services/formsolution` | ⬜ 예정 |

> **아이글 · NeoStudio2 · Ncode 프린터는 별도 관리 메뉴를 두지 않는다.** 두 서비스의 코드는 `PRJ-01 코드 프로젝트`의 **사용 서비스 필터**로 조회한다(사용 서비스 값 자체는 `SOB-02`에 그대로 유지).

서비스 추가 시: `web/lib/menu.ts`의 `SERVICE_MENUS`에 1건 추가 → IA에 화면코드 등록 → 화면 구현 시 PRD 작성.
