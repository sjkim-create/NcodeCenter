## 1. 기능 개요

발급된 티켓 **한 건**을 열어 기록을 바로잡고 정산을 등록하는 화면이다. **N Key 와 App Key 를 같은 화면으로** 연다.

| 항목 | 내용 |
|---|---|
| 권한 | STAFF / ADMIN |
| 진입 | `TKT-03` 목록의 **발급번호 · 발급 내용 · [상세] · [정산]** |
| 대상 | **N Key · App Key 공통** — 종류에 따라 상단 표기만 달라진다 |
| 구성 | **탭 2개** — 발급 기본정보 / 정산 정보 |
| 저장 | **[저장] 한 번으로 두 탭 내용이 함께 기록된다** |

> 이 화면의 수정은 **발급 원장의 기록을 바로잡는 것**이다. 이미 내려받은 키 파일은 바뀌지 않는다.

## 2. 화면 흐름 (Flow)

```
TKT-03 Key 관리 목록
   ├─ 발급번호 · 발급 내용 · [상세] ─▶ TKT-05  (발급 기본정보 탭)
   └─ [정산] ───────────────────────▶ TKT-05  (정산 정보 탭이 선택된 상태)

TKT-05
   ├─ 탭 전환 ── 발급 기본정보 ⇄ 정산 정보   (저장 전 내용은 유지)
   ├─ [저장] ─(검증)─▶ 두 탭 내용 함께 기록 ─▶ 이 화면에 머무름
   ├─ [목록] ────────▶ TKT-03
   └─ [발급 기록 삭제] ─(확인)─▶ 목록에서 제거 ─▶ TKT-03
```

## 2-1. Key 정보 항목 순서 `PC-070`

좌표 → 범위 → 코드 종류 → 시간 → 티켓 속성 순으로 읽도록 고정한다. `Issued Time` 은 **`Code Type` 뒤**에 온다.

| 순서 | 항목 |
|---|---|
| ① 소유 | `Company Name` · `Account Id` · `App Key` · `Service` · `Usage` · `Used Customer` |
| ② 좌표 | `Section` · `Owner` |
| ③ 범위 | `Book Start` · `Book Volume` · `Book End` · `Page Start` · `Page Volume` · `Page End` |
| ④ 종류 | `Code Type` |
| ⑤ 시간 | `Issued Time` · `Valid Until Time` |
| ⑥ 티켓 | `Ticket Type` · `Ticket Version` |

- **항목명은 모두 띄어쓴다** `PC-065` — `AccountId` → `Account Id`, `IssuedTime` → `Issued Time`.
- 이미 저장된 키의 옛 항목명·순서는 **화면에 올릴 때 자동으로 맞춘다**(별도 작업 없음).

| 정책 | 이 화면에서의 적용 |
|---|---|
| `P-15` 티켓 = N Key / App Key + 정산 | 종류와 무관하게 같은 화면으로 연다 |

| 발급 번호 | 삭제해도 **다시 쓰지 않는다** |

| `PC-016` 출처 구분 | 과거 발급 이력(대장)도 같은 화면에서 연다 |

## 4. 사용법

### 4.1 머리말

발급 건을 식별하는 값이 한 줄로 붙는다 — **종류(N Key / App Key)** · **발급 {No}번** · **고객사** · 과거 이력이면 **대장**.

### 4.2 탭 1 — 발급 기본정보

| 항목 | 수정 | 내용 |
|---|---|---|
| 고객사 | **잠금** | 원장 기준값 |
| 발급일시 | **잠금** | 원장 기준값 |
| 발급인 | **잠금** | 없으면 `-` |
| **발급 내용** | 가능 | 목록에 표기되는 한 줄 요약. **필수** |
| **Key 정보** | 값만 가능 | 발급 당시 파라미터를 `Key` · `Value` 표로 보여준다 |

**Key 정보** 는 발급 시점에 기록된 항목을 그대로 나열한다(`Section` · `Owner` · `BookStart` · `BookVolume` · `PageStart` · `PageVolume` · `ValidUntilTime` · `PatternType` 등). **항목을 추가하거나 지울 수는 없고 값만 고친다.** 종류에 따라 항목 구성이 다르다.

> 원래 숫자였던 항목은 저장할 때 숫자로 되돌린다. 표시·재사용 시 형식이 흐트러지지 않게 하기 위함이다.

### 4.3 탭 2 — 정산 정보

| 과금 유형 | 추가 입력 |
|---|---|
| **미정** | 없음 — 아직 결정하지 않은 상태 |
| **유료** | **금액(원) 필수** |
| **무료** | 없음 (사유는 비고) |
| **체험** | **체험 만료일** — 기본값은 발급일 + 1개월 |

**비고** 는 모든 유형에서 입력할 수 있다(사유·계약 정보). 이전에 정산을 등록한 적이 있으면 **최근 등록 일시와 등록자**가 함께 표시된다.

### 4.4 저장

**[저장]** 하나가 **두 탭 내용을 함께 기록**한다. 탭은 화면을 나눠 보여줄 뿐이고 저장 단위가 아니다.

검증에 걸리면 **해당 탭으로 자동 전환**하고 그 자리에서 멈춘다.

| 순서 | 검사 | 실패 시 |
|---|---|---|
| ① | 발급 내용이 비었는가 | **발급 기본정보** 탭으로 전환 |
| ② | 유료인데 금액이 0인가 | **정산 정보** 탭으로 전환 |

저장해도 **목록으로 돌아가지 않고 이 화면에 머무른다** — 이어서 다른 항목을 고칠 수 있다.

### 4.5 계산 규칙

**(가) 체험 만료일 기본값**

```
체험 만료일 기본값 = 발급일 + 1개월

예) 발급일 2026-08-26 → 기본값 2026-09-26
    이 값은 그대로 두거나 달력으로 바꿀 수 있다
```

**(나) 정산 유형을 바꿀 때의 값 처리**

```
유료 → 다른 유형 : 금액을 0 으로 되돌린다
체험 → 다른 유형 : 체험 만료일을 비운다
비고             : 유형과 무관하게 유지된다

예) 유료 ₩3,500,000 → 무료 로 변경 후 저장
    금액 0 · 비고 유지 · 목록 금액 열은 '-' 로 표시
```

## 5. 상태별 변화 · 메시지

### 5.1 상태

| 상태 | 화면 | 화면 번호 |
|---|---|---|
| 발급 기본정보 탭 | 고객사·발급일시·발급인 잠금 + 발급 내용 + Key 정보 표 | S1 |
| Key 정보 값 수정 | 표의 값만 고친다. 항목 추가·삭제 없음 | S2 |
| 정산 정보 탭 — 미정 | 과금 유형 4칸 중 미정 선택. 추가 입력 없음 | S3 |
| 정산 정보 탭 — 유료 | 금액 입력칸이 나온다 | S4 |
| 정산 정보 탭 — 체험 | 체험 만료일이 나온다(기본 발급일+1개월) | S5 |
| 정산 정보 탭 — 무료 | 청구하지 않는다는 안내 | S6 |
| 검증 실패 — 발급 내용 | **발급 기본정보** 탭으로 전환 후 메시지 | S7 |
| 검증 실패 — 유료 금액 | **정산 정보** 탭으로 전환 후 메시지 | S8 |
| 저장 완료 | 두 탭 내용이 함께 기록된다 | S9 |
| App Key 건 열람 | 종류 표기가 **App Key** 로 바뀐다. 구성은 동일 | S10 |
| 발급 기록 삭제 확인 | 확인창 | S11 |
| 발급 기록 없음 | 잘못된 주소로 들어온 경우 | S12 |

### 5.2 메시지

| 상황 | 노출 방식 | 문구 | 화면 |
|---|---|---|---|
| 발급 내용 비움 | 인라인 | **발급 내용을 입력하세요.** | S7 |
| 유료인데 금액 0 | 인라인 | **유료는 금액을 입력해야 합니다.** | S8 |
| 저장 성공 | 인라인 | **발급 기본정보와 정산 정보가 저장되었습니다.** | S9 |
| 삭제 확인 | 확인창 | **발급 {No}번 기록을 삭제할까요?** | S11 |
| 기록 없음 | 안내 | **발급 기록을 찾을 수 없습니다.** — [Key 관리 목록으로] | S12 |
