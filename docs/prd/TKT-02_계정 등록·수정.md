## 1. 기능 개요

`TKT-01` 계정 목록에서 열리는 **두 화면**이다. 여기 계정은 **티켓 고객사의 키 발급 계정**이다 `PC-128`.

| 화면 | 주소 | 하는 일 |
|---|---|---|
| **계정 및 App Key 등록** | `/tickets/account/new` | 계정 정보를 입력하고, 원하면 App Key 를 함께 발급해 **[계정 추가]** |
| **계정 및 App Key 상세 수정** | `/tickets/account/{email}` | 계정 정보를 고쳐 **[저장]**, App Key 아래 **코드 범위(=티켓)** 를 발급·삭제한다 |

| 항목 | 내용 |
|---|---|
| 권한 | STAFF / ADMIN |
| 진입 | `TKT-01` 의 **[＋ 계정 추가]** / 목록 행 클릭 |
| 탭 | **계정 정보 · App Key 발급** 2개 — 한 번에 한 탭 `PC-062` |
| 고객사 | **티켓 고객사** — nkey(HLP) 대장 프로젝트명 + 화면에서 **[＋ 신규 등록]** 한 고객사 `PC-123` |
| 선행 조건 | App Key 까지 발급하려면 그 티켓 고객사에 **발급 범위**(대장 이력 또는 SOBP 맵 (K) 할당)가 있을 것 |

> **인증 서비스·권한은 이 화면에 없다** `PC-131`. 서비스 로그인 계정과 CasterN 권한은 고객사 관리 `MEM-02` 의 **계정 및 서비스 권한**에서 다룬다 `PC-128`.
>
> **App Key 는 계정당 1개**다 `PC-050`. 발급은 선택이라 계정만 등록해 두고 나중에 붙일 수 있다. 키 아래 **코드 범위(=티켓)를 여러 건** 발급하고, **사용기간은 티켓마다** 지정한다 `PC-118`.

## 2. 화면 흐름 (Flow)

```
TKT-01 계정 목록
   ├─ [＋ 계정 추가] ─▶ TKT-02 등록  (탭: 계정 정보 / App Key 발급)
   │      계정 정보(고객사·NAME·ID·PWD·ADDR·HOMEPAGE)
   │        └─ 고객사 [＋ 신규 등록] ─▶ 티켓 고객사 등록(이름 + 발급 범위 1건)
   │      App Key 발급(선택) ─▶ 발급 범위 + Book·Page + Code Type + 사용기간
   │      └─ [계정 추가] ─▶ TKT-01 목록 (범위를 골랐으면 App Key 동시 발급)
   │
   └─ 행 클릭 ─▶ TKT-02 상세 수정
          ├─ [저장] ────────────────────▶ 계정 정보 반영
          ├─ [코드 범위 발급] ───────────▶ 티켓 추가 + 원장 티켓 → TKT-03 · LOG-01 `PC-119`
          ├─ 발급 내역 [티켓 삭제] ──────▶ 그 티켓 + 연결 원장 티켓(마지막이면 키까지) `PC-121`
          ├─ 발급 내역 [키 삭제] ────────▶ 키 전체 삭제
          ├─ 발급 내역 티켓 선택 ────────▶ 아래 Key 정보 갱신 `PC-120`
          └─ [계정 삭제] ─(확인창)───────▶ 계정 + 연동 App Key 삭제 → TKT-01
```

## 3. 정책

| 정책 | 이 화면에서의 적용 |
|---|---|
| `PC-123` 티켓 고객사 | 고객사는 **고객사 관리와 별개**인 티켓 고객사다. 등록해도 고객사 관리에는 생기지 않는다. 주소·사용 서비스를 끌어오지 않는다 |
| `PC-128` 계정 분리 | 이 화면 = **키 발급 계정**. 서비스 로그인 계정(권한)은 `MEM-02` 계정 및 서비스 권한 |
| `PC-131` 인증 서비스 삭제 | 인증 서비스·권한 탭과 그 값(Service·Usage 등)을 다루지 않는다 |
| `PC-029` 계정 수 | 고객사당 제한 없음. ID(이메일)는 **전체에서 유일**(서비스 계정 포함) |
| `PC-050` App Key 단위 | **계정당 1개**. 키 아래 **코드 범위(=티켓)를 여러 건** 발급 — 재발급 개념은 없다 |
| `PC-118` 사용기간 = 티켓별 | 사용기간(시작~끝)은 계정이 아니라 **코드 범위(=티켓)마다** 유지된다 |
| `PC-119` 범위 발급 = 원장 티켓 | 범위를 발급할 때마다 `TKT-03` 원장에 APP 티켓 1건. [티켓 삭제] 시 함께 제거 `PC-121` |
| `P-05` 무겹침 | 범위는 **발급 범위 목록에서 고른다**(대장 이력 S/O/B · SOBP (K) 할당). 좌표를 직접 타이핑하지 않고 Book · Page 만 지정한다 |
| `P-02` 코드 종류 | `Code Type` 은 직접 고른다 — PDS2 · PDS3 · PDS4 · OID `PC-064` |
| `PC-132` 문구 | 항목명 `영문 (한글)` · 안내 `~합니다/~하세요` — `TKT-04` N Key 발급과 같은 표현 |

|---|---|---|---|
| 고객사 | ✔ | **티켓 고객사**에서 고른다. 없으면 **[＋ 신규 등록]**(§4.2) | **잠금** |
| NAME (담당자명) | — | | 수정 가능 |
| ID (이메일) | ✔ | 이메일 형식 · 이미 등록된 ID 는 쓸 수 없다 | **잠금**(키 연동 기준값) |
| PWD (비밀번호) | ✔ | 요청이 없으면 **[임의 생성]** 으로 10자리 | 수정 가능 |
| ADDR (주소) | — | 직접 입력 | 수정 가능 |
| HOMEPAGE (홈페이지) | — | | 수정 가능 |

> 사용기간은 계정 정보에 없다. [App Key 발급] 탭에서 **코드 범위를 발급할 때** 지정한다 `PC-118`.

### 4.2 티켓 고객사 신규 등록 `PC-123`

| 항목 | 규칙 |
|---|---|
| 고객사명 * | 티켓 고객사 안에서 유일 |
| 코드 종류 · S · Owner * | PDS3(Ncode) · PDS4(Scode) · PDS2 · OID |
| Start Book · End Book | 비우면 **오너 전체**가 범위 |
| [등록] | 그 고객사가 바로 선택된다. **고객사 관리에는 생기지 않는다**. `TKT-03` [고객사] 탭에도 나온다 |

### 4.3 App Key 발급

| 화면 | 동작 |
|---|---|
| **등록** | [App Key 발급] 탭에서 **발급 범위를 고르면** 계정과 함께 발급, 고르지 않으면 **계정만 등록** `PC-071` |
| **상세 수정** | 범위·사용기간을 고르고 **[코드 범위 발급]** → 키에 티켓 1건 + 원장 티켓 `PC-119` (키가 없으면 첫 발급) |

| 항목 | 규칙 |
|---|---|
| 발급 범위 (대장 이력 · SOBP 할당) | 선택하면 Section·Owner·Book·Code Type 이 자동으로 채워집니다. 없으면 **이 고객사의 발급 범위(대장 이력)가 없습니다.** |
| Start Book · Book 볼륨 (권) | 범위 안에서. **Book End = Start + 볼륨 − 1** `PC-050` |
| Start Page · Page 볼륨 | 계정마다 B·P 영역을 다르게 잡는다 `PC-059` |
| Code Type | PDS2 · PDS3 · PDS4 · OID `PC-064` |
| Valid From Time (사용기간 시작) · Valid Until Time (사용기간 끝) | 이 티켓의 기간. 끝은 날짜 또는 **무제한** `PC-118` |
| 자동·고정 | Section · Owner · Ticket Type(무제한 = Unlimited / 기간 = Period) · Ticket Version 1 |

**발급 결과** — **ID · PWD · App Key**(영문·숫자 29자 `PC-066`)가 나오고 **[전체 복사]** 로 한 번에 복사한다.

### 4.4 발급 내역 · Key 정보

| 영역 | 내용 |
|---|---|
| 키 헤더 | 키 값 · **코드 범위 N개** · 생성 일시 · **[키 삭제]** |
| 티켓 줄 | 코드 종류 · S/O/B/P · 권수 · **사용기간** · **[티켓 삭제]** `PC-118` `PC-121` |
| [티켓 삭제] | 그 티켓과 연결 원장 티켓을 함께 제거. **마지막 티켓**이면 확인 후 App Key 까지 삭제 |
| 티켓 선택 | 아래 **Key 정보**가 그 티켓 값으로 바뀐다. 기본 = 첫 티켓 `PC-120` |
| Key 정보 | Company Name · Account Id · App Key · Code Type · 코드 범위 · 권수 · Valid From/Until Time · Ticket Type · Ticket Version (**Service · Usage 없음** `PC-131`) |
