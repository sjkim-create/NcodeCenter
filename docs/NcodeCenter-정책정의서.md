# NcodeCenter 정책 정의서 (Policy Definition)

> **성격**: 개발팀 전달용 **확정 정책 정의 문서**. 각 정책을 "정의 · 근거 · 개발 반영" 형식으로 규정한다.
> **관계**: 협의 원칙·프로토타입 근거·**변경 이력**은 [운영 정책](NcodeCenter-Operations-Policy.md)(§0 Changelog, §1~6)에 있고, 이 문서는 그 결과를 **정의로 확정**한 것이다. 화면은 [IA](NcodeCenter-IA.md), 구조는 [Structure](NcodeCenter-Structure.md).
> **버전**: 2026-08-03 기준 · 정책ID `P-NN` · 근거는 `PC-NNN`(변경이력).

---

## 1. 목적 · 범위

- **NcodeCenter** = Ncode(SOBP 코드)의 **할당 · 사용 · 만료 상태를 관리하는 중추 시스템**.
- **범위**: 고객사/프로젝트 등록 · 코드 할당(SOBP) · 티켓 발급 · 편집 정산 · 사용 관제 · 활동 로그. **코드 물리 발급/집행은 NDP 위임**.
- **범위 외**: S코드(제외), 외부 고객 직접 가입/요청(폐기).

---

## 2. 용어 정의

| 용어 | 정의 |
|------|------|
| **SOBP** | 코드 좌표 = **S**ection–**O**wner–**B**ook–**P**age. |
| **코드 종류** | **N코드 / G코드** (물리 체계 PDS3≈N, PDS2≈G). |
| **펜 구분** | **Ncp**(소리펜) / **Ndp**(필기펜). 동일 SOBP라도 분리 관리. |
| **코드 상태** | **할당됨(발급) / 미발급(빈 코드)** 2가지. (예약/사용중 구분 없음) |
| **Owner** | 프로젝트/제품라인 단위 (1 업체 N Owner). |
| **Book** | Owner 안의 개별 상품/교재. |
| **공통(커먼)코드** | 여러 고객사가 함께 쓰도록 지정된 코드 = `(타입 k, Section, Owner)`. |

## 3. 정책 정의

### 3.1 도메인 · 코드

| ID | 정책 | 정의 | 근거 | 반영 |
|----|------|------|------|------|
| **P-01** | 코드 좌표 = SOBP | 모든 코드는 Section–Owner–Book–Page로 식별한다. | 협의(§용어) | ✅ |
| **P-02** | 코드 종류 = N/G | 취급 코드는 **N·G 두 가지**. **S코드 제외**. 기준: 해외 N · 국내 소리펜 G · 국내 소리+필기 N (최종 Neo 결정). | PC-001 | ✅ |
| **P-03** | 펜 구분 Ncp/Ndp | 소리펜(Ncp)·필기펜(Ndp)은 동일 SOBP라도 **분리 관리**(구분 관리 원칙). | 협의 §3 | ⬜ DB 필드 필요 |
| **P-04** | 코드 상태 = 할당됨/미발급 | 코드 상태는 **할당됨(발급) / 미발급(빈 코드)** 2가지. **예약(RESERVED)/사용중(IN_USE) 구분·"Ncode 예약" 메뉴는 폐기.** | PC-003·004·005 | ✅ |

### 3.2 할당 규칙

| ID | 정책 | 정의 | 근거 | 반영 |
|----|------|------|------|------|
| **P-05** | 무겹침(최우선) | 신규 할당은 기존 할당과 **절대 겹치지 않는다**. | 협의 §1 | ✅ 엔진+DB EXCLUDE |
| **P-06** | 연속성 = book 단위 | 연속 페이지 부족 시 **book 분리**(각 book 내 page 연속 유지, 조각 병합 금지). 연속성 요건은 **서비스별 분기**(casterN 불필요 · NeoStudio2 book 종속 · 외부는 개발물 따라). | 협의 §1 | 🟡 book분리 구현 / 서비스 플래그 미구현 |
| **P-07** | SO 공유 불가 | Section·Owner는 **프로젝트/고객사 식별 축**으로 공유하지 않는다. 빈 공간이 남아도 재활용 금지. (단, 지정된 공통코드 Owner는 예외) | 협의 §5 | 🟡 표기만 |
| **P-08** | Owner 발급 이원화 | 대형/일반 = **Owner 별도 발급**, 소규모 = **NeoStudio2 Owner 하위 book 흡수**, 폼솔루션 = **별도 Owner 운영**. | 협의 §2 | ⬜ |
| **P-09** | 등급별 SO 차등 | 등급마다 SO(Section–Owner)를 다르게 할당(예: a=S0/1,000p, b=S3/100p), G·N 구분. | 협의 §3 | ⬜ |

| **P-12** | 공통코드 중앙 모델 | 코드 정본 = **`(타입 k, Section, Owner)` 중앙 레지스트리**. k = N(PDS3)·G(PDS2)·A(IDS, 이력전용). 홀더 **1회사=1코드** 분리. 옛 `nspCommon/nwpCommon` 플래그 폐기. | PC-006~009 | ✅ |
| **P-13** | 사용 서비스 · 지정 위치 | 서비스 = **casterN · 아이글 · 폼솔루션 · NeoStudio2 · 서비스없음**. 서비스는 **SOBP 맵의 [직접 코드 할당]에서만 지정**. **코드 프로젝트는 조회·검색 전용**. | PC-010·011 | ✅ |
| **P-14** | 편집 = casterN | 편집 데이터로 만들어진 코드 = **casterN(자동)**. **[편집 프로젝트] 메뉴 = casterN 서비스 관리** 화면. | PC-012 | ✅ |

### 3.4 발급 · 정산

| ID | 정책 | 정의 | 근거 | 반영 |
|----|------|------|------|------|
| **P-15** | 티켓 = N Key / App Key + 정산 | **N Key**=물리 키(오프라인, 계정 불필요) · **App Key**=계정 연동 키. **정산(과금)**=유료/무료/체험/미정. 출처=대장(ledger)/신규발급 구분. | PC-016 | ✅ |
| **P-16** | 정산 — 항목별 단가표(2026) | 소리펜(적용·편집·Compound 2~8언어·슬롯전환·그룹재생·게임·프롬프트·RAG·4도출력)·필기펜(적용·none·action·노트서버) **각 항목 "수량×단가"**. 단가는 전사 기본 → **고객사별 개별 지정**(Company.rates). **청구액 = Σ(수량×단가) × (1−할인율) − 추가할인액**. | PC-018 | ✅ |

## 4. 개발팀 협의 필요 (미확정)

- [ ] 폼솔루션 코드: 등급별로 **S 값을 둘 다** 가질 수 있게 개발 가능한지
- [ ] 서비스별 **페이지 연속성 분기** 처리 방식(casterN/NeoStudio2/외부)
- [ ] **편집 신규 할당** 시 편집 파트 참여 프로세스
- [ ] **소규모 프로젝트 흡수 기준**(별도 Owner vs NeoStudio2 book) 임계 물량
- [ ] **SOBP 맵 필터링(5종)** API 지원, **casterN 사용량 자동 반영** API (개발팀 반영 필요 항목)

---

## 5. 변경 이력

정책 변경은 [운영 정책 §0 Changelog](NcodeCenter-Operations-Policy.md)에 `PC-NNN`으로 누적한다(raw 데이터 정리·정책 변경 시 1행 추가). 이 정의서는 확정 정책의 **현재 스냅샷**이며, 근거 PC는 각 정책 행에 표기했다.
