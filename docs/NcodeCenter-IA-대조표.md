# IA 대조표 — IA(메뉴구조도)의 사본 ↔ 현재 구현

작성 기준: `web/` 실제 화면(JSX) · 2026-08-29
비교 대상: `NcodeCenter 기획 문서.xlsx` → 시트 **IA(메뉴구조도)의 사본** (문서번호 `NcodeCenter_001_IA_001`, 작성일 2026.08.04)

이 문서는 IA를 직접 고치기 위한 참고용이다. 화면코드를 바꾸면 **파일명 3종 + 문서 안의 `**화면 ID**` + Figma 프레임 이름**이 함께 바뀌어야 한다.

---

## 0. 가장 먼저 결정할 것 — TKT 코드 충돌

IA 사본의 `TKT-01 ~ TKT-06` 배정이 **현재 문서·구현과 전혀 다르다.** 같은 코드가 다른 화면을 가리킨다.

| 코드 | IA 사본 (제안) | 현재 문서·구현 | 상태 |
| --- | --- | --- | --- |
| `TKT-01` | 계정발급 | **N Key 발급** | 충돌 |
| `TKT-02` | 계정 추가(등록/수정) | — | 신규 |
| `TKT-03` | Key 관리 | **계정 발급** | 충돌 |
| `TKT-04` | Key 정보 확인 | **Key 발급 정산** | 충돌 |
| `TKT-05` | 정산 등록 | 정산 등록 | 일치 (PRD만 존재) |
| `TKT-06` | N Key 발급 | **계정 등록·수정** | 충돌 |

IA 사본대로 가면 `TKT-01` ↔ `TKT-06`, `TKT-03` ↔ `TKT-04`가 사실상 자리를 맞바꾸는 재배정이다.
영향 범위는 아래 4곳 전부다.

- `docs/prd/TKT-*.md` (5개)
- `docs/screens/TKT-*.html` (4개)
- `docs/figma/prd/TKT-*.md` (4개) + 각 파일의 `**화면 ID**:` 줄
- `docs/figma/prd/FRAME-NAMES.md` + Figma 파일의 실제 프레임 이름 (`TKT-01:S01 …` 형태)

**권장** — 재배정 대신 **기존 코드를 유지하고 신규 화면에만 새 번호를 부여**하는 쪽이 문서 유실 위험이 적다. 재배정을 택한다면 4곳을 한 번에 일괄 변경해야 한다.

## 2. IA 사본 ↔ 현재 구현 행별 대조

### 2-1. 코드_티켓 발급

| IA 사본 | 현재 구현 | 차이 |

## 4. IA 수정 시 결정이 필요한 항목

1. **TKT 코드 재배정 여부** — 재배정하면 문서 4곳 일괄 변경. 유지하면 IA 쪽 번호를 현재 문서에 맞춘다.
2. **`TKT-04` Key 정보 확인 / `MEM-03` 업무요청 메모** — 탭·패널로 흡수됐다. 화면코드를 없앨지, 부속 화면으로 남길지.
3. **`INF-02`/`INF-03`** — 현재 「확장 언어 슬롯」 탭 하나. IA대로 Common/Cake를 나눌지, 탭 하나로 합칠지.
4. **신규 화면코드 3건 부여** — 발급 상세·수정 / N Key 불러오기 / 편집 고객사 추가
5. **누락 3건 추가** — `OID-01` OID 관리대장, 브랜드 (CI), DB 구조
6. **모달 → 페이지 승격 반영** — `TKT-02`(계정 등록/수정), `PRJ-03`(편집 프로젝트 상세)는 이제 별도 라우트다.
7. **「서비스 관리」 그룹 신설 여부**

## 6. 권장 매핑 — 이대로 IA에 옮기면 된다

### 6-0. 원칙

**기존 화면코드는 하나도 바꾸지 않는다.** 현재 문서에 `TKT-02` 가 비어 있어서, 신규 화면을 빈 번호에 채우는 것만으로 정리된다. 재배정 없음 = Figma 프레임 이름과 기존 PRD 19종이 그대로 살아 있다.

### 6-2. IA 사본에서 지울 행

탭·패널로 흡수돼 **독립 화면이 아니게 된 것**들이다.

| IA 사본 행 | 지우는 이유 |
| --- | --- |
| `TKT-02` 계정 추가(등록/수정) | `TKT-06` 계정 등록·수정과 같은 화면 |
| `TKT-04` Key 정보 확인 | `TKT-02` 발급 상세의 「발급 기본정보」 탭 안 표 |
| `MEM-03` 고객사 수정_업무요청 메모 | `MEM-02` 수정 모달의 우측 패널 |
| `INF-02` Common 확장 언어 슬롯 | `INF-01` 「확장 언어 슬롯」 탭 (Common/Cake 미분리) |
| `INF-03` Cake 확장 언어 슬롯 | 위와 같은 탭 |
| `INF-04` 발급구조 | `INF-01` 「발급 구조」 탭 |
| `INF-05` 알아야 할 사항 | `INF-01` 「알아야 할 사항」 탭 |

> `INF-02`/`INF-03` 번호는 위에서 비니까 **브랜드 (CI) / DB 구조**에 재사용한다.
> 나중에 Common·Cake 슬롯을 별도 화면으로 뽑을 계획이 있으면 `INF-04`/`INF-05` 를 그쪽에 쓰면 된다.

### 6-3. IA 사본에서 코드를 바꿔 적을 행

IA 사본이 제안한 번호를 **현재 문서 번호로 되돌린다.**

| 계정 발급(목록) | `TKT-01` | `TKT-03` |
| Key 관리(목록) | `TKT-03` | `TKT-04` |

### 6-4. 실제로 손봐야 할 파일 — 개명 2건

메뉴명이 바뀐 것만 파일명·본문 제목을 맞춘다. **화면 ID 값은 그대로**라 Figma 프레임은 건드릴 필요 없다.

| 현재 파일명 | 바꿀 이름 |

### 6-5. 새로 써야 할 문서 — 5건

각각 `docs/prd/*.md` → `docs/screens/*.html` → `docs/figma/prd/*.md` 순으로 만든다.

| 코드 | 화면명 | 비고 |
| --- | --- | --- |
| `TKT-02` | 발급 상세 · 수정 | 문서 3종 전부 없음 |
