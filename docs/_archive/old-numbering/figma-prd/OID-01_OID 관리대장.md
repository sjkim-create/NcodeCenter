## 2. 화면 구성

### 개요

**OID 관리대장** — OID 는 **index 만 갖는 코드**로, 외부 코드를 **우리 펜으로 읽으려고** 만든 방식이다. 펜으로 찍으면 코드 값이 **1개만** 나오고, 총량이 **약 6만 개**뿐이라 분량이 적으면 **book 으로 나누지 않는다**.

대장은 업체 구분에 S/O 를 써 왔고 분량이 늘어난 업체만 book 번호로 나눴는데, 그 **book 번호가 곧 OID index** 로 보인다. 그래서 이 화면은 **업체 + index** 로 모아 본다. 좌표 기준 조회는 `SOB-01` 의 종류 **[OID]** 필터로 한다 `PC-035`. (옛 **IDS**(A코드) 표기 = OID 동일)

### 상태 구성

이 화면은 **4개 상태**로 나뉜다. 구분: 기본 · 분기 · 차단

| 상태 | Figma 프레임 | 제목 | 구분 |
|---|---|---|---|
| `S1` | `OID-01:S01` | 기본 — index 관리 업체 | 기본 |
| `S2` | `OID-01:S02` | book 미분할 업체 | 분기 |
| `S3` | `OID-01:S03` | 필터 · 검색 | 분기 |
| `S4` | `OID-01:S04` | 검색 결과 없음 | 차단 |

## 3. 상태별 변화

### OID-01: S01 기본 — index 관리 업체

*화면 정의서 상태 `S1`*

**구분** — 기본

**Ncode 정보**(`/info`)의 **[OID 관리대장] 탭**이다 — 별도 메뉴로 두지 않는다 `PC-034`. 맨 위 안내에 OID 개념이 고정으로 붙는다 — **index 만 갖는 코드**, 펜으로 찍으면 **코드 1개만**, 총량 **약 6만 개**, 분량이 적으면 **book 미분할** `PC-033`.

왼쪽은 **업체(관리 단위)**, 오른쪽은 그 업체의 **index + 교재** 표다. 기존 SOBP 좌표는 **📝 메모**로만 표시한다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| 업체 카드 | 클릭 | 오른쪽 표 갱신 | **업체 + index** 가 관리 단위 |
| index 칸 | 표시 | — | book 번호가 곧 **OID index** (예: 431~464) |
| 📝 좌표 | 표시 | — | 이 업체 OID 이력의 좌표(S/O·Book) — 좌표 지도는 `SOB-01` 종류 [OID] |
| 용어 | — | 통합 | 옛 **IDS(A코드)** = **OID** 동일 `PC-035` |
| 요약 4칸 | 표시 | — | 관리 업체 · 대장 항목 · 사용 index · OID 총량(약 6만) |
| 펜 배지 | 표시 | — | 원장 출처(소리펜 NSP · 필기펜 NWP) |
| 탭 [발급 구조] | 클릭 | `INF-01` | OID 개념 설명 |
| 사이드바 [SOBP 맵] | 클릭 | `SOB-01` | PDS2·PDS3·PDS4 좌표 지도 |

### OID-01: S03 필터 · 검색

*화면 정의서 상태 `S3`*

**구분** — 분기

**index 관리(book)** / **미분할(업체 단위)** 로 업체를 좁히고, 검색은 **업체 · 교재 · index** 를 함께 본다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| index 관리(book) | 클릭 | 해당 업체만 | 웅진 · Common 처럼 book 으로 나눈 업체 |
| 미분할(업체 단위) | 클릭 | 해당 업체만 | 한솔 · 잉글리시에그 등 |
| 검색 | 입력 | 업체·항목 동시 필터 | 업체 목록과 오른쪽 표에 함께 적용 |
| 사용 고객사 | 표시 | — | 공유(커먼) 코드에서 실제 사용 고객사(예: LG U+) |
| 탭 [발급 구조] | 클릭 | `INF-01` | OID 개념 설명 |
| 사이드바 [SOBP 맵] | 클릭 | `SOB-01` | PDS2·PDS3·PDS4 좌표 지도 |
