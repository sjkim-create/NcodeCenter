## 2. 화면 구성

### 개요

**Section → Owner → Book → Page** 드릴다운 코드 지도. 조회 전용이며 저장 동작이 없다. 상태는 **실제 화면에서 갈라지는 것**만 담았다.

**[＋ 직접 코드 할당]** 은 이 화면 위에 모달로 열리지만 화면코드가 달라 `SOB-02` 로 분리했다.

### 기능 개요

**Section → Owner → Book → Page** 를 단계별로 좁혀 들어가며 **어떤 코드가 누구에게 발급되어 있고, 어디가 비어 있는지**를 확인하는 코드 지도다. 신규 발급 대상 좌표를 여기서 고른 뒤 `SOB-02`로 할당한다. 코드 발급 업무의 출발점 화면이다.

| 항목 | 내용 |
|---|---|
| 권한 | STAFF / ADMIN |
| 진입 | 좌측 메뉴 [SOBP 맵] |
| 성격 | **조회 전용**. 이 화면 자체에는 저장 동작이 없다 |
| 발급 | **[＋ 직접 코드 할당]** 을 누르면 `SOB-02` 가 **이 화면 위에 창으로** 열린다 |

### 화면 흐름 (Flow)

```
좌측 메뉴 [SOBP 맵]
   └─▶ SOB-01
         ① 코드 필터 (전체 / PDS2 / PDS3 / PDS4(S-code) / OID)
         ② 상태 필터 · 고객사 검색으로 범위 좁히기
         ③ SECTION ─▶ OWNER ─▶ BOOK ─▶ PAGE 드릴다운
         └─ [＋ 직접 코드 할당] ─▶ SOB-02 (현재 선택한 Section·Owner가 발급 대상)
                                    └─ 할당 완료 ─▶ SOB-01 (지도 갱신 · 선택 Book 초기화)
```

고객사명을 검색창에 정확히 입력하거나 목록에서 고르면 **그 고객사가 보유한 첫 S/O/B 위치로 지도가 자동 이동**한다.

### 정책

| 정책 | 이 화면에서의 적용 |
|---|---|
| `P-05` 무겹침 | 이미 발급된 좌표는 상태·고객사명으로 드러나며, 그 위에 겹쳐 발급할 수 없다(`SOB-02`에서 차단) |
| `P-07` SO 공유 불가 | Section·Owner는 고객사 식별 축. 다른 고객사가 쓰는 S/O에는 발급할 수 없고, **공유(커먼) 코드로 지정된 Owner만 예외** |
| `P-01` 좌표 = SOBP | **좌표가 먼저**다. Section→Owner→Book→Page 로 짚고, 좌표가 유일하므로 중복은 성립하지 않는다 `PC-032` |
| `P-02` 코드 종류 = 좌표 속성 | **PDS3 · PDS2 · PDS4(S-code = Section 44) · OID** 중 무엇인지만 가린다. 종류 칩으로 전환한다. 옛 **IDS(A코드) = OID 동일 용어** `PC-035` |
| `P-02-1` S/O 내 종류 단일 | 지도에서는 **차단하지 않고 종류 배지(용도)** 로 보여준다 `PC-039`. **신규 발급은 한 S/O 에 한 종류만**이며 그 검사는 `SOB-02` 할당 시점에 한다 `PC-041`. **과거 혼용 이력**(S3/O42 · S3/O44 · S3/O1020)은 배지 두 개로 그대로 보인다 |
| 코드 종류 미정 | **원장 보강 프로젝트**(할당 원장에만 있는 S/O)는 종류가 없어 **배지를 표시하지 않는다** `PC-041` |
| `P-02-2` OID | **index 전용 코드**(외부 코드 판독용)도 이 지도에서 **종류 [OID]** 로 필터해 본다 `PC-035`. 같은 S/O 를 다른 종류와 함께 쓸 수 있어 **OID로 잡은 Book 만** 발급으로 표시된다. 업체별 index 목록은 `INF-04`(코드 관리 정보 탭) |
| `P-03` 펜 구분 | **소리펜(NSP)·필기펜(NWP)** 은 좌표 속성으로 **배지로만 표시**한다. 지도에 **펜 필터는 두지 않는다** `PC-037` |
| `P-04` 코드 상태 | 상태는 **코드 발급 / 코드 미발급** 기준. 발급된 코드 안에서 **편집 / 공유 / 사용가능**을 세분해 보여준다 |
| `P-12` 공통(커먼) 코드 | 공유 Owner는 발급 여부와 무관하게 항상 **공유**로 표기하고, 사용 고객사를 함께 보여준다 |
| 테스트/개발 섹션 | **PDS2 S0·S14** 는 상용 미출시 → **추천제외** 배지. 직접 선택은 가능. **PDS3에는 추천제외 Section이 없다** |

### 사용법

#### 4.2 발급 대상 선택 (S1)

도구 아래에 **[＋ 직접 코드 할당]** 버튼과 **발급 대상(현재 선택한 S/O)** 이 함께 표시된다 — *위에서 고른 Section·Owner에 코드를 발급합니다.*

#### 4.3 드릴다운 4단

|---|---|---|---|

#### 4.4 PAGE — 용량 맵

선택한 Book의 페이지를 **얼마나 쓰고 있는지** 보여주는 조회 전용 영역이다.

요약 4종

| 항목 | 의미 |
|---|---|
| 전체 | 이 Section이 Book 하나에 줄 수 있는 최대 페이지 |
| 권장 | 운영 권장 사용량 **1,000p** (전체 용량이 더 작으면 전체가 상한) |
| 실 사용 | 실제 편집·발급에 쓰인 페이지 |
| 잔여 (발급 가능) | 전체 − 실 사용 |

막대 3종

- **전체** — 100% 기준
- **권장** — 전체 대비 권장 비율
- **실 사용** — **두 줄**로 나눠 표시한다(권장 기준 / 실제 사용). 실제 사용이 권장을 넘으면 **넘은 구간이 빗금**으로 그려지고 범례에 **⚠ 초과 +{n}p** 가 붙는다

각 막대에 마우스를 올리면 수치 안내가 뜬다 (S17).

| 상황 | 화면 | 화면 번호 |
|---|---|---|
| 사용 중 | 고객사 · 프로젝트 · 교재 · **사용 구간** 을 함께 표시 | S1 |
| 사용 중 아님 | **미사용 (발급 가능) — 이 S/O/B에는 사용 중인 프로젝트가 없습니다.** · 실 사용 0p · 사용 구간 줄 없음 | S14 |
| 공유 코드 | 라벨이 **고객사 → 공유 고객사** 로 바뀐다. 실사용 고객사가 없으면 **사용 고객사 없음** | S15 |
| 편집 중인 코드 | **편집** 배지 + **[✏️ 편집으로 이동 →]** (`PRJ-02`) | S15 |

## 3. 상태별 변화

### SOB-01: S01 기본 — 코드 전체 · 상태 전체

*화면 정의서 상태 `S1`*

**구분** — 기본

**좌표(SOBP)가 먼저**다 `PC-032`. Section·Owner·Book·Page 로 코드를 짚고, 그 좌표가 **PDS3 · PDS2 · PDS4(S-code, Section 44) · OID** 중 무엇인지를 **종류 칩**으로 가른다. 좌표는 유일하므로 중복은 성립하지 않는다. **옛 IDS(A코드) 표기는 OID 와 같은 것**으로 함께 본다 `PC-035`.

상단은 **「코드」 필터(전체 · PDS2 · PDS3 · PDS4 · OID)** 와 **「상태」 필터** 두 묶음이고, 오른쪽에 고객사 검색이 붙는다 `PC-039`. 처음 연 상태 = 코드 **전체** · 상태 **전체** · 고객사 비움이며, 전체 보기의 Section 정원은 그 섹션을 쓰는 **종류들의 최대치**다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |

### SOB-01: S19 OID 좌표 보기

*화면 정의서 상태 `S19`*

**구분** — 분기

`PC-035` — **OID** 는 index 만 갖는 코드(외부 코드를 우리 펜으로 판독)이고 **옛 IDS(A코드) 표기와 같은 것**이다. 종류 칩 **OID** 로 좌표를 걸러 본다. Section 은 데이터가 있는 **3 · 4** 만 나오고, OID 는 같은 S/O 를 다른 종류와 함께 쓸 수 있어(index 부여) **OID 로 잡은 Book 만** 발급으로 표시된다. 업체별 index 목록은 `INF-04` 관리대장(코드 관리 정보 탭)에서 본다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
