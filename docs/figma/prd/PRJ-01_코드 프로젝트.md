## 2. 화면 구성

### 개요

**고객사별로 어떤 코드(SOBP)를 얼마나 발급받았는지**를 조회·검색하는 화면. 코드 발급 자체는 `SOB-02`에서 이뤄지므로 **이 화면에는 프로젝트 등록 기능이 없다**(조회·검색 전용 / 수정·삭제만 가능). 실제 구현은 **고객사 선택 → 프로젝트 → 발급 구성** 3단이며, 좌측에 **코드 종류(PDS2/PDS3) · 유형(편집/코드발급) · 사용 서비스** 3중 필터가 있다. 기준: `web/components/ProjectsView.tsx` (2026-08-27 확인).

### 상태 구성

이 화면은 **8개 상태**로 나뉜다. 구분: 기본 · 필터 · 분기 · 모달 · 확인창 · 빈 상태

| 상태 | Figma 프레임 | 제목 | 구분 |
|---|---|---|---|
| `S1` | `PRJ-01:S01` | 기본 · 고객사 선택 (프로젝트 미선택) | 기본 |
| `S2` | `PRJ-01:S02` | 프로젝트 선택 · 발급 구성 | 기본 |
| `S3` | `PRJ-01:S03` | 필터 적용 · PDS3 + 편집 | 필터 |
| `S4` | `PRJ-01:S04` | 공유 코드 · 사용 고객사(하위) | 분기 |
| `S5` | `PRJ-01:S05` | 프로젝트 수정 (모달) | 모달 |
| `S6` | `PRJ-01:S06` | 프로젝트 삭제 확인 | 확인창 |

## 3. 상태별 변화

### PRJ-01: S01 기본 · 고객사 선택 (프로젝트 미선택)

*화면 정의서 상태 `S1`*

**구분** — 기본

좌측 메뉴 [코드 ▸ 코드 프로젝트]로 진입. 실제 구현은 **3단 구성**이다 — ① **고객사 선택**(280px) ② **프로젝트**(250px) ③ **발급 구성**(나머지). 상단은 KPI 카드가 아니라 **요약 한 줄**이며 우측에 [초기화]가 있다. ⚠ PRD §1은 "좌: 고객사 목록 · 우: 선택 프로젝트 상세" **2단**으로 적혀 있어 구현과 다르다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| 코드 종류 칩 | 클릭 | 목록·집계 필터 | **전체 / PDS3 / PDS2 / PDS4(S-code) / OID** — 좌표 속성 기준 `PC-032` · 옛 IDS = OID 동일 `PC-035` · 선택 시 프로젝트 선택 해제 |
| 유형 칩 | 클릭 | 목록·집계 필터 | **전체 / 편집 / 코드발급** — 편집 = casterN이거나 심볼 보유 |
| 사용 서비스 | 드롭다운 선택 | 목록·집계 필터 | **사용 서비스 · 전체** 기본값 · casterN / 폼솔루션 / 서비스 없음 |
| 고객사 검색 | 입력 | 즉시 필터링 | 값이 있으면 **×**로 해제 |
| 고객사 항목 | 클릭 | ② 프로젝트 목록 갱신 | 부제 = **{사용서비스} · 코드 {n}** + 코드종류 배지 N/G |
| 프로젝트 카드 | 클릭 | S2 발급 구성 | — |
| [초기화] | 클릭 | 확인창 | **테스트 데이터를 초기화할까요? (엑셀 시드로 복원)** |
| ③ 안내 | 표시 | — | **{고객사} — 가운데에서 프로젝트를 선택하면 어떤 코드가 어떻게 발급되었는지(SOBP 블록·발급일·코드 수) 확인할 수 있습니다.** |
| [✏️ 편집 →] | 클릭 | `PRJ-02` | 해당 owner의 편집 프로젝트로 이동 |
| 코드 신규 발급 | 이동 | `SOB-01` → `SOB-02` | **이 화면에서는 발급하지 않는다** `PC-011` |
| 고객사 정보·단가 확인 | 이동 | `MEM-01` → `MEM-02` | — |
| 티켓 발급 | 이동 | `TKT-01` / `TKT-03` | 발급된 코드로 사용 허가 생성 |

### PRJ-01: S02 프로젝트 선택 · 발급 구성

*화면 정의서 상태 `S2`*

**구분** — 기본

프로젝트를 고르면 ③에 **발급 요약 4종 + 발급 SOBP 내역**이 표시된다. 발급 내역은 **조회 전용** — 발급/수정은 `SOB-02`(Ncode 예약·할당)에서 한다 `PC-011`.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| 발급 요약 4종 | 조회 | — | 발급 코드(B×P) · 실등록 페이지 · 편집 심볼 · 코드 종류 |
| 발급 SOBP 내역 | 조회 | — | 블록마다 **N(PDS3) S O B P** 칩 + 발급일 + **{권}권 × {p}p = {코드}** + 실등록 |
| [수정] | 클릭 | S5 프로젝트 수정 모달 | — |
| [삭제] | 클릭 | S6 삭제 확인 | 발급 코드가 **reset(회수)** |
| 미발급 프로젝트 | 표시 | — | **발급 내역이 없습니다. (미발급)** |
| [✏️ 편집 →] | 클릭 | `PRJ-02` | 해당 owner의 편집 프로젝트로 이동 |
| 코드 신규 발급 | 이동 | `SOB-01` → `SOB-02` | **이 화면에서는 발급하지 않는다** `PC-011` |

| 티켓 발급 | 이동 | `TKT-01` / `TKT-03` | 발급된 코드로 사용 허가 생성 |

### PRJ-01: S03 필터 적용 · PDS3 + 편집

*화면 정의서 상태 `S3`*

**구분** — 필터

필터는 **프로젝트 단위**로 적용되어 좌측 고객사 목록과 상단 집계가 함께 줄어든다. 필터가 걸리면 요약 꼬리말이 **· 필터 적용 (전체 {n}곳 / {n}건)**으로 바뀐다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| PDS3(Ncode) | 클릭 | PDS3 보유 고객사만 | 프로젝트 선택 해제 |
| [편집] | 클릭 | 편집 프로젝트만 | casterN 서비스이거나 심볼 보유 |
| 사용 서비스 | 선택 | 해당 서비스만 | — |
| 상단 요약 | 자동 | 재계산 | **· 필터 적용 (전체 {n}곳 / {n}건)** |
| [전체] | 클릭 | S1 복귀 | — |
