## 2. 화면 구성

### 개요

**OID 관리대장** — OID 는 **index 만 갖는 코드**로, 외부 코드를 **우리 펜으로 읽으려고** 만든 방식이다. 펜으로 찍으면 코드 값이 **1개만** 나오고, 총량이 **약 6만 개**뿐이라 분량이 적으면 **book 으로 나누지 않는다**.

대장은 업체 구분에 S/O 를 써 왔고 분량이 늘어난 업체만 book 번호로 나눴는데, 그 **book 번호가 곧 OID index** 로 보인다. 그래서 이 화면은 **업체 + index** 로 모아 본다. 좌표 기준 조회는 `SOB-01` 의 종류 **[OID]** 필터로 한다 `PC-035`. (옛 **IDS**(A코드) 표기 = OID 동일)

### 기능 개요

**OID = index 만 갖는 코드**다. **외부 코드를 우리 펜으로 읽을 목적**으로 만든 방식이라, OID 책을 우리 펜으로 찍으면 **코드 값이 1개만** 나온다.

| 특성 | 내용 |
|---|---|
| 총량 | **약 60,000개** — SOBP 코드에 비해 매우 적다 |
| 용어 | 옛 **IDS(A코드)** 표기는 **OID 와 같은 것**이다. 화면·필터에서 구분하지 않는다 `PC-035` |
| 분할 | 책의 양이 많지 않으면 **book 으로 코드를 나누지 않는다** |
| 업체 구분 | 대장에서는 **S/O 로 업체를 구분**해 왔다 (관리 편의를 위한 구분이며 좌표 발급이 아니다) |
| index | 분량이 늘어난 업체만 **book 번호로 나누며, 그 번호가 곧 OID index** 로 보인다 |
| 관리 축 | **업체 + index**. 좌표(S/O·Book)는 함께 표시한다. 좌표 기준 조회는 **SOBP 맵의 종류 [OID] 필터** `PC-035` |

| 항목 | 내용 |
|---|---|
| 권한 | STAFF / ADMIN |
| 진입 | 좌측 메뉴 **[정보] ▸ [코드 관리 정보]** (`/info`) 의 **[OID 관리대장] 탭** — 별도 메뉴로 두지 않는다 `PC-034` |
| 데이터 | NSP/NWP 원장의 **코드 구분 = OID** 행 → `oid-data.json` (SOBP 데이터에서 분리) |
| 관련 화면 | `SOB-01` SOBP 맵(좌표 지도 — OID 제외) · `INF-01` 코드 관리 정보(개념 설명) |

> **왜 따로 보나** — OID는 좌표를 점유하는 코드가 아니라 **index 를 부여해 외부 코드를 읽게 하는 수단**이라, 업체별로 몇 번까지 index 를 썼는지가 관리 기준이다. **book 을 나누지 않은 업체**(한솔·잉글리시에그 등)는 SOBP 맵에서 **OWNER 까지만** 보이고(Book 없음) `PC-036`, 항목 목록은 이 대장에서 본다.

### 화면 흐름 (Flow)

```
좌측 메뉴 [정보] ▸ [코드 관리 정보] ▸ [OID 관리대장] 탭
   └─▶ INF-04
         ├─ 개념 안내(고정) — index 전용 · 코드 1개 노출 · 약 6만 개 · book 미분할 조건
         ├─ 요약 4칸 (관리 업체 · 대장 항목 · 사용 index · OID 총량)
         ├─ 필터 [전체 / index 관리(book) / 미분할(업체 단위)] + 검색
         └─ 업체 목록(좌) ─선택─▶ 항목 표(우) : index · 교재 · 페이지 · 발급일 · 사용 고객사
                                     └─ 📝 기존 좌표 메모 (관리 기준 아님)
```

### 정책

| 정책 | 이 화면에서의 적용 |
|---|---|
| `PC-033` OID 개념 | OID는 **index 만 갖는 코드**다. 업체 + index 로 이 대장에서 모아 보고, 좌표는 함께 표시한다 |
| `PC-035` 용어·필터 | **IDS = OID 동일 용어**. 좌표 조회는 **SOBP 맵 종류 [OID]** 필터로 한다 |
| `P-01` 코드 좌표 = SOBP | 이 화면은 **업체·index 목록**이다. 좌표 지도는 `SOB-01`(종류 [OID] 필터) |
| `P-02` 코드 종류 | 코드 종류 4종(**PDS3 · PDS2 · PDS4 · OID**) 중 하나다. 다만 좌표 발급이 아니라 **index 부여**라 같은 S/O 를 다른 종류와 함께 쓸 수 있다 |
| `P-03` 펜 구분 | 대장 항목에 원장 출처(**소리펜 NSP / 필기펜 NWP**)를 배지로 표시한다 |

### 사용법

#### 4.1 개념 안내 (S1 · 고정)

`INF-01` 의 4번째 탭으로 열린다(탭 순서: Code Info · 확장 언어 슬롯 · 발급 구조 · **OID 관리대장** · 알아야 할 사항).

화면 맨 위에 OID 개념이 항상 표시된다 — **index 만 갖는 코드 · 펜으로 찍으면 코드 1개 · 총량 약 6만 개 · 분량이 적으면 book 미분할 · 업체+index 관리(좌표는 메모)**.

#### 4.2 요약 (S1)

| 칸 | 내용 |
|---|---|
| 관리 업체 | 대장에 있는 업체 수 |
| 대장 항목 | 전체 항목(교재·프로젝트) 수 |
| 사용 index | book 으로 나눈 업체는 index 개수, 미분할 업체는 1(업체 단위)로 계산 |
| OID 총량(약) | **60,000** — 전체 대비 사용량 감을 잡기 위한 참고값 |

#### 4.3 필터 · 검색 (S3 · S4)

| 항목 | 규칙 |
|---|---|
| index 관리(book) | book 번호로 index 를 나눈 업체만 (예: 웅진씽크빅-17 · Common-21) |
| 미분할(업체 단위) | book 을 나누지 않은 업체만 (예: 한솔교육-25 · 잉글리시에그-18) |
| 검색 | **업체 · 교재 · index** 를 함께 본다. 업체 목록과 오른쪽 항목 표에 동시에 적용된다 |

#### 4.4 업체 목록 (관리 단위, S1 · S2)

| 표시 | 내용 |
|---|---|
| 업체명 | 대장의 관리 단위 (`{업체}-{owner}`) |
| 펜 배지 | 원장 출처 — 소리펜(NSP) / 필기펜(NWP) |
| index 배지 | **index 관리**(book으로 나눔) / **미분할**(업체 단위) |
| 건수 · index | `{n}건 · index {범위}` 또는 `미분할 (업체 단위)` |
| 📝 기존 좌표 메모 | `S{n}/O{n} · B{시작}~{끝}` 또는 `S{n}/O{n} · book 미분할` — **관리 기준이 아니라 히스토리** |

#### 4.5 항목 표 (S1 · S2)

| 열 | 내용 |
|---|---|
| index | book 번호 = OID index. 미분할 업체는 **—** |
| 교재 · 프로젝트 | 대장에 적힌 교재/프로젝트명 |
| 페이지 | 있으면 표시 |
| 발급일 | 있으면 표시 |
| 사용 고객사 | 공유(커먼) 코드에서 실제 사용 고객사 (예: LG U+) |

미분할 업체는 표 아래에 안내가 붙는다 — **분량이 적어 book 으로 나누지 않고 업체 단위(S/O)로만 관리해 왔습니다.**

*화면 정의서 상태 `S1`*
