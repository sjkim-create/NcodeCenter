## 2. 화면 구성

### 개요

코드를 발급받는 **업체(고객사) 마스터**. 사업자·계좌·서류·편집 단가·업무 이력을 관리한다. **모든 코드 발급과 티켓 발급의 선행 조건**이며, 여기에 등록되지 않은 업체에는 코드를 할당할 수 없다. 계층은 `P-11`에 따라 **상위 / 하위 / 단독** 3분류이고 구분 필터로 거른다. **행을 클릭하면 `MEM-02` 수정 화면**으로 이동한다.

### 기능 개요

코드를 발급받는 **업체(고객사) 마스터**. 사업자·계좌·서류·편집 단가·업무 이력을 한곳에서 관리한다. **모든 코드 발급과 티켓 발급의 선행 조건**이 되는 화면으로, 여기에 등록되지 않은 업체에는 코드를 할당할 수 없다.

| 항목 | 내용 |
|---|---|
| 권한 | STAFF / ADMIN (ADMIN 권장 — §7 협의) |
| 진입 | 좌측 메뉴 [고객사 관리] |
| 성격 | 목록 · 검색 · 등록/수정/삭제 |
| 등록·수정 화면 | `MEM-02` |

### 화면 흐름 (Flow)

```
좌측 메뉴 [고객사 관리]
   └─▶ MEM-01
         ├─ 구분 필터(전체/상위/하위/단독) · 검색
         ├─ [＋ 고객사 등록] ─▶ MEM-02 (등록 모드)
         ├─ 행 클릭 ──────────▶ MEM-02 상세·수정 (업무요청 메모 포함)
         ├─ 행 [삭제] ─ 이름 입력 확인 ─▶ 프로젝트·코드 reset 후 목록 갱신
         └─ [초기화] ─ 확인 ─▶ 엑셀 시드로 복원
```

No · 업체명 · 담당자 / 연락처 · 사업자번호 · 은행 / 계좌 · 커먼 코드 · 편집 단가 · 주소 · 서류 · 업무 · 작업

#### 4.3 구분 (계층)

| 구분 | 뜻 |
|---|---|
| **상위 고객사** | 공통(커먼)코드를 **보유**한 대표 고객사 — 하위 고객사가 이 코드를 함께 쓴다 |
| **하위 고객사** | 공통(커먼)코드를 **사용**하는 고객사. 귀속 대표사가 툴팁에 표시된다 |
| **단독** | 자체 코드만 쓰는 고객사(상위·하위 관계 없음) |

#### 4.4 프로젝트 종료 업체 (S4)

`MEM-02` 에서 **사업 종료**로 바꾼 고객사는 목록에서 **흐리게** 표시되고 이름 옆에 **종료** 배지가 붙는다(툴팁 = 종료 사유·이관 메모). **코드 발급 이력은 그대로 남는다.**

> **종료 ≠ 삭제** — 종료는 이력을 보존하고, 삭제는 코드를 회수(reset)한다.

#### 4.5 삭제 (S5 · S6 · S7)

행의 **[삭제]** → 경고 모달 **⚠ 고객사 삭제 — 신중히 확인하세요**.

모달의 경고 3줄

- 삭제 업체는 **3~4년 뒤 재연락되는 경우가 많습니다.** 정말 삭제가 필요한지 재확인하세요.
- 이 고객사의 **프로젝트 {n}건 / 발급 코드 {n}건이 reset**됩니다(회수).
- 서류·업무 원장 기록도 함께 삭제되며, **되돌릴 수 없습니다.**

확인을 위해 **업체명을 정확히 입력**해야 하며, 일치하기 전에는 **[삭제 확정 (코드 reset)]** 이 눌리지 않는다.

### MEM-01: S04 프로젝트 종료 업체

*화면 정의서 상태 `S4`*

**구분** — 변형

PRD §5 — 사업이 끝난 고객사는 **행 전체가 흐리게**(배경 #fafafa · 불투명도 0.6) 표시되고 **종료** 배지가 붙는다. 툴팁은 종료 사유(`closedNote`)를 보여준다. 코드 발급 이력은 보존된다.
