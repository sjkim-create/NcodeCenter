## 2. 화면 구성

### 개요

**NcodeCenter에서 코드의 주인이 정해지는 유일한 지점**이며, 이 코드를 어떤 서비스가 쓸지(**사용 서비스**)도 여기서만 지정한다 `PC-011`. 할당 단위는 **S/O** — Owner 전체를 그 고객사가 점유한다.

`SOB-01` 의 **[＋ 직접 코드 할당]** 으로만 열리며, **자동 추천은 사용하지 않는다**(모드 토글 없음).

### 기능 개요

고객사에 **SOBP 코드를 할당(발급)** 하는 창. NcodeCenter에서 **코드의 주인이 정해지는 유일한 지점**이며, 이 코드를 어떤 서비스가 쓸지(**사용 서비스**)도 여기서만 지정한다.

`SOB-01` 에서 이미 고른 **Section·Owner에 그대로 발급**한다. **모드 선택이 없다** — 자동 추천은 사용하지 않는다(`PC-028`).

| 항목 | 내용 |
|---|---|
| 권한 | STAFF / ADMIN |
| 진입 | `SOB-01`의 **[＋ 직접 코드 할당]** — 지도 위에 창으로 열린다 |
| 할당 단위 | **S/O 단위** — Owner 전체를 그 고객사가 점유한다 |
| 선행 조건 | 대상 고객사가 **`MEM-01`에 등록**되어 있어야 한다 (이 화면에서 신규 고객사를 만들지 않는다) |

### 화면 흐름 (Flow)

```
SOB-01 ─ [＋ 직접 코드 할당] ─▶ SOB-02 (창)
   │
   ├─ 고객사 선택 ─▶ 그 고객사의 기존 보유 코드 표시
   │                    └─ 보유 코드 클릭 ─▶ 그 S/O로 이동해 이어서 추가 발급
   ├─ 사용 서비스 선택
   │
   ├─ [취소] ─────────────▶ SOB-01 (변경 없음)
   └─ [할당] ─ 검증 통과 ─▶ SOB-01 (지도 갱신 · 선택 Book 초기화)
                              ├─▶ PRJ-01 에 코드발급 프로젝트 생성
                              └─▶ LOG-01 활동 로그 기록(코드 할당(등록))

미등록 고객사인 경우 ─▶ MEM-02 고객사 등록 후 재시도
```

### 정책

| 정책 | 이 화면에서의 적용 |
|---|---|
| `P-05` 무겹침(최우선) | 이미 다른 고객사에 할당된 S/O에는 발급할 수 없다. 발급 입력이 **잠금(🔒 전용 · 할당 불가)** 상태가 된다 |
| `P-07` SO 공유 불가 | Section·Owner는 고객사 식별 축. 예외는 **미리 공유 OWNER로 지정된 경우**뿐이며, 그때는 Book 번호만 겹치지 않으면 된다 |
| `P-12` 공유 코드 사용 고객사 | 공유(커먼) 코드는 **[고객사 관리]에서 그 코드의 사용 고객사(하위 등록)로 체크한 고객사에만** 발급한다 `PC-045`. 체크되지 않은 고객사를 고르면 🚫 안내와 함께 **[할당]이 잠긴다**. 코드를 보유한 대표 고객사는 예외이며, 레지스트리에 없는 임의 공유 OWNER 는 검사 대상이 아니다 |
| `P-02` 코드 종류 = 좌표 속성 | 좌표(SOBP)를 먼저 잡고 그 좌표가 **PDS3 · PDS2 · PDS4(S-code)** 중 무엇인지를 갖는다 `PC-032`. 이 화면에서 **코드 종류를 직접 고른다(단일 선택)** — OID 는 index 부여라 할당 대상이 아니다 `PC-035` |
| `P-02-1` S/O 내 종류 단일 | **신규 발급은 한 S/O 에 한 종류만** `PC-041`. 그 S/O 가 이미 다른 종류로 쓰이면 안내와 함께 **[할당]이 잠긴다**(OID 제외). 지도의 🚫 영역 할당 차단은 폐지된 상태 `PC-039` — **과거 혼용 이력**(S3/O42 · S3/O44 · S3/O1020)은 그대로 표시한다 |
| `P-13` 사용 서비스 지정 위치 | **사용 서비스는 이 화면에서만 지정한다**(`PC-011`). 코드 프로젝트에서는 지정하지 않는다 |
| `P-14` 편집 = casterN | 사용 서비스를 **casterN**으로 지정하면 그 코드는 편집 프로젝트(`PRJ-02`) 관리 대상이 된다 |
| `PC-026` 사용 서비스 3종 | 지정 가능한 서비스는 **casterN · 폼솔루션 · 서비스 없음** 뿐이다. 그 외 용도(Ncode 프린터 등)의 코드는 **서비스 없음(코드만 발급)** 으로 할당한다 |
| `PC-028` 자동 추천 폐기 | 조건(판형·페이지·권수)으로 SOBP를 추천하는 기능은 **사용하지 않는다**. 발급 대상은 `SOB-01`에서 사람이 고른다 |

### 사용법

#### 4.0 화면 구성 — 세 묶음 `PC-046`

| 묶음 | 내용 | 조작 |
|---|---|---|
| **① 발급 대상** | `S{n}` `O{n}` · 코드 종류 배지 · **상태 배지**(🔒 전용 / 공유 OWNER / 사용 중 / 미발급) | **보여 주기만** 한다. 좌표는 `SOB-01` 지도에서 고른다 |
| **② 발급 정보** | 고객사 * · 사용 서비스 · **코드 종류** | **한 행에 3열**로 둔다 `PC-047`. 코드 종류는 **PDS2 · PDS3** 순 칩 |
| **②′ 이미 발급된 좌표** | 고객사(보유 업체) · 사용 서비스 · 코드 종류 | 고객사·코드 종류는 **상태 표시**, 바꿀 수 있는 것은 **사용 서비스** 하나 `PC-048` |
| **③ 보유 코드** | 선택 고객사가 이미 가진 좌표 | 고객사를 골라야 나온다. 클릭하면 그 좌표로 이동 |

- 창 제목은 **「코드 할당」** 만 쓴다 — S/O 는 바로 아래 **[발급 대상]** 에 있으므로 겹쳐 적지 않는다 `PC-047`.
- **코드 종류를 바꿔도 S/O 는 그대로다** `PC-046`. 종류는 모달 안에서만 쓰는 값이라 지도 선택을 건드리지 않는다.
- 그 S/O 를 **이미 쓰는 종류가 있으면 그 종류로 고정**되고 문구로만 보여 준다 (한 S/O = 한 종류 `PC-041`).
- **Section · Owner 셀렉트는 없다.** 전용 코드처럼 **추가 발급 대상이 아닌 좌표**도 잠금 문구가 아니라 **상태 배지 한 줄**로 표시한다.
- 차단 사유는 **한 줄**만 보여 준다 — 전용 좌표는 **“{업체명}” 전용으로 추가 발급이 불가** `PC-048`.
- **이미 발급된 좌표**에서는 고객사가 입력 칸이 아니라 **보유 업체 상태**로 나오고, 코드 종류도 **배지만** 보여 준다(설명 문구 없음). 버튼은 **[사용 서비스 저장]** 으로 바뀌어 **사용 서비스만** 고칠 수 있다 `PC-048`.


#### 4.1 고객사와 사용 서비스 (S1)

창 제목에 **발급 대상 코드 종류 · S · O** 가 들어간다.

| 항목 | 필수 | 규칙 |
|---|---|---|
| 고객사 | ✔ | 목록에서 선택하거나 직접 입력(검색). **`MEM-01`에 등록된 고객사만** 발급 가능 |
| 사용 서비스 | — | `casterN (편집툴)` / `폼솔루션` / `서비스 없음 (코드만 발급)` **3종**. 기본값 = 서비스 없음 |

사용 서비스별 안내

| 선택 | 안내 | 화면 |
|---|---|---|
| 서비스 없음 | 코드만 발급 — 자체 서비스 미사용(사용량 모니터링 불가). | S1 |
| casterN | casterN 편집툴 — [편집 프로젝트]에서 관리·모니터링. | S4 |
| 폼솔루션 | 자체 서비스 — 코드 사용량이 모니터링됩니다. | S5 |

> 고객사를 고르기 전에는 **기존 보유 코드 영역이 나오지 않고**, **[할당]** 도 눌리지 않는다.

#### 4.2 선택 고객사의 기존 보유 코드

| 상황 | 화면 | 화면 번호 |
|---|---|---|
| 보유 코드 없음 | **보유한 코드가 없습니다 — 새 S/O로 발급됩니다.** | S2 |
| 보유 코드 있음 | 코드 종류·S·O·Book(·Page) 을 **2열**로 나열. 지금 보고 있는 좌표와 같은 칸은 **강조**된다 | S3 |

코드를 클릭하면 그 **S/O로 이동해 이어서 추가 발급**할 수 있고, 시작 Book은 **가장 빠른 빈 번호**로 자동 설정된다. 빈 Book이 없으면 **S{n}/O{n} 에 사용 가능한 Book 번호가 없습니다.** 를 알려준다.

Page 범위는 **지정된 코드에만** 붙는다.

#### 4.3 발급 상세

발급 대상이 **코드 종류 · S · O · owner 전체** 로 표시된다.

> 이 **S{n}/O{n}** 전체를 **{고객사}** 에 발급(점유)합니다. owner 아래 **모든 Book이 '사용가능'** 이 되고, 실제 발급 규모(코드 수)는 **편집 시 집계**됩니다.

#### 4.4 저장 (S10)

**[할당]** — 검증을 통과하면 창이 닫히고 지도(`SOB-01`)로 돌아간다. 지도가 갱신되고 **선택 Book이 초기화**되며, 해당 고객사의 **코드발급 프로젝트**가 `PRJ-01`에 생성되고 `LOG-01`에 기록된다.

## 3. 상태별 변화

### SOB-02: S01 진입 직후 — 고객사 미선택

*화면 정의서 상태 `S1`*

**구분** — 기본

`SOB-01` 의 **[＋ 직접 코드 할당]** 으로 열린다. 구성은 세 묶음이다 `PC-046` — ① **발급 대상**(좌표·종류·상태를 **보여 주기만** 한다) ② **발급 정보**(고객사 · 사용 서비스 · 코드 종류) ③ **보유 코드**(고객사를 고르면 나온다). 좌표(Section · Owner)는 **지도에서 고른 값**이라 모달에서 바꾸지 않는다. **[할당]** 은 고객사를 고르기 전에는 눌리지 않고, 사용 서비스 기본값은 **서비스 없음**.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |

| 고객사 * | 목록 선택 또는 직접 입력(검색) | 기존 보유 코드 영역 표시 | `MEM-01` 에 등록된 고객사만 — **여기서 신규 고객사를 만들지 않는다** |

### SOB-02: S03 고객사 선택 · 보유 코드 있음

*화면 정의서 상태 `S3`*

**구분** — 분기

이 고객사가 이미 받은 코드를 **2열** 로 보여준다(많으면 영역 안에서 스크롤). 지금 보고 있는 코드 종류·S·O 와 같은 칸만 **파랑으로 강조**된다. Page 범위는 **지정된 코드에만** 붙는다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
