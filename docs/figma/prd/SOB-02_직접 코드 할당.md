## 2. 화면 구성

### 개요

**NcodeCenter에서 코드의 주인이 정해지는 유일한 지점**이며, 이 코드를 어떤 서비스가 쓸지(**사용 서비스**)도 여기서만 지정한다 `PC-011`. 할당 단위는 **S/O** — Owner 전체를 그 고객사가 점유한다.

`SOB-01` 의 **[＋ 직접 코드 할당]** 으로만 열리며, **자동 추천은 사용하지 않는다**(모드 토글 없음).

## 3. 상태별 변화

### SOB-02: S01 진입 직후 — 고객사 미선택

*화면 정의서 상태 `S1`*

**구분** — 기본

`SOB-01` 의 **[＋ 직접 코드 할당]** 으로 열린다. 제목에 **발급 대상 S·O·코드 종류** 가 들어간다. 발급 대상(코드 종류 · Section · Owner)은 **모달 안에서 다시 고를 수 있다** `PC-035`. 고객사를 고르기 전에는 **기존 보유 코드 영역이 아예 나오지 않고**, **[할당]** 도 눌리지 않는다. 사용 서비스 기본값은 **서비스 없음**.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| 고객사 * | 목록 선택 또는 직접 입력(검색) | 기존 보유 코드 영역 표시 | `MEM-01` 에 등록된 고객사만 — **여기서 신규 고객사를 만들지 않는다** |
| 사용 서비스 | 선택 | 아래 안내문 교체 | casterN / 폼솔루션 / 서비스 없음 **3종** `PC-026` |
| 코드 종류 * | 선택 | Section 목록 재구성 | **PDS3 · PDS2 · PDS4** 중 하나 — **단일 선택**(다중 선택 없음). OID 는 index 부여라 할당 대상이 아니다 `PC-035` |
| Section * · Owner * | 선택·입력 | 발급 대상 변경 | 지도에서 고르고 들어와도 **모달 안에서 다시 고를 수 있다**. 바꾸면 왼쪽 지도 선택도 함께 이동한다 |
| [할당] | — | 비활성 | 고객사 미선택 · 전용 잠금 · 반대 코드 종류 선점 중 하나라도 걸리면 잠긴다 |
| [할당] | 강제 실행 | 확인창 | **고객사를 선택하세요. (신규 고객사는 고객사 관리에서 등록)** |
| [취소] · ✕ | 클릭 | `SOB-01` | 변경 없이 복귀 |

### SOB-02: S06 전용 코드 — 입력 잠금

*화면 정의서 상태 `S6`*

**구분** — 차단

`P-05` 무겹침 — 이 S/O 를 **다른 고객사가 전용으로 쓰고 있는** 경우. 상단 안내가 빨강으로 바뀌고, 발급 대상에 **🔒 전용 · 할당 불가** 가 붙고, **발급 입력 전체가 잠긴다**.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |

| 해제 | 공유 OWNER 지정 | **미구현** | ⚠ 안내 문구는 [공유 OWNER] 체크를 권하지만 **화면에 그 체크박스가 없다** — 현재는 **미리 공유로 지정된 Owner**(S7)만 공유로 동작한다 |

### SOB-02: S07 공유 OWNER

*화면 정의서 상태 `S7`*

**구분** — 분기

`P-07` 의 예외 · `P-12` — 미리 **공유(커먼) 코드로 지정된 Owner**. 여러 고객사가 같은 Owner 를 쓸 수 있고 **Book 번호만 겹치지 않으면 된다**. 전용 잠금이 걸리지 않는다.

| [할당] | 클릭 | 정상 발급 | Book 번호가 겹치지 않으면 발급된다 |
| [취소] · ✕ | 클릭 | `SOB-01` | 변경 없이 복귀 |

### SOB-02: S08 같은 S/O 를 여러 종류가 함께 사용

*화면 정의서 상태 `S8`*

**구분** — 분기

`PC-039` — **좌표(SOBP)가 코드 종류보다 상위**다. 예전의 「같은 S/O 는 한 종류만」 배타와 **🚫 영역 할당됨** 차단은 **폐지**했다. 한 고객사가 같은 **S/O** 안에서 **Book 을 나눠** PDS2·PDS3 를 함께 쓰는 실데이터가 있다(구몬D-37 · 대교-31 · 교원구몬-10 등 7건). 이제 좌표를 할당하고, 그 좌표가 어떤 종류인지는 **용도 표시**로만 남는다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| 종류 배타 | — | 폐지 | **🚫 영역 할당됨** 배지·차단·확인창을 모두 없앴다 |
| 코드 종류 | 선택 | 용도 표시 | 할당한 좌표가 **PDS2 / PDS3 / PDS4** 중 무엇으로 쓰이는지만 기록한다 |
| 전용 잠금 | — | 유지 | **다른 고객사** 전용 코드는 여전히 잠긴다(S6) |
| (S,O,B) 중복 | — | **확인 필요** | ⚠ 실데이터에 Book 까지 겹치는 사례 **1건**(S3/O1017/B1 · J research) — 장부 표기 확인 필요 |
| [취소] · ✕ | 클릭 | `SOB-01` | 변경 없이 복귀 |

### SOB-02: S10 할당 성공

*화면 정의서 상태 `S10`*

**구분** — 완료

**owner 전체를 그 고객사가 점유**한다. Owner 아래 모든 Book 이 **사용가능** 이 되고, 실제 발급 규모(코드 수)는 **0으로 시작해 편집 시 집계**된다. 창이 닫히고 지도로 돌아가며 선택 Book 이 초기화된다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| [할당] | 성공 | `SOB-01` | 지도 갱신 · 선택 Book 초기화 |
| 발급 결과 | 자동 | `PRJ-01` | **{고객사} 코드발급 · S{n}/O{n}** 코드 프로젝트가 생성된다 |
| 발급 결과 | 자동 | `LOG-01` | **코드 할당(등록)** 으로 기록 |
| 할당 취소·회수 | — | **미결** | ⚠ §7 — 되돌리기 기능이 없다. 잘못 할당하면 `PRJ-01` 에서 프로젝트를 지워야 한다 |
