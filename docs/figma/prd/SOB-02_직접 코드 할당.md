## 2. 화면 구성

### 개요

**NcodeCenter에서 코드의 주인이 정해지는 유일한 지점**이며, **사용 서비스와 코드 종류는 여기서 정하지 않는다** — 서비스는 고객사 속성이라 `MEM-02` 에서 정한다 `PC-076` `PC-011`. 할당 단위는 **S/O** — Owner 전체를 그 고객사가 점유한다.

`SOB-01` 의 **[＋ 직접 코드 할당]** 으로만 열리며, **자동 추천은 사용하지 않는다**(모드 토글 없음). 그림의 값은 로컬 앱 시드 데이터 화면에서 옮겼다(2026-11-23).

### 기능 개요

고객사에 **SOBP 코드를 할당(발급)** 하는 창. NcodeCenter에서 **코드의 주인이 정해지는 유일한 지점**이다.
**사용 서비스와 코드 종류는 여기서 정하지 않는다** — 서비스는 **고객사 속성**이라 `MEM-02` 에서 `PC-076`, 종류는 발급 화면에서 정한다 `PC-074`.

`SOB-01` 에서 이미 고른 **Section·Owner에 그대로 발급**한다. **모드 선택이 없다** — 자동 추천은 사용하지 않는다(`PC-028`).

| 항목 | 내용 |
|---|---|
| 권한 | STAFF / ADMIN |
| 진입 | `SOB-01`의 **[＋ 직접 코드 할당]** — 지도 위에 창으로 열린다 |
| 할당 단위 | **S/O 단위** — Owner 전체를 그 고객사가 점유한다 |
| 할당 범위 | **Book · Page 전체** — 그 S/O 를 쓸 수 있는 코드 타입 중 **넓은 쪽** 기준 `PC-279`. 예) S3 · O2000 은 PDS2 만 쓸 수 있어(PDS3 Owner 는 0~1023) PDS2 범위(Book 0~4095 · Page 0~4095), S3 · O5 는 Book 은 PDS3(0~8191) · Page 는 PDS2(0~4095). 코드 타입 태그는 붙지 않는다 |
| 선행 조건 | 대상 고객사가 **`MEM-01`에 등록**되어 있어야 한다 (이 화면에서 신규 고객사를 만들지 않는다) |

### 화면 흐름 (Flow)

```
SOB-01 ─ [＋ 직접 코드 할당] ─▶ SOB-02 (창)
   │
   ├─ 고객사 선택 ─▶ 그 고객사의 기존 보유 코드 표시
   │                    └─ 보유 코드 클릭 ─▶ 그 S/O로 이동해 이어서 추가 발급
   ├─ 사용 서비스 ─ 읽기 표시(고객사 관리에서 정한 값) · [고객사 관리 →] `PC-076`
   │
   ├─ [취소] ─────────────▶ SOB-01 (변경 없음)
   └─ [할당] ─ 검증 통과 ─▶ SOB-01 (지도 갱신 · 선택 Book 초기화)
                              ├─▶ PRJ-01 에 코드발급 프로젝트 생성
                              └─▶ LOG-01 활동 로그 기록(코드 할당(등록))

미등록 고객사인 경우 ─▶ MEM-02 고객사 등록 후 재시도
```

### 정책

| 정책 | 이 화면에서의 적용 |
|---|---|
| `P-05` 무겹침(최우선) | 이미 다른 고객사에 할당된 S/O에는 발급할 수 없다. 발급 입력이 **잠금(🔒 전용 · 할당 불가)** 상태가 된다 |
| `P-07` SO 공유 불가 | Section·Owner는 고객사 식별 축. 예외는 **미리 공유 OWNER로 지정된 경우**뿐이며, 그때는 Book 번호만 겹치지 않으면 된다 |
| `P-12` 공유 코드 사용 고객사 | 공유(커먼) 코드는 **[고객사 관리]에서 그 코드의 사용 고객사(하위 등록)로 체크한 고객사에만** 발급한다 `PC-045`. 체크되지 않은 고객사를 고르면 🚫 안내와 함께 **[할당]이 잠긴다**. 코드를 보유한 대표 고객사는 예외이며, 레지스트리에 없는 임의 공유 OWNER 는 검사 대상이 아니다 |
| `P-02` 코드 종류 = 좌표 속성 | 좌표(SOBP)를 먼저 잡고 그 좌표가 **PDS3 · PDS2 · PDS4(S-code)** 중 무엇인지를 갖는다 `PC-032`. **이 화면에서는 종류를 고르지 않는다** `PC-074` — App Key 발급 · N Key 발급 · 편집 프로젝트에서 정한다 `PC-051` |
| `PC-281` Book 별 코드 타입 | **한 S/O 안에서 Book 마다 다른 코드 타입**을 쓸 수 있다(B1 PDS2 · B2 PDS3). 한 Book 은 한 타입만. 신규 발급의 「S/O 내 종류 단일」(`PC-041`)은 폐기 — 할당이 타입 없이 S/O 를 잡고(`PC-279`), 타입은 편집 · 키 발급에서 Book 단위로 정하기 때문 |
| `P-13` 사용 서비스 지정 위치 | **사용 서비스는 [고객사 관리](`MEM-02`)에서 지정한다** `PC-076`. 이 화면과 코드 프로젝트는 **읽기만** 한다 — 서비스는 좌표가 아니라 **고객사**의 성격이기 때문이다 |
| `P-14` 편집 = casterN | 고객사의 사용 서비스가 **casterN**이면 그 고객사가 편집 프로젝트(`PRJ-02`) 관리 대상이 된다 `PC-076` |
| `PC-076` 사용 서비스 2종 | 고르는 값은 **casterN · 폼솔루션** 둘뿐이고, **아무것도 고르지 않으면 = SDK 연동(코드만 할당)** 이다. 그 외 용도(Ncode 프린터 등)의 코드가 여기 해당한다 |
| `PC-279` 할당 범위 = 넓은 코드 타입 | 할당에는 코드 타입(PDS2 · PDS3) 태그가 붙지 않는다 — 태그는 편집 · 키 발급에서 정한 값이 있을 때 보인다. 그래서 할당 범위는 **그 S/O 를 쓸 수 있는 코드 타입 중 넓은 쪽**(Book · Page 각각)으로 미리 잡고, 실제 발급(편집 · App Key · N Key · 서비스 티켓)에서 정한 타입의 범위를 넘으면 그 화면에서 막는다 |
| `PC-028` 자동 추천 폐기 | 조건(판형·페이지·권수)으로 SOBP를 추천하는 기능은 **사용하지 않는다**. 발급 대상은 `SOB-01`에서 사람이 고른다 |

### 사용법

#### 4.0 화면 구성 — 세 묶음 `PC-046`

| 묶음 | 내용 | 조작 |
|---|---|---|
| **① 발급 대상** | `S{n}` `O{n}` · 이 S/O 를 이미 쓰는 **종류 칩(있을 때만 · 여럿이면 모두)** · **상태 배지**(🔒 전용 · 추가 발급 불가 / 공유 OWNER · Book 만 배타 / 사용 중 · 이어서 발급 / 미발급 · 신규 발급) · 오른쪽 *owner 전체 점유 · 코드 종류는 발급 때 지정* · 막힘이 있으면 상자가 빨강 + 한 줄 | **보여 주기만** 한다. 좌표는 `SOB-01` 지도에서 고른다 |
| **② 발급 정보** | 고객사 * · 사용 서비스(또는 (K) 고객사면 **구분**) | **한 행에 2열**. 사용 서비스는 **읽기 표시** `PC-076`. **코드 종류 칸은 없다** `PC-074` — 종류는 App Key 발급·N Key 발급·편집 프로젝트에서 정한다 `PC-051` |
| **②′ 이미 발급된 좌표** | 고객사(보유 업체 — 여럿이면 *·* 로 이어서 + *보유*) · 사용 서비스 | **조회 전용** — 바꿀 것이 없어 **[취소]** 만(그룹 조건이 맞으면 [그룹에 넣기]) `PC-048` `PC-076` |
| **②″ 확장 언어 그룹** | 그룹 칸 / *🌐 확장 언어 그룹 없음* / 소속 한 줄 | §4.5 · (K) 고객사에는 없다 |
| **③ 보유 코드** | 선택 고객사가 이미 가진 좌표 | 고객사를 골라야 나오고 **0건이면 칸이 없다**. 클릭하면 그 좌표로 이동 |

- 창 제목은 **「코드 할당」** 만 쓴다 — S/O 는 바로 아래 **[발급 대상]** 에 있으므로 겹쳐 적지 않는다 `PC-047`.
- **코드 종류는 이 창에서 다루지 않는다** `PC-074`. 이미 쓰이는 좌표의 종류만 **[발급 대상] 배지**로 보인다.
- **Section · Owner 셀렉트는 없다.** 전용 코드처럼 **추가 발급 대상이 아닌 좌표**도 잠금 문구가 아니라 **상태 배지 한 줄**로 표시한다.
- 차단 사유는 **한 줄**만 보여 준다 — 전용 좌표는 **“{업체명}” 전용으로 추가 발급이 불가** `PC-048`.
- **이미 발급된 좌표**에서는 고객사가 입력 칸이 아니라 **보유 업체 상태**로 나오고(그래서 보유 코드 칸도 없다), 코드 종류도 **배지만** 보여 준다. **조회 전용**이라 [취소] 만 있다 — 옛 [사용 서비스 저장] 은 폐지 `PC-076`.


#### 4.1 고객사와 사용 서비스 (S1)

| 항목 | 필수 | 규칙 |
|---|---|---|
| 고객사 | ✔ | 목록에서 선택하거나 직접 입력(검색). **`MEM-01`에 등록된 고객사만** 발급 가능 · 목록에는 **(K) N Key 고객사**(nkey 대장)도 함께 나온다 — 고르면 「사용 서비스」 칸이 **「구분」** 으로 바뀌어 *(K) 티켓 고객사 · 키 발급 대상 · 고객사 관리와 별개*(대장에 없으면 빨강 *대장에 없는 티켓 고객사*) + **[N Key 관리 →]** `PC-125` `PC-152` (S15) |
| 사용 서비스 | — | **고르는 값이 아니라 읽기 표시** `PC-076`. 고른 고객사의 사용 서비스를 그대로 보여주고, 옆에 **[고객사 관리 →]** 링크를 둔다 |

사용 서비스 표시

| 고객사의 사용 서비스 | 표시 | 화면 |
|---|---|---|
| *(지정 없음)* | **SDK 연동 (코드만 할당)** — 우리 서비스를 거치지 않는 고객사 | S1 |
| casterN | **casterN (편집툴)** 배지 — 이 고객사는 [편집 프로젝트]에서 관리된다 | S4 |
| 폼솔루션 | **폼솔루션** 배지 (서비스 개발 전이라 현재 0곳) | S5 |

> 바꾸려면 **[고객사 관리](`MEM-02` §4.2)** 로 간다. 서비스는 좌표가 아니라 **고객사**의 성격이기 때문이다 `PC-076`.

> 고객사를 고르기 전에는 **기존 보유 코드 영역이 나오지 않고**, **[할당]** 도 눌리지 않는다.

#### 4.2 선택 고객사의 기존 보유 코드

| 상황 | 화면 | 화면 번호 |
|---|---|---|
| 보유 코드 없음 | **칸이 나오지 않는다** | S2 |
| 보유 코드 있음 | 제목 *{고객사} 보유 코드 {n}건 · 클릭하면 이동* 아래 **3열** — 칸마다 **종류 칩(정해진 코드만) · S · O**. 지금 보고 있는 좌표와 같은 칸은 **강조**된다 | S3 |

코드를 클릭하면 지도가 그 좌표로 이동한다(코드 종류 · Section · Owner 가 함께 바뀌고 Book 선택이 풀린다). 할당만 한 좌표는 종류가 없어 칩이 붙지 않는다 `PC-280`.

#### 4.3 발급 상세

발급 대상이 **코드 종류 · S · O · owner 전체** 로 표시된다.

> 이 **S{n}/O{n}** 전체를 **{고객사}** 에 발급(점유)합니다. owner 아래 **모든 Book이 '사용가능'** 이 되고, 실제 발급 규모(코드 수)는 **편집 시 집계**됩니다.

#### 4.4 저장 (S10)

이미 쓰는 좌표(S6 · S8 · S13②)에서는 **조회 전용**이라 [취소] 만 있다 `PC-076` — 옛 **[사용 서비스 저장]** 버튼은 없앴다.

**[할당]** — 검증을 통과하면 창이 닫히고 지도(`SOB-01`)로 돌아간다. 지도가 갱신되고 **선택 Book이 초기화**되며, 해당 고객사의 **코드발급 프로젝트**가 `PRJ-01`에 생성되고 `LOG-01`에 기록된다.

#### 4.5 확장 언어 그룹 `PC-330` (화면 S11~S14)

고른 고객사에 **확장 언어 그룹**(`MEM-02` §4.12)이 있고 같은 Section 이면, 발급 정보 아래에 **🌐 확장 언어 그룹** 칸이 생긴다. (K) 티켓 고객사에는 없다.
이미 쓰는 좌표(조회 전용 — 고객사 입력칸 없음)는 **보유 고객사가 한 곳**이면 그 고객사로 보고 같은 규칙을 쓴다 `PC-332`.

| 경우 | 화면 `PC-332` |
|---|---|
| 이 S/O 가 이미 다른 고객사 그룹의 Owner(기본 · 확장)임(고객사를 아직 안 고름 · 예전 슬롯 고객사 보유 포함) | 한 줄 *🌐 확장 언어 그룹 {그룹} · 기본 O{n} · 기본 Owner / 확장 {k} · {언어 · 언어 …}* (언어가 없으면 *지정된 언어 없음*) — 보기만 |
| 고른 고객사에 이 Section 의 그룹이 없음 | 한 줄 *🌐 확장 언어 그룹 없음* + 링크 *언어 확장이 필요하면 기본 코드를 할당한 뒤 고객사 관리 ▸ 공통코드 · 확장 언어 에서 그룹을 만드세요 →*(그 고객사 상세로 이동) `PC-357` |
| 고른 고객사에 이 Section 의 그룹이 있음 `PC-357` | 칸 머리 **🌐 확장 언어 그룹 [연결할 그룹 ▾]** — *연결 안 함 (전용 코드)* / *기본 S{s}/O{n} 그룹 · 확장 {n}개* … · 기본값 = 이 S/O 가 든 그룹(있으면 셀렉트 잠김), 없으면 **연결 안 함** · 그룹을 고르면 아래 ②가 열린다 · 연결 안 함이면 일반 할당 |
| 이미 쓰는 좌표 · 보유 고객사 한 곳 · 그 고객사에 이 Section 그룹 있음 | 아래 칸을 그대로 보여주고, 그룹을 고르면 아래 버튼은 [할당] 대신 **[그룹에 넣기]** — 이 좌표가 이미 그룹에 있고 함께 할당할 Owner 도 없으면 버튼을 감춘다 |

| 항목 | 규칙 |
|---|---|
