## 2. 화면 구성

### 개요

App Key 를 발급하는 화면이다. 「**고객사 · App Key 계정 · 계정 상세**」 3단 한 화면이며 옛 `TKT-01` 계정 발급(목록)과 옛 `TKT-02` 계정 등록·수정을 합쳤다 `PC-146` `PC-158`. 고객사는 **고객사 관리 고객사를 불러온다**(여기서 등록하지 않음) `PC-153`. 계정은 **App Key 계정** — 계정과 App Key 가 매칭되는 개념으로, 고객사 관리의 **서비스 계정**(서비스 권한)과 별개다. 화면 모양은 `TKT-02` N Key 관리와 같은 조각을 쓴다 `PC-154`. **App Key 와 티켓은 다른 개념** — 계정 상세의 탭이 [App Key] · [권한] / [티켓 발급] · [티켓 내역] · [정산] / [계정 정보] 로 나뉜다 `PC-208`.

### 기능 개요

**App Key 를 발급하는 화면**이다. 「**고객사 | App Key 계정 | 계정 상세**」 3단 한 화면에서 고객사를 고르고, 그 고객사의 App Key 계정을 만들고, 계정마다 App Key 와 코드 범위(=티켓)를 발급한다.

| 항목 | 내용 |
|---|---|
| 권한 | STAFF / ADMIN |
| 진입 | 좌측 메뉴 **[티켓 발급] ▸ [App Key 관리 (계정 발급)]** (`/tickets/account`) |
| 고객사 | **고객사 관리(`MEM-01`) 고객사를 불러온다** — 여기서 고객사를 등록하지 않는다 `PC-153` |
| 계정 | **App Key 계정** — 계정과 App Key 가 매칭되는 개념(계정당 App Key 1개) |
| 과거 자료 | 개발팀 **Caster_계정_퍼미션_티켓.xlsx** 의 계정 15건(대장) — 고객사명으로 고객사 관리 고객사에 잇는다 |
| 짝 화면 | `TKT-02` N Key 관리 — 같은 3단 · 같은 UI 조각 `PC-154` |

> **App Key 계정 ≠ 서비스 계정.** App Key 계정은 *계정과 App Key 를 매칭*하는 발급 단위이고, 고객사 관리(`MEM-02`)의 **서비스 계정**은 *고객사가 서비스 권한(CasterN 등)을 갖게 하는* 계정이다. 두 계정은 서로의 목록에 나오지 않는다 `PC-128` `PC-153`.

### 화면 흐름 (Flow)

```
좌측 메뉴 [티켓 발급] ▸ [App Key 관리 (계정 발급)]
   └─▶ TKT-01  ┌ 고객사(고객사 관리) ┬ App Key 계정 ─────┬ 계정 상세 ─────────────────┐
               │ [발급 고객사]/[전체] │ 카드 목록          │ 탭: 계정 정보 / App Key 발급 │
               │ 검색 · 고객사 미연결 │ [＋ 계정 추가]      │                            │
               └──────────────────┴──────────────────┴────────────────────────────┘
      고객사 클릭 ─▶ 그 고객사 계정 · 첫 계정 상세
      [＋ 계정 추가] ─▶ 「새 계정 · 작성 중」 + 빈 폼 ─ [계정 추가] ─▶ 그 계정 상세 (범위를 골랐으면 App Key 동시 발급)
      계정 상세 ├ 계정 정보 [저장]
                ├ App Key 발급 ─ [코드 범위 발급] ─▶ 티켓 + 원장 티켓(TKT-02 목록에는 N Key 만) · LOG-01
                ├ 발급 내역 [티켓 수정] ─▶ 수정 폼 ─ [수정 저장] (티켓 · 키 삭제 없음 `PC-192`) · 티켓 선택 ─▶ Key 정보
                └ [계정 삭제] ─(확인창)─▶ 다음 계정 — 발급된 티켓이 있으면 비활성
      발급 범위 없음 ─▶ SOB-02 에서 SOBP 할당 후 다시
```

### 정책

| 정책 | 이 화면에서의 적용 |
|---|---|
| `PC-153` 키 발급 고객사 | 고객사 = **고객사 관리 고객사**. 키 발급 화면에서 고객사를 등록하지 않는다 |
| `PC-128` 계정 2종 | **App Key 계정**(이 화면) / **서비스 계정**(`MEM-02`) — 섞지 않는다 |
| `PC-029` 계정 수 | 고객사당 제한 없음. ID(이메일)는 **전체에서 유일**(서비스 계정 포함) |
| `PC-050` App Key 단위 | **계정당 1개** — 재발급 개념 없음. 이전에 발급된 키가 있으면 [발급 내역]에 기록만 보이고 새 키는 발급하지 않는다 `PC-206` |
| `PC-208` App Key · 티켓 분리 | App Key 와 티켓은 **다른 개념** — 계정 상세 탭을 **[App Key] · [권한]**(키 · 키 권한) / **[티켓 발급] · [티켓 내역] · [정산]**(티켓) / **[계정 정보]** 로 나눈다. App Key 는 **범위(SOBP) 없이 키만** 발급한다(계정 추가 때 「계정 추가와 함께 App Key 발급」 체크 · 기본 체크, 또는 [App Key] 탭의 [App Key 발급]). 티켓은 **App Key 를 먼저 발급한 계정에만** 발급 — 키가 없으면 [티켓 발급] 탭에 *App Key 를 먼저 발급하세요.* 첫 탭: 티켓이 있으면 [티켓 내역], 키만 있으면 [티켓 발급], 키가 없으면 [App Key] |
| `PC-207` App Key 권한 | 계정 상세 **[권한] 탭** — App Key 가 가지는 **Caster 권한 20항목**(Project · Edit · Export · Settings · Tool · Ncode · Nproj)을 **true / false** 로 지정한다. 표 = 대장과 같은 「분류 · Permission · 값 · 설명」 · [모두 true] [모두 false] · [취소] [권한 저장]. **기본값은 모두 false**, 개발팀 대장(`Caster_계정_퍼미션_티켓.xlsx`) 계정은 대장 값 그대로. 고객사 관리 서비스 계정의 CasterN 권한 6종(`PC-105`)과는 별개 |
| `PC-206` 티켓 = 계정 소속 | 고객사는 계정을 여러 개 둘 수 있고, **티켓은 App Key 가 아니라 계정에 소속**된다 — 계정당 여러 개. SOBP 가 바뀌어도 App Key 를 더 발급하지 않고 **티켓으로 발급**한다. 티켓 항목 = **Type · Section · Owner · Book · Page · Info · Period**(Caster 티켓 표기 — Type N3C6 = PDS3 · G3C6 = PDS2 · S1C6 = PDS4, Period YYMMDD · 무제한 = 991231). 정산은 **티켓마다** |
| `PC-118` 사용기간 | 계정이 아니라 **코드 범위(=티켓)마다** 유지 |
| `PC-119` 원장 티켓 | 코드 범위를 발급할 때마다 원장에 APP 티켓 1건. [티켓 수정] 시 함께 고친다 `PC-192` |
| `PC-200` 발급 내역 탭 | 계정 상세의 **첫 탭 [발급 내역]** — 지금까지 발급한 티켓(코드 범위)을 줄마다 **코드 구간(종류 · S · O · B · P)** 과 **발급일(대장분은 「대장」) · 권수 · 사용기간**, 정산, [수정] 으로 보인다. 줄을 누르면 그 아래에 Key 정보가 열리고 다시 누르면 접힌다. 발급분이 있으면 이 탭이 먼저 열리고(없으면 [App Key 발급]), [App Key 발급] 탭에는 발급 · 수정 폼만 둔다. 탭 순서 발급 내역 · App Key 발급 · 정산 · 계정 정보, 계정 저장 · 삭제 버튼은 [계정 정보] 탭에서만 |
| `PC-199` 하위 고객사 두 길 | 하위 고객사는 **상위 고객사 묶음 안에서도, 전체 목록 제자리에서도** 고를 수 있다. 하위 고객사를 바로 고르면 그 하위 고객사가 들어간 **모든 상위 고객사의 SOBP** 가 발급 범위에 나오고, 범위마다 「상위 · 상위 고객사명」 을 보인다 |
| `PC-198` 상위 고객사 접기 · 펼치기 | 상위 고객사 줄의 **▶ 로 하위 고객사를 접고 편다**(기본 접힘, 이름 옆 「하위 n」). 하위 고객사는 **왼쪽 세로 안내선 안에 들여** 보인다(└ · 「하위」 표시 없앰). 검색 중이거나 고른 고객사가 하위면 저절로 펼친다. App Key 관리 · N Key 관리 고객사 칸은 같은 조각 · 같은 모양 — N Key 고객사 칸의 「미정 n」 표시는 없앴다 |
| `PC-196` 하위 고객사 선택 | 왼쪽 고객사 목록에서 **하위 고객사는 상위(공통코드 보유) 고객사 밑에 └ 「하위」로 들여** 보인다. 고르고 [＋ 계정 추가] → App Key 발급 범위에 상위 SOBP 가 나온다. [발급 고객사] 보기에도 하위 고객사가 발급받은 상위 고객사가 함께 나온다 |
| `PC-195` 하위 고객사 · 구간 현황 | **하위 고객사는 상위(공통코드 보유) 고객사의 SOBP 영역으로 발급**한다 — 하위끼리는 Book · Page 가 겹치지 않게(`PC-174`). 범위를 고르면 아래에 **구간 사용 현황**(이미 발급된 구간 · 빈 Book 구간 · 입력 구간 사용 가능 여부)이 보이고, 빈 구간을 누르면 Start Book 이 그 자리로 간다 |
| `PC-192` 삭제 없음 · 수정 | 발급된 **티켓 · 키는 지우지 않는다.** 티켓 정보를 고치고, 바꾼 코드 구간은 **같은 S/O 의 할당 범위 안 + 다른 발급분과 겹치지 않을 때**(자기 자신 제외)만 저장한다. 발급된 티켓이 있는 계정은 삭제할 수 없다 |
| `P-05` 무겹침 | 범위는 **발급 범위 목록에서 고른다**(좌표를 타이핑하지 않음). Book · Page 만 지정 |
| `PC-174` SOBP 무겹침 | **N Key · App Key · 서비스 티켓은 SOBP 가 절대 겹칠 수 없다** — 계정 추가(범위 선택 시) · App Key 발급 · 코드 범위 추가 때 전체 발급분과 비교해 겹치면 막는다 |
| `PC-154` UI 통일 | `TKT-02` 와 같은 조각 — 한쪽만 고치지 않는다 |

#### 4.4 App Key 발급 · 티켓 발급 `PC-208`

**App Key**([App Key] 탭) — 범위 없이 **키만** 발급(계정당 1개, 영문 소문자 · 숫자 29자 예 `32b019140790385d8cb6fa32d9b81`). 키가 있으면 키 값 · [복사] · 발급일 · 이전 키 기록만(S8).

**티켓**([티켓 발급] 탭) — **App Key 를 먼저 발급한 계정에만**(없으면 S17). 아래 항목으로 발급한다.

| 항목 | 규칙 |
|---|---|
| 발급 범위 (Caster 대장 이력 · SOBP 할당) | 이 고객사의 Caster 대장 범위 + **고객사 관리에서 할당한 SOBP**. 고르면 Section·Owner·Book·Code Type 이 채워진다. 없으면 **이 고객사의 발급 범위가 없습니다.** (S10) |

### TKT-01: S15 하위 고객사 — 전체 고객사에서 바로 선택 · 발급 내역

*화면 정의서 상태 `S15`*

**구분** — 분기

하위 고객사는 상위 묶음 안뿐 아니라 **목록 제자리에도** 있어 **[전체 고객사]**에서 검색해 바로 고를 수 있다 `PC-199`. 고르면 그 고객사의 계정이 **[발급 내역]** 탭으로 열려 지금까지 발급한 티켓을 한눈에 본다 `PC-200`. 바로 골라 발급하면 그 하위 고객사가 들어간 **모든 상위 고객사의 SOBP** 가 발급 범위에 나온다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| 고객사 검색 | 입력 | 하위 고객사도 제자리에 보임 | 상위 묶음이 목록에 있으면 그 안에도 보인다 |
| 하위 고객사 | 클릭 | [발급 내역] 탭 | 티켓 줄 · 정산 · [수정] · 줄을 누르면 Key 정보 |
| [App Key 발급] 탭 범위 | 선택 | 모든 상위 고객사의 SOBP | 범위마다 「상위 · 상위 고객사명」 |

### TKT-01: S16 권한 탭 — App Key 권한 true / false

*화면 정의서 상태 `S16`*

**구분** — 분기

계정 상세의 **[권한]** 탭. 고객사 관리의 서비스 권한처럼, **App Key 가 가지는 Caster 권한 20항목**을 **true / false** 로 지정한다 `PC-207`. 표는 개발팀 대장(`Caster_계정_퍼미션_티켓.xlsx`)과 같은 「**분류 · Permission · 값 · 설명**」. **기본값은 모두 false**, 대장 계정은 대장의 값을 그대로 가져온다(예: 네오랩 17 · 스콜라스틱 12 · 맥컬리 6 · Tranwisdom 0 / 20). 탭 배지는 true 개수. 고객사 관리 서비스 계정의 CasterN 권한 6종과는 별개다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| 값 true / false | 클릭 | 그 항목만 바뀜 | 저장 전이면 **● 저장하지 않은 변경이 있습니다** |
| [모두 true] · [모두 false] | 클릭 | 20항목 한 번에 | — |
| [권한 저장] | 클릭 | 저장 | **권한이 저장되었습니다.** · 탭 배지 true 개수 · `LOG-01` |
| [취소] | 클릭 | 저장된 값으로 | — |

### TKT-01: S17 티켓 발급 — App Key 없는 계정

*화면 정의서 상태 `S17`*

**구분** — 빈 상태

티켓은 계정 소속이지만 **App Key 를 먼저 발급한 계정에만** 발급한다 `PC-208`. 키가 없는 계정의 **[티켓 발급]** 탭은 입력 폼 대신 **「App Key 를 먼저 발급하세요」** 안내와 [App Key 탭으로]만 보인다. [App Key] 탭에는 [App Key 발급] 버튼이 있다.

|---|---|---|---|
| [티켓 발급] 탭 | — | **차단** | **App Key 를 먼저 발급하세요. 티켓은 App Key 가 있는 계정에만 발급할 수 있습니다.** |
| [App Key 탭으로] | 클릭 | S8 | [App Key 발급] — 범위 없이 키만 |
