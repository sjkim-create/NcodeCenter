## 2. 화면 구성

### 개요

코드 발급·편집 업무에 필요한 **참조 정보**를 **밑줄 탭 5개**로 제공한다 — Code Info(Section별 발급 범위 — PDS2·PDS3·PDS4) · 확장 언어 슬롯 · 발급 구조 · **티켓 정보** `PC-246` · 알아야 할 사항. 모두 **참조 전용**이다. **[OID 관리대장] · [펜 모델] 탭은 폐지** `PC-325` — OID 설명은 [티켓 정보] 탭의 OID 안내 카드로, 좌표 조회는 SOBP 맵 [OID] 필터로 하고, 펜 모델은 화면 등록 없이 데이터를 직접 고쳐 관리한다. 권한은 전 역할(STAFF / ADMIN). 탭 2~5는 각각 `LangSlotView` · `NcodeInfoView` · `TicketInfoView` · `NcodeGuideView`를 불러 쓴다.

### 기능 개요

코드 발급·편집 업무에 필요한 **참조 정보**를 모아 둔 화면. 발급 범위(Section별 owner·bookcode·page·판형), 확장 언어 슬롯, 코드 발급 구조, 티켓 용도(OID 안내 포함), 운영상 알아야 할 기준을 **탭 5개**로 제공한다 `PC-325`.

| 항목 | 내용 |
|---|---|
| 권한 | 전 역할(STAFF / ADMIN) |
| 진입 | 좌측 메뉴 [코드 관리 정보] |
| 성격 | **참조 전용 · 기능 없음** — 입력·저장·발급 동작이 없다 |

> **INF-02(Common)와 INF-03(Cake)은 화면상 같은 탭에서 그룹 필터로 전환**된다. 문서상으로는 코드를 나눠 두되, 화면은 한 탭이고 고객사 관리의 확장 언어 그룹을 그룹별로 보여 준다 `PC-330`.

### 화면 흐름 (Flow)

```
좌측 메뉴 [코드 관리 정보]
   └─▶ INF-01
         ├─ 탭 [Code Info]         ─ Section별 발급 범위표 (PDS2 · PDS3 · PDS4)
         ├─ 탭 [확장 언어 슬롯]     ─ INF-02 Common / INF-03 Cake … 확장 언어 그룹별 보기 (그룹 필터) `PC-330`
         ├─ 탭 [발급 구조]          ─ 코드 체계 · SOBP 계층 · 펜 구분 · 오너코드 발급 구조 · 티켓 발급 구조
         ├─ 탭 [티켓 정보]          ─ App Key · N Key · 서비스 티켓 용도 `PC-246` + OID 안내 카드 `PC-325`
         └─ 탭 [알아야 할 사항]      ─ INF-05

   ※ [OID 관리대장](INF-04) · [펜 모델] 탭은 폐지 `PC-325`

여기서 확인한 기준으로 실제 작업은:
   코드 할당 ─▶ SOB-01 → SOB-02
   OID 좌표 조회 ─▶ SOB-01 [OID] 필터 `PC-325`
   티켓 발급 ─▶ TKT-02 / TKT-01
   편집 정산 ─▶ PRJ-02 → PRJ-03
```

### 정책

| 정책 | 이 화면에서의 적용 |
|---|---|
| `P-01` SOBP | 발급 범위는 Section별 **owner · bookcode · page · length(판형)** 로 정의된다. **PDS4(S-code)는 length 대신 `xy`** 를 갖는다 `PC-042` |
| `P-02` 코드 종류 = 좌표 속성 | 좌표(SOBP)마다 **PDS3(N3C6)=Ncode · PDS2(G3C6)=Gcode · PDS4(S-code, Section 44)** · **OID**(옛 IDS(A) 표기도 같은 것 `PC-035`) 를 갖는다 `PC-032` |
| `P-02-1` S/O 내 종류 단일 | **신규 발급**은 같은 S/O 에 한 종류만 `PC-041`. 과거 혼용 이력은 그대로 표시한다. OID 는 index 부여라 함께 쓸 수 있다 |
| `P-02-2` OID | **index 만 갖는 코드**(외부 코드를 우리 펜으로 판독 · 펜으로 찍으면 코드 1개 · 총량 약 6만 · 분량 적으면 book 미분할). 좌표 조회는 **SOBP 맵 종류 [OID] 필터** `PC-035`, 설명은 **[티켓 정보] 탭의 OID 안내 카드** `PC-325`(옛 [OID 관리대장] 탭 폐지). **새로 발급하지 않는다.** **옛 IDS(A) = OID 동일** |
| 판형(length) 규칙 | length = **코드를 입힐 수 있는 최대 크기**. 판형이 커지면 **Section이 달라진다** |
| 테스트/개발 섹션 | Section 1은 **테스트/개발 전용(상용 미출시)** |
| `PC-042` PDS4 범위 | Section **44 = PDS4(S-code)** — **owner 0~4095 · bookcode 0~255 · page 0~255 · xy 0~255**. Code Info 표에 정식 수록한다 |
| `P-12` 공통(커먼) 코드 | 확장 언어 슬롯은 공통코드 Owner 체계 위에서 운영된다 |
| 정책 정본 | 이 화면의 설명은 **참조**이며, 정본은 [정책 정의서](../NcodeCenter-정책정의서.md)·[운영 정책](../NcodeCenter-Operations-Policy.md) |

### 사용법

#### 4.1 Code Info (Section별 코드 발급 범위) — S1

Section별로 **PDS2(G3C6)** · **PDS3(N3C6)** · **PDS4(S-code)** 의 `owner · bookcode · page · length` 를 나란히 비교한다. Section 하나가 **4행**(항목별)으로 묶여 표시된다.

**PDS4(S-code)는 4번째 행이 `length` 가 아니라 `xy`** 다 `PC-042`. Section 44 행은 PDS2·PDS3 칸이 모두 `—` 이고 PDS4 칸에만 값이 있다.

| Section | PDS4 owner | PDS4 bookcode | PDS4 page | PDS4 xy |
|---|---|---|---|---|
| **44** | 0~4095 | 0~255 | 0~255 | 0~255 |

| 표에 나오는 Section | PDS2 범위 |
|---|---|
| **0 · 3 · 14** | 있음 |
| **5 · 10 · 11 · 15** | **없음** — PDS2 칸이 전부 `—` |

즉 PDS3는 7개 Section 전부, PDS2는 3개 Section만 쓸 수 있다.

**length(판형)의 의미** — 화면 안내 그대로

- length는 **코드를 입힐 수 있는 최대 크기(판형)** 를 나타냅니다. (length ≒ 판형 크기)
- 신규 프로젝트 시작 시 **향후 발매 예정 콘텐츠의 판형까지 고려**해 큰 사이즈가 필요하면, 그에 맞는 **섹션·오너를 발행**해 드립니다.
- 초반에 작은 판형만 쓰다가 이후 **큰 판형 교구에 코드 적용**이 필요해지면, **신규 섹션의 코드를 발행**해 펌웨어 혹은 서비스 프로그램에 추가하여 작업합니다.
- 따라서 **최대 적용 크기(판형=length)와 페이지 수를 모두 고려**해야 하며, **판형 크기에 따라 섹션이 달라집니다.**
- ※ Section 1은 테스트/개발 전용(상용 미출시).
- ※ **Section 44 = PDS4(S-code)** — owner 0~4095 · bookcode 0~255 · page 0~255 · **xy 0~255** 로 관리한다 `PC-042`. PDS4 는 판형(length) 대신 **xy** 값을 가지므로 표의 마지막 행이 xy 다.

> 판형(length)과 페이지 수를 보고 **어느 Section에 발급할지 사람이 판단하는 근거표**다. 조건으로 Section을 자동 추천하던 기능은 **폐기**되었다(`PC-028`).

#### 4.2 확장 언어 슬롯 (INF-02 Common / INF-03 Cake) — S2 · S3 · S8

**보기 전용 그룹 보기**다 `PC-330`. 고정된 Common · Cake 두 묶음 대신 **고객사 관리 ▸ 공통코드 · 확장 언어** 에 등록된 **확장 언어 그룹**을 그룹마다 하나씩 보여 준다. 이 화면에서는 아무것도 고칠 수 없다.

- **안내** — 「그룹 · 언어는 **고객사 관리** ▸ 공통코드 · 확장 언어 에서, Owner 연결은 **SOBP 맵** 할당 창에서 합니다.」 두 화면 이름은 링크다.
- **필터** — **[전체]** + 그룹명(지금은 **[Common-21] [Cake-1009]**). 그룹을 고르면 그 그룹만 보인다(S3).
- **그룹 머리** — 그룹명 · **확장 언어 슬롯** · *{코드 종류} · Section {n} · 기본 O{n} · 확장 O{첫}~O{끝} ({n}개) · 필요 언어 {n}개 · 오너당 4슬롯*. 확장 범위는 작은 번호부터 적는다. Section · 기본 Owner 가 아직 없으면 *미정*, 확장 Owner 가 없으면 *없음*.
- **Owner 카드** — 기본 Owner 가 첫 카드(**기본** 표시 · 슬롯 1~4)이고 확장 Owner 는 **연결한 순서**대로 슬롯 5~8 · 9~12 … 를 갖는다. 카드마다 슬롯 4줄(번호 + 언어)이며 언어가 없는 슬롯은 **사용가능**으로 표시된다.
- **할당 전 자리** — 그룹의 **필요한 Owner 수**(기본 1 + ⌈필요 언어 수 ÷ 4⌉ − 1)만큼 카드를 보인다. 아직 Owner 가 연결되지 않은 자리는 *할당 전*(점선 카드)이고 고객사 관리에서 미리 넣은 언어가 보인다 `PC-334` (S8).
- **그룹이 없을 때** — *등록된 확장 언어 그룹이 없습니다.*

| 그룹 | 코드 종류 | 기본 Owner (슬롯 1~4) | 확장 Owner | 필요 언어 | 등록된 확장 언어 |
|---|---|---|---|---|---|
| **Common-21** (INF-02) | PDS2 | O21 (한국어·영어·중국어·일본어) | O964~O983 (20개) | 10개 | O964 베트남어·러시아어·몽골어·캄보디아어(크메르어) · O965 스리랑카어·필리핀어(따갈로그어) |
| **Cake-1009** (INF-03) | PDS3 | O1009 (한국어·영어·일본어·스페인어) | O984~O1003 (20개 · O1003 부터 연결) | 8개 | O1003 BTS·중국어·인도네시아어·러시아어 |

- 두 그룹은 처음 화면의 기본값이며 이후 값은 고객사 관리에서 고친다. 두 그룹 모두 Section 3.

#### 4.3 발급 구조 — S4 · S9

**좌표(SOBP)가 먼저**이고 코드 종류(PDS3·PDS2·PDS4·OID)는 그 좌표의 속성이라는 **코드 체계**와 발급 구조를 설명한다 `PC-032`. 기능 조작 없이 읽는 페이지다.

| 섹션 | 내용 |
|---|---|
| 코드 종류 — 좌표(SOBP)의 속성 | PDS3(Ncode) · PDS2(Gcode) · PDS4(Scode) · OID(인덱스) **4행** 표 — 옛 IDS(A) 는 OID 와 같은 것이라 행을 두지 않는다 `PC-035` · 안내 3줄: 같은 S/O 는 PDS2·PDS3·PDS4 중 한 종류만(무겹침), OID 는 같은 S/O 함께 사용 가능 / 펜 구분(소리펜 · 필기펜)도 좌표 속성 / SOBP 맵 · 코드 프로젝트에서 PDS2 · PDS3 · PDS4 · OID 로 필터해 조회 |
| OID — index 전용 코드 | **개념** 3줄(index 만 갖는 코드 · 찍으면 코드 값 1개 · 약 60,000개라 book 미분할) + **대장 관리 방식** 표 — 업체 구분(S/O) · book 미분할(6만 페이지 미만은 업체 단위) · index 관리(book 번호 = OID index) · 조회 화면(SOBP 맵 [OID] 필터 · OID 설명은 [티켓 정보] 탭 카드, 옛 [OID 관리대장] 탭 폐지 `PC-325`) · 용어(IDS = OID) |
| SOBP 계층 | S · O · B · P 네 단계와 페이지 안 X·Y 좌표 |
| 펜 구분 · 편집 산출물 | 소리펜(Ncp) = ncp2(좌표 + mp3 묶음) · 디바이스(소리펜)에 저장 / 필기펜(Ndp) = nproj + PDF + JPG + 썸네일 png · 서버에 등록(mp3 리소스는 디바이스) |
| 오너코드 발급 구조 (예시) | Section · Owner · ACCOUNT · Book 범위 · Page · X · Y 예시 5행 — Section·Owner 에 따라 최대 차원이 다르다 · 페이지 1장이 2.3m 이하면 overflow 없이 페이지 수만으로 발급 규모를 산정 |
| 티켓 발급 구조 — N Key vs App Key | 사용처별 키(오프라인 편집툴 = N Key · 온라인(웹) 편집툴 = 계정 + App Key · SDK 연동 = App Key) · 비교표(성격 · 사용 대상 · 전달 방식 · 계정 연동 · 사용 흐름 · 주요 항목) · 발급 절차(1 코드 할당 → 2 티켓 발급 요청 → 3-A N Key / 3-B 계정 발급) · 계정 안내(App Key 는 계정 없이 발급되지 않음 · SDK 목적 고객사는 담당자가 임의 비밀번호 지정) |
| Section 1 · 44 안내 | Section 1 = 테스트/개발 전용(상용 미출시 · 레거시 아님) · Section 44 = PDS4(S-code) |

화면 정의서에서는 내용이 길어 **S4**(코드 종류 · OID · SOBP 계층)와 아래로 이어지는 **S9**(펜 구분 이하)로 나눠 그린다.

#### 4.4 티켓 정보 — S7

**App Key · N Key · 서비스 티켓**의 용도를 비교하는 읽기 전용 탭이다 `PC-246`. 비교표 · App Key 관계 카드 `PC-247` · 「어떤 티켓을 주나」 · N Key 프로필별 Section 표 다음에 **OID 안내 카드**가 오고 · 세 티켓 공통 규칙으로 끝난다.

**OID 안내 카드** `PC-325` — 옛 [OID 관리대장] 탭의 설명을 여기로 옮겼다. 제목 「OID — index 전용 코드 · 새로 발급하지 않음」.

- **OID = index 만 갖는 코드** — 외부 코드를 우리 펜으로 읽으려고 만든 방식. OID 책을 우리 펜으로 찍으면 코드 값이 1개만 나온다(옛 IDS 표기도 같은 것).
- 총량이 **약 60,000개**뿐이라 책의 양이 많지 않으면 **book 으로 코드를 나누지 않는다**. 업체 구분은 S/O, 분량이 늘어난 업체만 book 번호(= OID index)로 나눴다.
- SOBP(PDS2·PDS3·PDS4) 좌표 관리와 달리 **index 로만** 관리한다. 좌표로 보려면 **SOBP 맵에서 종류 [OID]** 로 필터한다.
- OID 는 티켓을 **새로 발급하지 않는** 코드 종류다(N Key 표 참고). 이력만 남아 있다.

**세 티켓 공통** — 4항목.

- 고객사에 **할당된 SOBP 안에서만** 발급 · 지정한다.
- App Key · N Key · 서비스 티켓은 **SOBP 가 겹칠 수 없다** — 고객사를 가리지 않고 전체 발급분과 비교한다.
- 발급한 티켓은 **지우지 않고 고친다**([티켓 수정]).
- SOBP 할당에는 기간이 없고(한 번 할당받은 고객사가 영구 소유), **사용기간은 티켓에만** 있다.

#### 4.5 알아야 할 사항 (INF-05) — S6

코드 발급·편집 운영에서 반드시 알아야 할 기준을 **번호 붙은 섹션 6개 + 정리**로 보여 준다.

| 섹션 | 요지 |
|---|---|
| ① 편집 비용 산출 기준 — 페이지 + 심볼 | 소리펜·필기펜 모두 **페이지 수 + 심볼 갯수**로 산출 · 심볼 = nproj 에서 영역을 설정한 편집 단위(리소스 매핑) · **심볼 갯수 = 작업량** · 필기펜 nproj 는 심볼이 늘수록 서버 용량 증가 · 재무팀은 편집 단가 협상 완료 |

| ④ 코드 발급 현황 — 재무·사업부용 | 발급 합계는 편집에 쓰지 않는다 · 사업부·재무팀이 **발급 규모**를 조회 · 코드 라이선스 비용은 사업팀이 별도 책정(편집 단가와 별개) |

| ⑥ 실제 산출 단가 (견적서 기준) | Ncode 적용 페이지당 500원 · Ncode 편집 심볼당 1,000 ~ 1,500원(난도 차등) · 노트서버 업로드 건당 10,000원 · 예: 2026-07-16 양지사 플래너 4종 견적 |
| 정리 | 리소스는 디바이스 저장, 필기펜 편집 파일만 서버 등록 · 페이지와 심볼 갯수로 작업량·비용 산출 · 발급 규모는 현황 파악용, 라이선스 비용은 사업팀 별도 책정 |

### INF-01: S02 확장 언어 슬롯 · 전체 그룹

*화면 정의서 상태 `S2`*

**구분** — 기본

PRD §4.2 — **보기 전용 그룹 보기** `PC-330`. 고정된 Common · Cake 두 묶음 대신 **고객사 관리 ▸ 공통코드 · 확장 언어**의 **확장 언어 그룹**을 그룹마다 카드 하나로 보여 준다. 필터 칩은 **[전체] + 그룹명**이다. 그룹 머리에 **{코드 종류} · Section · 기본 O{n} · 확장 O{첫}~O{끝} ({n}개) · 필요 언어 {n}개 · 오너당 4슬롯**을 붙인다. Owner 카드는 `repeat(auto-fill, minmax(168px, 1fr))` 격자이며 **Owner 당 4슬롯**, 슬롯 번호는 기본 1~4 · 확장은 연결 순서대로 5~8 · 9~12 … 로 이어진다. 언어가 없는 슬롯은 **사용가능**이다. 이 화면에서는 고칠 수 없다 — 그룹 · 언어는 고객사 관리, Owner 연결은 SOBP 맵 할당 창에서 한다.
