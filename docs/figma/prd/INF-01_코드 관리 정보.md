## 2. 화면 구성

### 개요

코드 발급·편집 업무에 필요한 **참조 정보**를 **밑줄 탭 4개**로 제공한다 — Code Info(Section별 발급 범위 — PDS2·PDS3·PDS4) · 확장 언어 슬롯 · 발급 구조 · OID 관리대장 · 알아야 할 사항. **참조 전용 · 기능 없음**이며 권한은 전 역할(STAFF / ADMIN). 탭 2~4는 각각 `LangSlotView` · `NcodeInfoView` · `NcodeGuideView`를 `embedded`로 불러 쓴다.

### 기능 개요

코드 발급·편집 업무에 필요한 **참조 정보**를 모아 둔 화면. 발급 범위(Section별 owner·bookcode·page·판형), 확장 언어 슬롯, 코드 발급 구조, 운영상 알아야 할 기준을 탭으로 제공한다.

| 항목 | 내용 |
|---|---|
| 권한 | 전 역할(STAFF / ADMIN) |
| 진입 | 좌측 메뉴 [코드 관리 정보] |
| 성격 | **참조 전용 · 기능 없음** — 입력·저장·발급 동작이 없다 |

> **INF-02(Common)와 INF-03(Cake)은 화면상 같은 탭에서 프로젝트 필터로 전환**된다. 문서상으로는 코드를 나눠 두되, 화면은 한 탭이다.

### 화면 흐름 (Flow)

```
좌측 메뉴 [코드 관리 정보]
   └─▶ INF-01
         ├─ 탭 [Code Info]         ─ Section별 발급 범위표 (PDS2 · PDS3 · PDS4)
         ├─ 탭 [확장 언어 슬롯]     ─ INF-02 Common / INF-03 Cake (필터 전환)
         ├─ 탭 [발급 구조]          ─ INF-04
         └─ 탭 [알아야 할 사항]      ─ INF-05

여기서 확인한 기준으로 실제 작업은:
   코드 할당 ─▶ SOB-01 → SOB-02
   티켓 발급 ─▶ TKT-04 / TKT-01
   편집 정산 ─▶ PRJ-02 → PRJ-03
```

### 정책

| 정책 | 이 화면에서의 적용 |
|---|---|
| `P-01` SOBP | 발급 범위는 Section별 **owner · bookcode · page · length(판형)** 로 정의된다. **PDS4(S-code)는 length 대신 `xy`** 를 갖는다 `PC-042` |
| `P-02` 코드 종류 = 좌표 속성 | 좌표(SOBP)마다 **PDS3(N3C6)=Ncode · PDS2(G3C6)=Gcode · PDS4(S-code, Section 44)** (+IDS 이력) 를 갖는다 `PC-032` |
| `P-02-1` S/O 내 종류 단일 | **신규 발급**은 같은 S/O 에 한 종류만 `PC-041`. 과거 혼용 이력은 그대로 표시한다. OID 는 index 부여라 함께 쓸 수 있다 |
| `P-02-2` OID | **index 만 갖는 코드**(외부 코드를 우리 펜으로 판독 · 펜으로 찍으면 코드 1개 · 총량 약 6만 · 분량 적으면 book 미분할). 좌표 조회는 **SOBP 맵 종류 [OID] 필터**, 업체별 index 목록은 **`INF-04` 탭** `PC-035`. **옛 IDS(A) = OID 동일** |
| 판형(length) 규칙 | length = **코드를 입힐 수 있는 최대 크기**. 판형이 커지면 **Section이 달라진다** |

| `PC-042` PDS4 범위 | Section **44 = PDS4(S-code)** — **owner 0~4095 · bookcode 0~255 · page 0~255 · xy 0~255**. Code Info 표에 정식 수록한다 |
| `P-12` 공통(커먼) 코드 | 확장 언어 슬롯은 공통코드 Owner 체계 위에서 운영된다 |
| 정책 정본 | 이 화면의 설명은 **참조**이며, 정본은 [정책 정의서](../NcodeCenter-정책정의서.md)·[운영 정책](../NcodeCenter-Operations-Policy.md) |

### 사용법

#### 4.1 Code Info (Section별 코드 발급 범위) — S1

Section별로 **PDS2(G3C6)** · **PDS3(N3C6)** · **PDS4(S-code)** 의 `owner · bookcode · page · length` 를 나란히 비교한다. Section 하나가 **4행**(항목별)으로 묶여 표시된다.

**PDS4(S-code)는 4번째 행이 `length` 가 아니라 `xy`** 다 `PC-042`. Section 44 행은 PDS2·PDS3 칸이 모두 `—` 이고 PDS4 칸에만 값이 있다.

| Section | PDS4 owner | PDS4 bookcode | PDS4 page | PDS4 xy |
|---|---|---|---|---|
| **44** | 0~4095 | 0~255 | 0~255 | 0~255 |

| 표에 나오는 Section | PDS2 범위 |
|---|---|
| **0 · 3 · 14** | 있음 |
| **5 · 10 · 11 · 15** | **없음** — PDS2 칸이 전부 `—` |

즉 PDS3는 7개 Section 전부, PDS2는 3개 Section만 쓸 수 있다.

**length(판형)의 의미** — 화면 안내 그대로

- length는 **코드를 입힐 수 있는 최대 크기(판형)** 를 나타냅니다. (length ≒ 판형 크기)
- 신규 프로젝트 시작 시 **향후 발매 예정 콘텐츠의 판형까지 고려**해 큰 사이즈가 필요하면, 그에 맞는 **섹션·오너를 발행**해 드립니다.
- 초반에 작은 판형만 쓰다가 이후 **큰 판형 교구에 코드 적용**이 필요해지면, **신규 섹션의 코드를 발행**해 펌웨어 혹은 서비스 프로그램에 추가하여 작업합니다.
- 따라서 **최대 적용 크기(판형=length)와 페이지 수를 모두 고려**해야 하며, **판형 크기에 따라 섹션이 달라집니다.**
- ※ Section 1은 테스트/개발 전용(상용 미출시).
- ※ **Section 44 = PDS4(S-code)** — owner 0~4095 · bookcode 0~255 · page 0~255 · **xy 0~255** 로 관리한다 `PC-042`. PDS4 는 판형(length) 대신 **xy** 값을 가지므로 표의 마지막 행이 xy 다.

> 판형(length)과 페이지 수를 보고 **어느 Section에 발급할지 사람이 판단하는 근거표**다. 조건으로 Section을 자동 추천하던 기능은 **폐기**되었다(`PC-028`).

#### 4.2 확장 언어 슬롯 (INF-02 Common / INF-03 Cake) — S2 · S3

언어별 코드 슬롯이 어떤 Owner에 배정돼 있는지 확인한다. 상단 필터로 **전체 / Common / Cake** 를 전환한다.

| 프로젝트 | 코드 종류 | 기본 Owner | 확장 Owner |
|---|---|---|---|
| **Common** (INF-02) | PDS2(Gcode) | O21 (한국어·영어·중국어·일본어) | O964~O983 |
| **Cake** (INF-03) | PDS3(Ncode) | O1009 (한국어·영어·일본어·스페인어) | O1003~O984 (내림차순) |

- 오너당 **4슬롯** 단위로 표시되며, 언어가 지정되지 않은 슬롯은 **사용가능**으로 표시된다.
- 출처: 소리펜 코드 목록 원본의 「Common 추가 언어 슬롯(964~983)」·「Cake(984~1003)」 시트.

#### 4.3 발급 구조 (INF-04) — S4

**좌표(SOBP)가 먼저**이고 코드 종류(PDS3·PDS2·PDS4·OID·IDS)는 그 좌표의 속성이라는 **코드 체계**와 발급 구조를 설명한다 `PC-032`. 기능 조작 없이 읽는 페이지다.

#### 4.4 알아야 할 사항 (INF-05) — S5

코드 발급·편집 운영에서 반드시 알아야 할 기준을 정리한다.

| 항목 | 요지 |
|---|---|
| 편집 비용 산출 | 소리펜·필기펜 모두 **페이지 수 + 심볼 개수**로 산출. 심볼 개수 = 작업량 |
| 산출물·저장 위치 | 리소스(mp3)·ncp2는 **디바이스**, nproj·PDF·JPG·썸네일은 **서버 등록** |
| 코드 종류 | PDS3(N3C6)=Ncode · PDS2(G3C6)=Gcode · **PDS4(S-code) = Section 44** · **OID**(index 전용 · 옛 IDS(A) 표기 포함) |
| OID 섹션 | **index 만 갖는 코드** — 개념(코드 1개 노출 · 약 6만 개 · book 미분할)과 관리 방식(업체 S/O 구분 · book 번호 = index)을 표로 설명. **조회 화면**(SOBP 맵 [OID] 필터 · `INF-04` 탭)과 **용어**(IDS = OID) 행 포함 |
| 펜 구분 | **소리펜(NSP) · 필기펜(NWP)** — 좌표 속성 |
| 코드 발급 현황 | 사업부·재무팀이 **발급 규모**를 조회. 코드 라이선스 비용은 사업팀이 별도 책정 |
| 실제 산출 단가 | 견적 기준 단가(적용·편집·노트서버 업로드 등) |

> 단가의 정본은 `P-16`(2026 항목별 단가표)이며, 고객사별 단가는 `MEM-02`에서 지정한다.

### INF-01: S04 발급 구조

*화면 정의서 상태 `S4`*

**구분** — 기본

PRD §4.3 — **좌표(SOBP)가 먼저**이고 코드 종류(PDS3·PDS2·PDS4·OID·IDS)는 그 좌표의 속성이라는 **코드 체계**와 **SOBP 계층**을 설명한다 `PC-032`. 기능 조작 없이 읽는 페이지다. 본문 최대 폭 1000px.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |

| 코드 종류 표 | 조회 | — | PDS3(N3C6)=**Ncode** 현행 주력 · PDS2(G3C6)=**Gcode** 구형/호환 · **PDS4(S-code)=Section 44**(owner 0~4095 · book 0~255 · page 0~255 · xy 0~255) · **OID**=인덱스 전용(같은 S/O 공유, B/P로 구분) · IDS(A)=이력 전용 |
