## 2. 화면 구성

### 개요

로그인 후 처음 만나는 화면. **코드가 얼마나 남아 있고 · 편집이 얼마나 진행됐고 · 받을 돈이 얼마이고 · 지금 처리할 일이 무엇인지**를 한 화면에서 파악한다. 분야별 **4개 구역**(코드 · 편집 · 정산 · 운영)으로 나뉘며 **조회 전용**이다 — 상세 확인·수정은 각 화면코드로 이동해서 수행한다. 집계는 화면을 열 때 원장에서 다시 계산하며, 계산 규칙과 예시는 PRD §4.2 에 있다.

### 기능 개요

로그인 후 처음 만나는 화면. **코드가 얼마나 남아 있고 · 편집이 얼마나 진행됐고 · 받을 돈이 얼마이고 · 지금 처리할 일이 무엇인지**를 한 화면에서 파악한다.

| 항목 | 내용 |
|---|---|
| 권한 | STAFF / ADMIN — **권한 분기 없음**(두 역할이 같은 화면을 본다) |
| 진입 | 로그인 성공 직후 · 좌측 메뉴 [대시보드] |
| 성격 | **조회 전용** — 이 화면에서 데이터를 등록·수정하지 않는다 |
| 구성 | **4개 구역**을 위에서 아래로 배치 — ① 코드(SOBP) ② 편집(CasterN) ③ 정산 ④ 운영 |

각 구역은 **요약 카드 3장 + 상세 카드**로 이루어지고, 구역 제목 우측의 이동 링크로 해당 관리 화면에 들어간다.

### 화면 흐름 (Flow)

```
로그인 ──▶ DSH-01 대시보드
             │
             ├─ ① 코드   ─── 카드/구역 링크 ──▶ SOB-01 SOBP 맵
             │                              ▶ PRJ-01 코드 프로젝트
             ├─ ② 편집   ─── 카드/구역 링크 ──▶ PRJ-02 편집 프로젝트 목록
             │                              ▶ MEM-01 고객사 관리 (전용 단가)
             ├─ ③ 정산   ─── 카드/구역 링크 ──▶ TKT-01 Key 관리
             │                              ▶ PRJ-02 편집 프로젝트 목록
             └─ ④ 운영   ─── 알림 항목 ──────▶ TKT-01 / TKT-04 / MEM-01 / SOB-01
                            [전체 로그] ────▶ LOG-01 활동 로그
```

이 화면은 **요약과 이동**만 제공한다. 값의 수정은 각 화면코드에서 수행한다.

### 정책

| 정책 | 이 화면에서의 적용 |
|---|---|
| `P-04` 코드 상태 = 할당됨 / 미발급 | 코드는 두 상태뿐이다. 예약·사용중 구분을 쓰지 않는다 (`PC-004`) |
| `P-01` SOBP | 집계 축은 Section / Owner / Book. 한글 대체어를 쓰지 않는다 |
| 테스트/개발 · 레거시 Section | 상용 미출시·옛 체계 Section에 배지를 붙여 상용 물량과 구분한다. **표기 전용**이며 집계에서 제외하지 않는다 |
| 편집 단가 | 청구액은 **교재 등록 시점의 고객사 단가**로 계산한다. 이후 단가를 바꿔도 기존 교재 금액은 변하지 않는다 |
| 정산 유형 | 미정 / 유료 / 무료 / 체험 4종. **미정은 아직 과금 결정이 안 된 상태**이며 매출로 잡지 않는다 |
| `P-18` 사용 관제(목표) | 집계는 발급 원장 기준이다. 실사용량 자동 반영은 미구현(§7) |

### 사용법

#### 4.1 화면 구성

##### ① 코드 (SOBP)

| 카드 | 값 | 부가 표기 |
|---|---|---|
| 코드 할당율 | 소유 owner 비율 | owner 정원 총합 · 진행 막대 |
| 발급 owner | 소유 owner 수 | 발급 레코드 수 · 업체 수 |
| 미발급 owner | 남은 owner 수 | 사용률이 가장 높은 Section 과 그 비율 |

**Section별 소유 현황** — Section마다 `소유 owner / 정원` 을 가로 막대로 비교한다. Section 이름 옆에 **테스트/개발** 또는 **레거시** 배지가 붙는다. 사용률이 **50% 이상인 Section은 강조 표시**하고 비율(%)을 함께 적는다.

**업체별 점유 Top 10** — 소유 owner 수 상위 10개 업체를 순위·업체명·막대·`owner {n}` 으로 표시한다.

##### ② 편집 (CasterN)

| 카드 | 값 | 부가 표기 |
|---|---|---|
| CasterN 고객사 | 편집 고객사 수 | 편집 교재 총 권수 |
| 편집 완료 교재 | 완료 상태 교재 수 | 전체 대비 비율 |
| 전용 단가 고객사 | 기본 단가를 벗어난 고객사 수 | 전체 고객사 수 |

**편집 진행 상태 분포** — 교재를 **진행중 / 완료 / 보류** 3상태로 나눠 누적 막대와 3칸 요약(건수·비율)으로 보여준다. 상태를 한 번도 지정하지 않은 교재는 **진행중**으로 집계한다.

##### ③ 정산

| 카드 | 값 | 부가 표기 |
|---|---|---|
| 편집 비용 청구액 | 편집 교재 청구액 합계 | 정가와 할인액 (할인이 있을 때만) |
| 미정산 금액 추정 | 미정 티켓의 추정 금액 합계 | 미정 건수 · 추정 근거별 건수 |
| Key 발급 정산 | 유료 티켓 금액 합계 | 유료 / 무료 / 체험 / 미정 건수 |

미정산 금액은 **추정치**이므로 값 앞에 `~` 를 붙이고, 어떤 근거로 몇 건을 계산했는지 함께 적는다.

##### ④ 운영

**운영 알림** — 처리가 필요한 항목만 건수와 함께 나열하고, 누르면 해당 화면으로 이동한다. **건수가 0이면 흐리게 표시**해 "할 일 없음"도 읽히게 한다.

| 알림 | 대상 | 이동 |
|---|---|---|
| 정산 미등록 티켓 | 과금 유형이 미정인 발급 티켓 | `TKT-01` |
| 체험 기간 만료 | 체험 만료일이 지난 티켓 | `TKT-01` |
| 체험 만료 임박 | 만료까지 7일 이내인 티켓 | `TKT-01` |
| App Key 미연동 계정 | 계정은 있으나 발급된 키가 없는 경우 | `TKT-04` |
| 사업 종료 고객사 | 종료 처리된 고객사와 보유 코드 프로젝트 건수 | `MEM-01` |
| 정원 50% 이상 사용 Section | 코드 여력이 줄어든 Section 목록 | `SOB-01` |

**최근 활동** — 최근 **8건**을 시간순으로 보여준다. 한 줄은 `MM-DD HH:MM` · 활동 종류 · 내용 · 담당자다.

#### 4.2 계산 규칙

집계는 모두 **화면을 열 때 원장에서 다시 계산**한다. 별도 저장값을 쓰지 않는다.

**(가) 코드 할당율**

```
코드 할당율 = 모든 Section 의 소유 owner 합 ÷ 모든 Section 의 owner 정원 합

예) 소유 475 ÷ 정원 13,568 = 0.0350 → 3.5%
    미발급 owner = 13,568 − 475 = 13,093
```

**(나) Section 사용률 · 경고 대상**

```
Section 사용률 = 그 Section 의 소유 owner ÷ 그 Section 의 정원
50% 이상이면 경고 대상

예) Section 5 : 163 ÷ 256 = 0.637 → 63.7% → 경고 대상
    Section 3 : 212 ÷ 4,096 = 0.052 → 5.2% → 해당 없음
```

**(다) 편집 비용 청구액**

교재 1권마다 계산한 뒤 전부 더한다. 단가는 **그 교재를 등록할 때의 고객사 단가**를 쓴다.

```
교재 청구액 = (페이지 수 × 페이지 단가 + 심볼 수 × 심볼 단가) − 할인
할인 = 정가 × 할인율 + 할인 금액

예) 페이지 320쪽 × 500원         = 160,000
    심볼 1,250개 × 1,000원        = 1,250,000
    정가                          = 1,410,000
    할인 10%                      = −141,000
    교재 청구액                    = 1,269,000
```

**(라) 편집 완료율**

```
편집 완료율 = 완료 상태 교재 수 ÷ 전체 교재 수

예) 완료 1,240권 ÷ 전체 8,483권 = 0.146 → 14.6%
```

**(마) 미정산 금액 추정**

미정 티켓마다 아래 순서로 금액을 정하고 합산한다.

```
1순위 : 같은 고객사의 가장 최근 유료 티켓 금액
2순위 : 전체 유료 티켓의 평균 금액
해당 없음 : 유료 이력이 전혀 없으면 그 건은 합계에서 제외

예) 전체 유료 3건 = 3,500,000 + 4,800,000 + 2,200,000 → 평균 3,500,000

    미정 ① 웅진씽크빅 — 최근 유료 4,800,000  → 1순위 적용   4,800,000
    미정 ② 대교       — 최근 유료 3,500,000  → 1순위 적용   3,500,000
    미정 ③ 신규업체   — 유료 이력 없음        → 2순위 적용   3,500,000
                                              추정 합계  11,800,000
    표기 : ~₩11,800,000 · 미정 3건 · 고객사 단가 2 / 평균 1
```

#### 4.3 사용 절차

1. 로그인하면 대시보드가 열린다.
2. **④ 운영 알림**에 건수가 있는지 먼저 본다 — 오늘 처리할 일이다.
3. **③ 정산**에서 청구 예정 금액과 미정산 규모를 확인한다.
4. **① 코드**에서 남은 발급 여력과 사용률이 높은 Section 을 확인한다.
5. **② 편집**에서 진행 물량과 완료 비율을 확인한다.
6. 상세 확인·수정은 각 카드·알림의 이동 링크를 따라간다.
