## 2. 화면 구성

### 개요

고객사를 **등록**하고 **상세·수정**하는 화면이다. 「**머리말 + 섹션 메뉴 · 본문**」 구조이며 섹션은 고객사 정보(기본 정보 · 편집 단가 · 관련 서류)와 운영(서비스 계정 · 업무 메모)이다 `PC-136`. **등록**은 한 번 — 머리말 [등록] 또는 서비스 계정 [계정 추가](고객사 함께 등록). 그 뒤는 **섹션·계정 단위로 저장**한다(PRD §4.8). 진행 상태는 머리말 오른쪽 진행중/사업 종료 `PC-139`, 사용 서비스는 **서비스 계정의 서비스** `PC-138`, 서비스 계정은 「카드 목록 · 상세」와 서비스 권한 탭 `PC-140` — **선택**이고, 비밀번호는 받지 않으며 **OWNER 는 1명** `PC-159`.

### 기능 개요

`MEM-01` 고객사 목록에서 열리는 **두 화면**이다. 모달이 아니라 각각 독립된 페이지다.

| 화면 | 주소 | 하는 일 |
|---|---|---|
| **고객사 등록** | `/companies/new` | 기본 정보를 입력하고 **[등록]**, 또는 서비스 계정에서 **[계정 추가]** 로 고객사와 계정을 함께 등록한다 |
| **고객사 상세·수정** | `/companies/{id}` | 섹션마다 고쳐 **[저장]**, 서비스 계정·업무 메모를 관리하고, 머리말에서 진행 상태를 바꾼다 |

| 항목 | 내용 |
|---|---|
| 권한 | STAFF / ADMIN |
| 진입 | `MEM-01` 의 **[＋ 고객사 등록]** / 목록 행 클릭 |
| 화면 구성 | **머리말**(업체명 · 구분 · 요약 · 진행중/사업 종료 · ⋯) + **섹션 메뉴** + **본문** `PC-136` |
| 섹션 | 고객사 정보(기본 정보 · 편집 단가 · 관련 서류) / 운영(서비스 계정 · 업무 메모) |
| 저장 | **§4.8 등록과 저장** — 등록은 한 번, 그 뒤는 섹션·계정 단위로 저장한다 |

> 등록 화면에는 업무요청 메모가 없다. 고객사가 만들어진 뒤부터 기록한다.
> 계정은 **App Key 관리의 키 발급 계정(티켓 고객사)과 다른 계정**이다 — 여기 계정은 고객사 관리 고객사의 **서비스 로그인 계정**이다 `PC-128`.

### 화면 흐름 (Flow)

```
MEM-01 고객사 목록
   ├─ [＋ 고객사 등록] ─▶ MEM-02 등록  (/companies/new)
   │      ① 기본 정보 입력 (업체명 필수 · 그 전에는 서비스 계정 잠김)
   │      ② (선택) 편집 단가 · 관련 서류 · 공통코드 · 진행 상태
   │      ③ 등록 — 둘 중 하나
   │         ├─ 머리말 [등록] ─────────────▶ 고객사만 등록 → MEM-02 상세 (기본 정보)
   │         └─ 서비스 계정 [계정 추가] ────▶ 고객사 + 계정 등록 → MEM-02 상세 (서비스 계정)
   │      [취소] ─▶ MEM-01 (아무것도 저장되지 않음)
   │
   └─ 행 클릭 ─────────▶ MEM-02 상세·수정  (/companies/{id})
          ├─ 섹션 [저장] ──────────▶ 그 섹션만 저장 · 이 화면에 머무름
          ├─ 머리말 진행중/사업 종료 ─▶ 바로 저장
          ├─ 서비스 계정 [계정 추가]/[저장] ─▶ 그 계정만 바로 저장 → 사용 서비스 다시 계산
          ├─ 업무 메모 Enter ───────▶ 메모 1건 바로 기록
          ├─ [←] ──────────────────▶ MEM-01
          └─ ⋯ [고객사 삭제] ─(업체명 재입력 확인)─▶ MEM-01
```

### 정책

| 정책 | 이 화면에서의 적용 |
|---|---|
| `P-11` 고객사 계층 | 공통코드를 **사용**하도록 체크하면 그 고객사는 **하위 고객사**가 된다. **대표(상위) 회사는 자기 코드의 하위가 될 수 없어** 해당 항목이 비활성으로 표시된다 (`PC-015`) |
| `P-12` 공통(커먼) 코드 중앙 모델 | 하위 등록은 **이미 발급된 공통코드를 함께 쓰는 것**이므로 **코드 할당이 발생하지 않는다** |
| `P-16` 정산 단가 | 편집 단가는 **2026 항목별 단가표** 기준. **기본값에서 바꾼 항목만 이 고객사 전용 단가**가 된다 |
| `PC-027` 단가 적용 시점 | 단가는 **고객사마다 등록·수정**할 수 있고, 변경은 **이후 등록되는 교재(책)부터 적용**된다. **기존 교재는 등록 당시 단가를 그대로 유지**한다(소급 적용 없음) |
| 단가 3단 구조 | 기본 단가 → **이 화면의 고객사 단가** → 교재별 할인(`PRJ-04`) |
| 프로젝트 종료 | 사업이 끝난 고객사는 **종료**로 표시하고 사유·이관 메모를 남긴다(코드 발급 이력은 보존) |

### 사용법

#### 4.0 화면 구성 `PC-136`

| 영역 | 내용 |
|---|---|
| **머리말** | ← 목록 · 업체명 · 구분(상위/하위/단독) · 요약(사용 서비스 · 서비스 계정 n명(활성) · 업무 메모 · 편집 단가) · 오른쪽에 **진행중 / 사업 종료**(§4.3) · **⋯**(고객사 삭제). 등록 화면은 ⋯ 대신 **[취소] [등록]** |
| **섹션 메뉴** | 고객사 정보 — **기본 정보 · 편집 단가 · 관련 서류** / 운영 — **서비스 계정 · 업무 메모**. 메뉴 옆에 개수(전용 단가 · 서류 · 계정 · 메모), 저장하지 않은 섹션은 **●** |
| **본문** | 고른 섹션 한 칸. **서비스 계정**만 「카드 목록 \| 상세」 2칸(§4.9) |

- 서비스 계정은 **기본 정보(업체명)가 입력된 뒤에** 열린다 — 그 전에는 메뉴가 회색이고, 누르면 「기본 정보(업체명)를 먼저 입력하세요.」 `PC-139`
- 업무 메모는 고객사가 등록된 뒤에 쓸 수 있다.

|---|---|---|

| 담당자 | — | |
| 연락처 | — | |
| 사업자등록증번호 | — | 형식 예: `000-00-00000` |

#### 4.2 사용 서비스 = 서비스 계정의 서비스 `PC-138`

고객사 화면에서 사용 서비스를 따로 체크하지 않는다. **서비스 계정의 서비스 권한(§4.9)에서 켠 서비스가 곧 이 고객사의 사용 서비스**다.

| 서비스 | 계정에서 켜면 |
|---|---|
| **CasterN** | 이 고객사가 **[편집 프로젝트](`PRJ-02`)의 대상**이 되고, 그 계정이 CasterN 을 쓴다(권한 6종) |
| **폼솔루션** `준비중` | 이 고객사가 **[폼솔루션 서비스 관리]** 에 나타난다 |

- **계산 시점**: 계정을 추가·저장·삭제할 때 그 고객사 계정들의 서비스를 모아 다시 저장한다. 등록할 때는 함께 추가한 계정 기준이다.
- **계정이 없는 고객사는 기존 지정값을 유지**한다 — 옛 casterN 71곳은 계정이 없어도 편집 대상이다. 계정을 처음 넣으면 그때부터 계정 기준이며, 새 계정은 고객사의 현재 사용 서비스(casterN 이면 CasterN)를 기본으로 켠다. 마지막 계정을 지워도 지정값은 바꾸지 않는다.
- 머리말 요약과 메뉴(서비스 계정 「casterN · n」)에 사용 서비스가 보인다.

#### 4.3 프로젝트 상태 — 머리말 오른쪽 `PC-139`

머리말 오른쪽 **「진행중 | 사업 종료」** 로 고객사 전체를 바꾼다. 기본 정보 안에는 두지 않는다.

| 동작 | 결과 |
|---|---|
| **[사업 종료]** | 작은 창이 열린다 — **종료 사유 / 코드 이관 메모**(예: 엠베스트-28로 코드 이관)를 적고 **[사업 종료]** 를 누르면 **바로 저장**된다 · [취소] 로 닫는다 |
| **[진행중]** (사업 종료 상태에서) | 「진행중으로 되돌릴까요?」 확인 후 **바로 저장** |
| 종료 사유 | 전환 버튼에 마우스를 올리면 보인다 |
| 등록 화면 | 고른 상태가 **[등록] 때 함께** 저장된다 |

> 사업 종료 시 코드 발급 이력만 유지되고, 목록·코드 프로젝트에서 비활성(회색)으로 표시된다.

#### 4.4 공통코드 사용 고객사(하위) 등록 — 기본 정보 안 `PC-077` `PC-138`

*대표 회사 아래로 귀속 · 코드 할당 불필요*

- 사용할 공통코드를 체크하면 이 고객사가 그 **공통코드의 사용 고객사(하위)** 로 등록된다.
- 목록에 오르는 것은 **여러 고객사가 함께 쓰는 코드**뿐이다 `PC-044`. 보유 고객사가 **한 곳뿐(자기 자신·자사)** 이거나 사용 이력이 **없는 코드**는 일반 코드이므로 이 목록에 나오지 않는다.
- 안내: 이미 발급된 공통코드를 쓰므로 **코드 할당은 없고**, 편집 프로젝트·티켓 발급에서 하위 고객사로 관리된다.
- **자기 회사가 보유한 코드는 선택할 수 없다**(비활성).

**2열 카드**로 늘어놓는다 `PC-093` — 한 칸에 **공통코드명**(굵게)과 **좌표**(`PDS2 · S3/O21`)가 2줄로 들어가고, 선택하면 파란 테두리·연파랑 배경이 된다.

**현재 목록 (5건)** — 레지스트리는 `lib/commonCodes.ts` 가 정본이고, 정본 데이터는 `build_all_sources.py` 가 만든다.

| 공통코드 | 좌표 | 사용 고객사 |
|---|---|---|
| Common-21 | PDS2 · S3/O21 | 50곳 |
| 네오노트-0-27 | PDS3 · S0/O27 | 6곳 |
| 네오노트-3-27 | PDS3 · S3/O27 | 154곳 |

| 스마트클래스키트-1013 | PDS3 · S3/O1013 | 4곳 |

**목록에서 뺀 코드**

| 코드 | 뺀 이유 |
|---|---|
| NLJ NTT-940 · 딥스원테크-303 · 구몬D-37 | 보유 고객사 1곳(자사)이거나 사용 이력 0곳 `PC-044` |
| **Common 추가 언어 슬롯-964** (PDS2 · S3/O964) | **사용 고객사 0곳 · 다국어 편집용 레퍼런스**라 하위 고객사를 두지 않는다 `PC-082` |
| 네오노트-IDS-27 (OID · S4/O27) | **이력전용** — 검색·이력에만 쓰고 이 목록에는 올리지 않는다 |

> `Common 추가 언어 슬롯-964` 를 목록에서 빼도 **SOBP 맵의 공유 OWNER 판정은 그대로다** `PC-082` — `O964~983` 은 NSP 커먼 코드 범위(`sharedOwners.ts`)라 계속 **공유**로 표시되고 Book 단위 배타만 적용된다.

#### 4.5 편집 단가 (2026 항목별)

소리펜과 필기펜은 **정산 단위가 다른 별개 묶음**이라 각각 카드로 나눠 보여준다.

| 그룹 | 성격 | 그룹 머리 표기 |
|---|---|---|
| **🔊 소리펜** | ncp2 산출 · mp3 심볼 | 항목 수 · 그 그룹의 전용 단가 개수 |
| **✍ 필기펜** | 필기 인식 · APP 연동 | 항목 수 · 그 그룹의 전용 단가 개수 |

전용 단가가 있는 그룹에만 **[기본값]** 이 나타나며 **그 그룹 항목만** 되돌린다. 상단의 **[전체 기본값]** 은 두 그룹을 모두 되돌린다.

| 요소 | 동작 |
|---|---|
| 항목별 단가 입력 | 항목마다 **단위**(페이지당 / 심볼당 / 건당)가 함께 표시된다 |

| [전체 기본값] | 모든 항목을 기본 단가로 되돌린다 |

| Compound 5 / 6 / 7 / 8언어 | 2,200 / 2,500 / 2,800 / 3,100 | action 변경 편집 (심볼당) | 1,500 |

| 게임 / 프롬프트 편집 / 발음평가 편집 (건당) | 각 50,000 | 교원구몬/KEP (건당) | 1,000 ⚠ |

> ⚠ **Custom · 교원구몬/KEP** 단가는 미확정(`PC-018` 확인 대기).

안내: **편집 프로젝트의 청구액이 이 단가로 계산됩니다(항목 수량 × 단가). 단가를 바꾸면 이후 등록되는 교재(책)부터 적용되고, 기존 교재는 등록 당시 단가가 그대로 유지됩니다. 교재별 할인은 편집 프로젝트 > 교재 수정에서.**

#### 4.8 등록과 저장 `PC-136` `PC-142`

> **등록** = 새 고객사를 **만든다**(등록 화면에서 한 번). **저장** = 이미 있는 고객사의 **한 섹션 또는 한 계정**을 고친 내용을 반영한다.

##### ① 등록 순서 — `/companies/new`

| 순서 | 할 일 | 저장 여부 |
|---|---|---|
| 1 | `MEM-01` **[＋ 고객사 등록]** → 등록 화면(기본 정보 섹션) | — |
| 2 | **기본 정보** 입력 — **업체명 필수**. 업체명을 넣기 전에는 서비스 계정이 잠겨 있다 | 화면에만 있음 |
| 3 | (선택) 편집 단가 · 관련 서류 · 공통코드 사용 고객사 · 진행 상태 | 화면에만 있음 |
| 4 | **둘 중 하나로 등록한다** | |
| 4-a | 머리말(또는 섹션 아래) **[등록]** → **고객사만** 등록. 1~3 에서 입력한 모든 섹션이 함께 저장된다. **서비스 계정은 선택**이라 계정 없이 등록해도 된다 `PC-159` | **저장** |
| 4-b | 서비스 계정 **[계정 추가]** → **고객사 + 그 계정**을 함께 등록. 1~3 의 입력도 함께 저장된다 | **저장** |
| 5 | 등록되면 **상세·수정 화면**으로 이동한다 — 4-a 는 기본 정보, 4-b 는 **서비스 계정** 섹션이 열린다. 이후는 ② 저장 규칙 | — |

- 등록 전에 [취소]·[←] 로 나가면 **아무것도 저장되지 않는다.**
- 등록 화면에는 「임시」 계정이 없다 — 계정을 추가하는 순간 고객사가 등록된다 `PC-142`.
- 업체명 없이 [등록] → **업체명은 필수입니다.**

##### ② 저장 규칙 — `/companies/{id}`

| 대상 | 저장 단위 | 버튼 · 동작 | 저장 시점 |
|---|---|---|---|
| 기본 정보(업체 정보 · 공통코드 사용 고객사) | 섹션 | 섹션 아래 **[저장]** | 누를 때 |
| 편집 단가 | 섹션 | **[저장]** | 누를 때 |
| 관련 서류 | 섹션 | **[저장]** | 누를 때 |
| 진행 상태 | 고객사 전체 | 머리말 **진행중 / 사업 종료** | **바로**(사업 종료는 사유 입력 후 [사업 종료], 진행중은 확인 후) |
| 서비스 계정 — 새 계정 | 계정 1개 | **[＋ 계정 추가]** → 오른쪽 폼 → **[계정 추가]** | **바로** |
| 서비스 계정 — 기존 계정 | 계정 1개 | 카드 선택 → 상세에서 고친 뒤 **[저장]** | 누를 때 · 삭제는 [계정 삭제] 확인 후 |
| 사용 서비스 | 고객사 | — (자동) | 계정을 추가·저장·삭제할 때 다시 계산(§4.2) |
| 업무 메모 | 메모 1건 | **Enter** / [＋ 기록] | **바로** |

- **섹션은 서로 따로 저장된다.** 기본 정보에서 [저장]을 눌러도 편집 단가의 고친 내용은 저장되지 않는다.
- 고치고 저장하지 않은 섹션·계정은 **메뉴에 ●**, 본문 아래에 「저장하지 않은 변경이 있습니다」가 보인다. **[취소]** 는 마지막으로 저장한 값으로 되돌린다.
- 다른 섹션으로 옮겨 가도 고친 값은 화면에 남아 있다. **화면을 떠나면 저장하지 않은 변경은 사라진다.**

#### 4.9 서비스 계정 `PC-128` `PC-136` `PC-140`

**「카드 목록 | 상세」** 2칸이다. 고객사마다 **서비스 로그인 계정을 여러 개** 둔다(개수 제한 없음 · ID 는 전체에서 유일).

| 항목 | 내용 |
|---|---|
| 카드 목록 | 이름 · **OWNER** · **대장** 배지 · 이메일 · **활성/비활성** · **CasterN n/6** · 최근 접속일. OWNER 가 맨 위. 위에 **[＋ 계정 추가]**, 4개 이상이면 검색 |
| 카드 선택 | 오른쪽에 계정 상세 — **기본 정보**(ID 잠금 · NAME · 계정 상태 활성/비활성 · **OWNER (대표 계정)**) · **서비스 권한** · **접속 · 이력**(최근 접속일 · 등록일 · App Key) |
| [＋ 계정 추가] | 오른쪽에 등록 폼 — ID (이메일) \* · NAME · 계정 상태 · OWNER · 서비스 권한. 새 계정은 고객사의 현재 사용 서비스를 기본으로 켜고, CasterN 이면 권한 6종 모두 |
| 비밀번호 | **받지 않는다** — 서비스 로그인은 SSO 다 `PC-159` |
| OWNER (대표 계정) | **고객사당 1명** `PC-159`. 체크한 계정을 저장하면 기존 OWNER 는 자동으로 풀린다(체크하면 「저장하면 OWNER 가 {기존} 에서 이 계정으로 바뀝니다」). OWNER 가 없는 고객사의 첫 새 계정은 체크된 채 시작 (S21) |
| 계정 없음 | **서비스 계정은 선택**이다. 계정이 없어도 고객사는 등록·사용할 수 있고 등록 폼을 저절로 열지 않는다 (S22) |
| 서비스 권한 | **서비스 탭(CasterN · 폼솔루션)** — 탭 머리에 사용 여부 점과 권한 수. 탭 안은 **사용 스위치** + 설명(「[편집 프로젝트]의 대상이 되고, 이 고객사 계정에 CasterN 사용 권한을 줄 수 있습니다」) + [모두 선택/모두 해제] + **권한 3열 그리드**(라벨 + 키). 꺼져 있으면 그리드가 흐려진다 `PC-140` |
| 계정 상태 | **비활성**이면 서비스에 로그인할 수 없다 `PC-135` |
| 저장 | §4.8 ② — 새 계정은 [계정 추가]로 바로, 기존 계정은 [저장] |
| 가입 승인 연결 | `MEM-01` 가입 승인 카드의 **[계정 추가 →]** 로 들어오면 서비스 계정 등록 폼이 열리고 SSO 이메일이 ID 칸에 들어가 있다 `PC-133` |

> App Key 관리의 **키 발급 계정**(티켓 고객사)과 다른 계정이다 `PC-128`.
