## 2. 화면 구성

### 개요

고객사의 **기본 정보 · 공통코드 귀속 · 편집 단가 · 관련 서류**를 입력한다. **모달이 아니라 별도 페이지 2개**다 — `MEM-01` 의 [＋ 고객사 등록] = 등록, 행을 누르면 상세·수정. 입력 항목이 길어 좌측을 **3탭**(기본 정보 / 편집 단가 / 관련 서류)으로 나눴고, 수정 화면에서는 **업무요청 메모가 탭과 무관하게 우측에 고정**된다 — 단가를 조정하면서 요청 내용을 함께 볼 수 있다. 단가는 **3단 구조**(기본 단가 → 고객사 단가 → 교재별 할인)이며, 변경은 **이후 등록되는 교재부터** 적용되고 기존 교재는 등록 당시 단가를 유지한다 `PC-027`.

### 기능 개요

`MEM-01` 고객사 목록에서 열리는 **두 화면**이다. 모달이 아니라 각각 독립된 페이지다.

| 화면 | 주소 | 하는 일 |
|---|---|---|
| **고객사 등록** | `/companies/new` | 기본 정보·공통코드 귀속·단가·서류를 입력하고 **[등록]** |
| **고객사 상세·수정** | `/companies/{id}` | 같은 항목을 고쳐 **[저장]**, 우측에서 **업무요청 메모**를 남긴다 |

| 항목 | 내용 |
|---|---|
| 권한 | STAFF / ADMIN |
| 진입 | `MEM-01` 의 **[＋ 고객사 등록]** / 목록 행 클릭 |
| 좌측 구성 | **탭 3개** — 기본 정보 / 편집 단가 / 관련 서류 |
| 우측 구성 | **업무요청 메모** — 수정 화면에서만 · 탭과 무관하게 항상 보인다 |
| 저장 | **[등록]/[저장] 한 번으로 세 탭 내용이 함께 기록된다** |

> 등록 화면에는 업무요청 메모가 없다. 고객사가 만들어진 뒤부터 기록한다.

### 화면 흐름 (Flow)

```
MEM-01 고객사 목록
   ├─ [＋ 고객사 등록] ─▶ MEM-02 등록  (/companies/new)
   │      탭: 기본 정보 · 편집 단가 · 관련 서류
   │      └─ [등록] ─▶ MEM-01 목록으로
   │
   └─ 행 클릭 ─────────▶ MEM-02 상세·수정  (/companies/{id})
          ├─ 좌: 탭 3개
          ├─ 우: 업무요청 메모 (탭과 무관하게 고정)
          ├─ [저장] ─▶ 이 화면에 머무름
          ├─ [목록] ─▶ MEM-01
          └─ [고객사 삭제] ─(업체명 재입력 확인)─▶ MEM-01
```

### 정책

| 정책 | 이 화면에서의 적용 |
|---|---|
| `P-11` 고객사 계층 | 공통코드를 **사용**하도록 체크하면 그 고객사는 **하위 고객사**가 된다. **대표(상위) 회사는 자기 코드의 하위가 될 수 없어** 해당 항목이 비활성으로 표시된다 (`PC-015`) |
| `P-12` 공통(커먼) 코드 중앙 모델 | 하위 등록은 **이미 발급된 공통코드를 함께 쓰는 것**이므로 **코드 할당이 발생하지 않는다** |
| `P-16` 정산 단가 | 편집 단가는 **2026 항목별 단가표** 기준. **기본값에서 바꾼 항목만 이 고객사 전용 단가**가 된다 |
| `PC-027` 단가 적용 시점 | 단가는 **고객사마다 등록·수정**할 수 있고, 변경은 **이후 등록되는 교재(책)부터 적용**된다. **기존 교재는 등록 당시 단가를 그대로 유지**한다(소급 적용 없음) |
| 단가 3단 구조 | 기본 단가 → **이 화면의 고객사 단가** → 교재별 할인(`PRJ-04`) |
| 프로젝트 종료 | 사업이 끝난 고객사는 **종료**로 표시하고 사유·이관 메모를 남긴다(코드 발급 이력은 보존) |

### 사용법

#### 4.0 탭 구성

입력 항목이 길어 좌측을 탭으로 나눈다. **한 번에 한 탭만** 보여주고 아래로 쌓지 않는다.

| 탭 | 내용 | 탭 머리 표기 |
|---|---|---|
| **기본 정보** | 업체·담당자·사업자·계좌·주소 + **사용 서비스 탭**(casterN ▸ 프로젝트 상태·공통코드 귀속 / 폼솔루션) `PC-077` | — |
| **편집 단가** | 소리펜·필기펜 항목별 단가 | 전용 단가 개수 |
| **관련 서류** | 서류 항목·파일 | 등록된 서류 수 |

탭을 열지 않아도 **전용 단가 개수와 서류 수**가 탭 머리에 보인다.

수정 화면에서는 **업무요청 메모가 우측에 고정**되어 어느 탭을 보든 함께 보인다. 좌측을 스크롤해도 따라온다 — 단가를 조정하면서 요청 내용을 확인하는 동선을 위해서다.

#### 4.2 사용 서비스 `PC-076`

**우리가 이 고객사를 어느 서비스로 다루는가**를 정한다. 이 값 하나로 **편집 프로젝트·폼솔루션 서비스 관리**가 고객사를 불러온다.

| 값 | 의미 | 준비 상태 |
|---|---|---|
| **casterN (편집툴)** | 우리가 이 고객사 자료를 편집한다 → **편집 프로젝트(`PRJ-02`)의 대상**이 된다 | 사용 중 (초기값 70곳) |
| **폼솔루션** | 폼솔루션 서비스로 관리한다 | **서비스 준비중** — 개발 전이라 지정된 고객사가 없다(0곳) |
| *(아무것도 고르지 않음)* | **SDK 연동 (코드만 할당)** — 우리 서비스를 거치지 않고 코드만 받아 직접 연동한다 | 기본값 |

**탭으로 나눈다** `PC-077` — 서비스마다 딸린 설정이 다르므로 **한 번에 한 서비스만** 보여준다. 계정의 [인증 서비스 및 권한](`TKT-02` §4.2) 과 같은 결이다.

| 탭 | 켰을 때 나오는 것 |
|---|---|
| **casterN (편집툴)** | **프로젝트 상태**(§4.3) · **공통코드 사용 고객사(하위) 등록**(§4.4) — 둘 다 **편집에 딸린 설정**이라 이 탭 안에 있다 |
| **폼솔루션** `준비중` | **지정할 항목이 없다.** 선택하면 이 고객사가 **[폼솔루션 서비스 관리]** 화면에 나타난다는 안내만 나온다 |

- 탭 머리의 서비스명 앞에 **✓** 가 붙어 어느 서비스가 켜져 있는지 한눈에 보인다.
- casterN 을 끄면 그 자리에 *casterN 으로 선택하면 프로젝트 상태·공통코드 사용 고객사를 지정할 수 있습니다.* 가 나온다.
- **복수 선택**할 수 있다. 한 고객사가 편집도 하고 폼솔루션도 쓸 수 있다.
- **초기값**은 편집팀 대장에서 채웠다 — 교재(책) 행이 있는 **70곳이 casterN**. 이전 방식(SOBP 맵 좌표별 지정 `PC-057`)은 43곳뿐이라 **실제 편집 고객사 27곳이 빠져 있었다**.
- **계정의 [인증 서비스](`TKT-02`)와 다른 값이다.** 이쪽은 *우리가 이 고객사를 어떻게 다루나*, 저쪽은 *외부 고객사가 우리 서비스 어디에 로그인하나* 이다. 우리가 고객사 자료를 편집하는 데는 계정·App Key 가 필요 없다.

#### 4.4 공통코드 사용 고객사(하위) 등록 — casterN 탭 안 `PC-077`

*대표 회사 아래로 귀속 · 코드 할당 불필요*

- 사용할 공통코드를 체크하면 이 고객사가 그 **공통코드의 사용 고객사(하위)** 로 등록된다.
- 목록에 오르는 것은 **여러 고객사가 함께 쓰는 코드**뿐이다 `PC-044`. 보유 고객사가 **한 곳뿐(자기 자신·자사)** 이거나 사용 이력이 **없는 코드**는 일반 코드이므로 이 목록에 나오지 않는다.
- 안내: 이미 발급된 공통코드를 쓰므로 **코드 할당은 없고**, 편집 프로젝트·티켓 발급에서 하위 고객사로 관리된다.
- **자기 회사가 보유한 코드는 선택할 수 없다**(비활성).

#### 4.5 편집 단가 (2026 항목별)

소리펜과 필기펜은 **정산 단위가 다른 별개 묶음**이라 각각 카드로 나눠 보여준다.

| 그룹 | 성격 | 그룹 머리 표기 |
|---|---|---|
| **🔊 소리펜** | ncp2 산출 · mp3 심볼 | 항목 수 · 그 그룹의 전용 단가 개수 |
| **✍ 필기펜** | 필기 인식 · APP 연동 | 항목 수 · 그 그룹의 전용 단가 개수 |

전용 단가가 있는 그룹에만 **[기본값]** 이 나타나며 **그 그룹 항목만** 되돌린다. 상단의 **[전체 기본값]** 은 두 그룹을 모두 되돌린다.
