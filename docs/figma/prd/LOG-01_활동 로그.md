## 2. 화면 구성

### 개요

**내부 직원이 언제 무엇을 했는지**를 시간순으로 확인하는 감사(audit) 화면. **ADMIN 전용**이며 STAFF는 본문이 🔒 안내로 대체된다. **조회 전용**(기록은 각 화면에서 자동 생성) · 한국시간(KST) 기준 · 보관 최근 7일. 필터는 **월 · 직원 · 활동 종류** 칩 3줄이고 각 칩은 **재클릭 시 해제(토글)**된다.

### 기능 개요

**내부 직원이 언제 무엇을 했는지**를 시간순으로 확인하는 감사(audit) 화면. 편집·사업·재무 여러 부서가 같은 데이터를 다루므로, 코드 할당·티켓 발급·고객사 변경 같은 주요 행위의 **변경 이력 추적**이 목적이다.

| 항목 | 내용 |
|---|---|
| 권한 | **ADMIN 전용** — 메뉴 자체가 ADMIN에게만 노출된다 |
| 진입 | 좌측 메뉴 [활동 로그] · `DSH-01`의 **[전체 로그]** |
| 성격 | 조회 전용(기록은 각 화면에서 자동 생성) |
| 기록 시각 | 한국시간(KST) 기준 |

### 화면 흐름 (Flow)

```
DSH-01 [전체 로그]  또는  좌측 메뉴 [활동 로그](ADMIN)
   └─▶ LOG-01
         ├─ 월 · 직원 · 활동 종류 필터
         ├─ 월 ▸ 일 그룹으로 목록 확인
         └─ [전체 삭제] ─ 확인 ─▶ 기록 초기화 (되돌릴 수 없음)

기록은 각 화면에서 자동 생성:
   MEM-02 → 고객사 관리 · SOB-02 → 코드 할당(등록) · PRJ-01 → 프로젝트 등록
   TKT-04/03/05 → 티켓 발급 · PRJ-04 → 교재 추가 / 교재 작업 · 로그인/로그아웃
```

### 정책

| 정책 | 이 화면에서의 적용 |
|---|---|
| `PC-002` 내부 직원 전용 | 기록 대상은 **내부 직원의 행위**뿐이다. 외부 고객 열람 없음 |
| 감사 목적 | 기록은 **자동 생성**된다. 사용자가 임의로 항목을 추가·수정할 수 없다 |
| 보관 기간 | 현재 **최근 7일**만 유지(테스트 기준) — 운영 기준은 §7 협의 항목 |
| 시간 기준 | 실행 환경의 시간대와 무관하게 **한국시간(KST)** 으로 기록·표시 |

### 사용법

#### 4.1 상단 (S1)

*내부 직원 활동을 **월별 · 일자별**로 확인. 활동 종류·직원·월로 필터. · 전체 {n}건* 과 우측의 **[전체 삭제]** 로 이루어진다.

#### 4.2 필터 (S1 · S2)

필터는 **월 / 직원 / 활동 종류** 3줄이며, 각 줄 왼쪽에 라벨이 붙는다. 모두 **알약 칩**이고 기본값은 **전체**다.

> 칩은 **토글**이다 — 선택된 칩을 다시 누르면 **전체**로 돌아간다.

| 필터 | 동작 |
|---|---|
| **월** | `YYYY년 M월` 단위. 기록이 있는 달만 **최신순**으로 나온다 |
| **직원** | 활동을 기록한 직원. 칩에 **이니셜 아바타**가 함께 표시된다 |
| **활동 종류** | 아래 8종. 칩마다 **색 점**과 **건수**가 붙는다 |

> 활동 종류 칩의 건수는 **월·직원 필터만 반영**한다. 다른 종류를 골라도 이 숫자는 바뀌지 않는다.

활동 종류

| 종류 | 발생 화면 |
|---|---|
| 고객사 관리 | `MEM-02` |
| 코드 할당(등록) | `SOB-02` |
| 프로젝트 등록 | `PRJ-01` |
| 티켓 발급 | `TKT-04` · `TKT-01` · `TKT-05`(정산 등록) |
| 교재 추가 | `PRJ-04` (등록) |
| 교재 작업 | `PRJ-04` (수정) |
| 로그인 / 로그아웃 | 로그인 화면 |

필터 아래에 **조건에 맞는 활동 {n}건** 이 표시된다.

#### 4.3 목록 (S1)

**최신순**으로 정렬되고 **월 ▸ 일** 로 묶인다.

| 구역 | 표시 |
|---|---|
| 월 헤더 | **{n}년 {n}월** + `{n}건` + 가로 구분선 |
| 일자 칸 (왼쪽) | **날짜 숫자**(크게) · `YYYY-MM · {요일}요일` · `{n}건` — 오른쪽 정렬 |
| 활동 카드 (오른쪽) | 한 줄에 **시각(시:분) · 활동 종류 배지(색) · 상세 내용 · 직원(이니셜 아바타)** |

상세 내용은 각 화면에서 남긴 요약이다 (예: 고객사·S/O·서비스·발급 범위).

**행은 고정 열이다** `PC-073` — 종류 배지의 글자 수에 따라 폭이 달라져 내용 영역을 밀던 문제를 없앴다.

| 열 | 폭 | 내용 |
|---|---|---|
| 시각 | **44px** | `시:분` |
| 종류 | **92px** | 활동 종류 배지 — 글자가 길어도 폭이 고정된다 |
| 내용 | 가변 | **2줄까지** 보이고(줄간 1.7) 넘치면 말줄임. 전체 내용은 **툴팁**으로 본다 |
| 사용자 | **108px** | 이니셜 아바타 + 이름 |

#### 4.4 전체 삭제 (S4)

**[전체 삭제]** 는 기록을 모두 지우고 새로 기록한다. 되돌릴 수 없으므로 확인창을 거친다.

## 3. 상태별 변화

### LOG-01: S01 기본 · 월 ▸ 일자 그룹

*화면 정의서 상태 `S1`*

**구분** — 기본

**ADMIN 전용** — 좌측 메뉴 [활동 로그] 또는 `DSH-01`의 [전체 로그]로 진입. 구현은 **본문 최대 1000px**이며 필터가 **드롭다운이 아니라 칩 3줄**(월 · 직원 · 활동 종류)이다. 목록은 **월 헤더 + 일자 그리드 `92px 1fr`** 구조로, 왼쪽에 큰 날짜 숫자, 오른쪽에 활동 카드가 붙는다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| 월 칩 | 클릭 | 해당 월만 | 전체 + 데이터에 있는 월 · **같은 칩 재클릭 = 해제(토글)** |
| 직원 칩 | 클릭 | 해당 직원만 | 아바타(이름 첫 글자) + 이름 · 토글 |
| 활동 종류 칩 | 클릭 | S2 (필터 적용) | 색 점 + 라벨 + **현재 조건 기준 건수** · 8종 · 토글 |
| 조건 건수 | 자동 | 재계산 | **조건에 맞는 활동 {n}건** |
| [전체 삭제] | 클릭 | S4 확인창 | 빨간 테두리 버튼 · 되돌릴 수 없음 |
| 기록된 코드 할당 | 확인 | `SOB-01` | 해당 S/O 상태 |
| 기록된 티켓 | 확인 | `TKT-03` | 발급 목록 상세 |
| 기록된 고객사 변경 | 확인 | `MEM-01` → `MEM-02` | — |
| ⚠ 칩 동작 | 참고 | **PRD와 다름** | PRD-00 §4.4는 "칩 = 단일 선택(토글 아님)"이나 구현은 **재클릭 시 전체로 해제**된다 |

### LOG-01: S02 활동 종류 필터 적용

*화면 정의서 상태 `S2`*

**구분** — 필터

칩을 고르면 목록과 **조건에 맞는 활동 {n}건**이 함께 줄어든다. 각 종류 칩의 건수도 **현재 월·직원 조건 기준**으로 다시 계산된다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| [티켓 발급] 칩 | 클릭 | 해당 종류만 | 활성 칩은 파란 배경 |
| 재클릭 | 클릭 | 전체로 해제 | 토글 동작 |
| 건수 | 자동 | 재계산 | **조건에 맞는 활동 31건** |
| 발생 화면 | 참고 | `TKT-04`·`TKT-01`·`TKT-05` | — |

### LOG-01: S03 조건에 맞는 활동 없음

*화면 정의서 상태 `S3`*

**구분** — 빈 상태

PRD §5 — 조건에 맞는 기록이 없으면 카드 하나로 안내한다. **보관 기간(7일)**이 지난 기록은 목록에 나타나지 않는다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| 빈 카드 | 표시 | — | **해당 조건의 활동이 없습니다.** |
| 보조 안내 | 표시 | — | **고객사 수정·코드 할당·프로젝트 등록·티켓 발급·교재 추가/작업·로그인 시 자동 기록됩니다.** |
| 필터 되돌리기 | 클릭 | S1 | 월·직원·종류를 전체로 |
| 보관 기간 | — | **최근 7일** | ⚠ 테스트 기준 · 운영 기준 미확정 (§7) |

### LOG-01: S05 STAFF 접근 차단

*화면 정의서 상태 `S5`*

**구분** — 권한

⚠ **PRD보다 강한 제어가 구현되어 있다.** PRD §5는 "메뉴에 노출되지 않는다"까지만 적혀 있으나, 구현은 STAFF가 이 화면에 들어와도 **본문 자체를 🔒 안내로 대체**한다. 즉 `DSH-01`의 [전체 로그]로 진입해도 목록은 보이지 않는다 — PRD-00 §7의 "역할별 화면 접근 제어" 미결 항목에 대한 **실제 답**이 이미 코드에 있다.

| 본문 | 표시 | — | **접근 권한이 없습니다** / **활동 로그는 관리자(ADMIN) 계정만 열람할 수 있습니다.** |
| 좌측 메뉴 [활동 로그] | — | **노출 안 됨** | ADMIN에게만 표시 |
| `DSH-01` [전체 로그] | 클릭 | 이 화면(차단) | 목록은 보이지 않는다 |
| 필터·목록 | — | **렌더링 안 됨** | — |
