## 2. 화면 구성

### 개요

**내부 직원이 언제 무엇을 했는지**를 시간순으로 확인하는 감사(audit) 화면. **ADMIN 전용**이며 STAFF는 본문이 🔒 안내로 대체된다. **조회 전용**(기록은 각 화면에서 자동 생성) · 한국시간(KST) 기준 · 보관 최근 7일. 필터는 **월 · 직원 · 활동 종류** 칩 3줄이고 각 칩은 **재클릭 시 해제(토글)**된다.

### 상태 구성

이 화면은 **5개 상태**로 나뉜다. 구분: 기본 · 필터 · 빈 상태 · 확인창 · 권한

| 상태 | Figma 프레임 | 제목 | 구분 |
|---|---|---|---|
| `S1` | `LOG-01:S01` | 기본 · 월 ▸ 일자 그룹 | 기본 |
| `S2` | `LOG-01:S02` | 활동 종류 필터 적용 | 필터 |
| `S3` | `LOG-01:S03` | 조건에 맞는 활동 없음 | 빈 상태 |
| `S4` | `LOG-01:S04` | 전체 삭제 확인창 | 확인창 |
| `S5` | `LOG-01:S05` | STAFF 접근 차단 | 권한 |

## 3. 상태별 변화

### LOG-01: S01 기본 · 월 ▸ 일자 그룹

*화면 정의서 상태 `S1`*

**구분** — 기본

**ADMIN 전용** — 좌측 메뉴 [활동 로그] 또는 `DSH-01`의 [전체 로그]로 진입. 구현은 **본문 최대 1000px**이며 필터가 **드롭다운이 아니라 칩 3줄**(월 · 직원 · 활동 종류)이다. 목록은 **월 헤더 + 일자 그리드 `92px 1fr`** 구조로, 왼쪽에 큰 날짜 숫자, 오른쪽에 활동 카드가 붙는다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| 월 칩 | 클릭 | 해당 월만 | 전체 + 데이터에 있는 월 · **같은 칩 재클릭 = 해제(토글)** |
| 직원 칩 | 클릭 | 해당 직원만 | 아바타(이름 첫 글자) + 이름 · 토글 |
| 활동 종류 칩 | 클릭 | S2 (필터 적용) | 색 점 + 라벨 + **현재 조건 기준 건수** · 8종 · 토글 |
| 조건 건수 | 자동 | 재계산 | **조건에 맞는 활동 {n}건** |
| [전체 삭제] | 클릭 | S4 확인창 | 빨간 테두리 버튼 · 되돌릴 수 없음 |
| 기록된 코드 할당 | 확인 | `SOB-01` | 해당 S/O 상태 |
| 기록된 티켓 | 확인 | `TKT-03` | 발급 목록 상세 |
| 기록된 고객사 변경 | 확인 | `MEM-01` → `MEM-02` | — |
| ⚠ 칩 동작 | 참고 | **PRD와 다름** | PRD-00 §4.4는 "칩 = 단일 선택(토글 아님)"이나 구현은 **재클릭 시 전체로 해제**된다 |

### LOG-01: S02 활동 종류 필터 적용

*화면 정의서 상태 `S2`*

**구분** — 필터

칩을 고르면 목록과 **조건에 맞는 활동 {n}건**이 함께 줄어든다. 각 종류 칩의 건수도 **현재 월·직원 조건 기준**으로 다시 계산된다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| [티켓 발급] 칩 | 클릭 | 해당 종류만 | 활성 칩은 파란 배경 |
| 재클릭 | 클릭 | 전체로 해제 | 토글 동작 |
| 건수 | 자동 | 재계산 | **조건에 맞는 활동 31건** |
| 발생 화면 | 참고 | `TKT-04`·`TKT-01`·`TKT-05` | — |

### LOG-01: S03 조건에 맞는 활동 없음

*화면 정의서 상태 `S3`*

**구분** — 빈 상태

PRD §5 — 조건에 맞는 기록이 없으면 카드 하나로 안내한다. **보관 기간(7일)**이 지난 기록은 목록에 나타나지 않는다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| 빈 카드 | 표시 | — | **해당 조건의 활동이 없습니다.** |
| 보조 안내 | 표시 | — | **고객사 수정·코드 할당·프로젝트 등록·티켓 발급·교재 추가/작업·로그인 시 자동 기록됩니다.** |
| 필터 되돌리기 | 클릭 | S1 | 월·직원·종류를 전체로 |
| 보관 기간 | — | **최근 7일** | ⚠ 테스트 기준 · 운영 기준 미확정 (§7) |

### LOG-01: S04 전체 삭제 확인창

*화면 정의서 상태 `S4`*

**구분** — 확인창

PRD §4.3 · §5 — 브라우저 `confirm()`으로 확인한다. 되돌릴 수 없으며 기록을 모두 지우고 새로 기록한다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| 확인창 문구 | 표시 | — | **활동 로그를 전부 삭제하고 새로 기록하시겠습니까? (되돌릴 수 없습니다)** |
| [확인] | 클릭 | S3 (기록 없음) | 되돌릴 수 없음 |
| [취소] | 클릭 | S1 복귀 | — |

### LOG-01: S05 STAFF 접근 차단

*화면 정의서 상태 `S5`*

**구분** — 권한

⚠ **PRD보다 강한 제어가 구현되어 있다.** PRD §5는 "메뉴에 노출되지 않는다"까지만 적혀 있으나, 구현은 STAFF가 이 화면에 들어와도 **본문 자체를 🔒 안내로 대체**한다. 즉 `DSH-01`의 [전체 로그]로 진입해도 목록은 보이지 않는다 — PRD-00 §7의 "역할별 화면 접근 제어" 미결 항목에 대한 **실제 답**이 이미 코드에 있다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| 본문 | 표시 | — | **접근 권한이 없습니다** / **활동 로그는 관리자(ADMIN) 계정만 열람할 수 있습니다.** |
| 좌측 메뉴 [활동 로그] | — | **노출 안 됨** | ADMIN에게만 표시 |
| `DSH-01` [전체 로그] | 클릭 | 이 화면(차단) | 목록은 보이지 않는다 |
| 필터·목록 | — | **렌더링 안 됨** | — |
