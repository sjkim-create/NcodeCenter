## 2. 화면 구성

### 개요

N Key 를 발급하고 정산하는 화면이다. 「**고객사 · 발급 티켓 · 발급 상세·정산**」 3단 한 화면이며 옛 `TKT-03` N Key 관리 · `TKT-04` N Key 발급 · `TKT-05` 발급 상세·수정 · `TKT-06` N Key 불러오기를 합쳤다 `PC-149` `PC-158`. 고객사는 **고객사 관리 고객사를 불러온다** `PC-153`. **정산 집계 6칸**은 고른 고객사 · 필터 기준이고, 필터는 전체에 걸고 고객사별로 묶어 본다 `PC-150`. 화면 모양은 `TKT-01` App Key 관리와 같은 조각을 쓴다 `PC-154`.

### 기능 개요

**N Key 를 발급하고 정산하는 화면**이다. 「**고객사 | 발급 티켓 | 발급 상세·정산**」 3단 한 화면에서 발급 이력을 고객사별로 보고, 건마다 정산을 등록하고, 새 N Key 를 발급한다.

**N Key** = 물리 키. 오프라인 편집툴(Caster lite)에서 쓰며 **계정이 필요 없다**. 발급하면 티켓 파일이 zip 으로 내려받아진다. 계정과 연동되는 키는 `TKT-01` App Key 관리.

| 항목 | 내용 |
|---|---|
| 권한 | STAFF / ADMIN |
| 진입 | 좌측 메뉴 **[티켓 발급] ▸ [N Key 관리]** (`/tickets/nkey`) |
| 고객사 | **고객사 관리(`MEM-01`) 고객사를 불러온다** — 여기서 고객사를 등록하지 않는다 `PC-153` |
| 자료 | **nkey(HLP).xlsx = N Key 발급 대장**(정본, 61건) + 이 화면에서 새로 발급한 N Key |
| 정산 | 코드 라이선스 과금(미정 · 유료 · 무료 · 체험). 편집 정산(`PRJ-03`)과 별개 `P-16` |
| 짝 화면 | `TKT-01` App Key 관리 — 같은 3단 · 같은 UI 조각 `PC-154` |

### 화면 흐름 (Flow)

```
좌측 메뉴 [티켓 발급] ▸ [N Key 관리]
   └─▶ TKT-02  정산 집계 6칸 (고른 고객사 · 필터 기준) · 체험 만료 경고
               필터 바 (정산 · 출처 · 검색 · [필터 해제] · [📂 N Key 불러오기])
               ┌ 고객사(고객사 관리) ───┬ 발급 티켓 ─────────┬ 오른쪽 ─────────────────────┐
               │ [발급 고객사]/[전체]   │ 「전체」= 고객사별 묶음 │ 발급 상세 (기본정보 · 정산 탭) │
               │ 「전체」 · 고객사 · 미연결 │ [＋ N Key 발급]      │ / N Key 발급 폼               │
               └─────────────────────┴───────────────────┴─────────────────────────────┘
      티켓 카드 ─▶ 발급 상세(보기) ─ [티켓 수정] ─▶ 수정 상태 ─ [수정 저장](코드 구간을 바꿨으면 사용 가능한 구간인지 검사) / 정산 탭 [정산 저장] — 발급 기록 삭제 없음 `PC-192` `PC-201`
      [＋ N Key 발급] ─▶ 발급 폼 ─ [N Key 발급] ─▶ zip 다운로드 → 그 티켓의 정산 정보 탭 · LOG-01
      [📂 N Key 불러오기] ─▶ 파일 확인 창(조회 전용)
      발급 범위 없음 ─▶ SOB-02 에서 SOBP 할당 후 다시
```

### 정책

| 정책 | 이 화면에서의 적용 |
|---|---|
| `PC-153` 키 발급 고객사 | 고객사 = **고객사 관리 고객사**. 키 발급 화면에서 고객사를 등록하지 않는다 |
| `PC-155` 대장 = 정본 | nkey(HLP) 발급 대장은 브라우저 저장 상태와 무관하게 늘 보인다. 화면에서 고친 정산 값은 유지, **지운 대장 발급번호는 되살리지 않는다** |
| `P-15` 티켓 | **N Key = 물리 키(오프라인 · 계정 불필요)** |
| `P-05` 무겹침 | **이미 할당된 범위 안에서만** 발급. Book 이 할당 범위를 넘으면 막힌다 |
| `PC-199` 하위 고객사 두 길 · 검색 | 하위 고객사는 **상위 고객사 묶음 안에서도, 전체 목록 제자리에서도** 고를 수 있다. 하위 고객사를 바로 고르면 그 하위 고객사가 들어간 **모든 상위 고객사의 SOBP** 가 발급 범위에 나오고, 범위마다 「상위 · 상위 고객사명」 을 보인다. **고객사 검색** 중이면 가운데 발급 티켓 칸에 검색한 고객사의 발급 티켓이 나온다 — 상위 고객사에서 「사용 고객사」 로 발급한 티켓도 그 하위 고객사(고객사 관리 등록)의 티켓으로 잡힌다 |
| `PC-198` 상위 고객사 접기 · 펼치기 | 상위 고객사 줄의 **▶ 로 하위 고객사를 접고 편다**(기본 접힘, 이름 옆 「하위 n」). 하위 고객사는 **왼쪽 세로 안내선 안에 들여** 보인다(└ · 「하위」 표시 없앰). 검색 중이거나 고른 고객사가 하위면 저절로 펼친다. App Key 관리 · N Key 관리 고객사 칸은 같은 조각 · 같은 모양 — N Key 고객사 칸의 「미정 n」 표시는 없앴다 |
| `PC-197` 상 · 하위 고객사 구별 | 왼쪽 고객사 목록과 발급 폼의 고객사 선택에서 **하위 고객사를 상위(공통코드 보유) 고객사 밑에 └ 「하위」로** 보인다(App Key 관리와 같은 조각). 하위 고객사를 고르면 상위 SOBP 가 발급 범위에 나온다. [발급 고객사] 보기에도 하위 고객사가 발급받은 상위 고객사가 함께 나온다. 상위 고객사를 고른 뒤 「사용 고객사」 로 고르는 방식도 그대로 둔다 |
| `PC-195` 하위 고객사 · 구간 현황 | **하위 고객사는 상위(공통코드 보유) 고객사의 SOBP 영역으로 발급**한다 — 하위끼리는 Book · Page 가 겹치지 않게(`PC-174`). 범위를 고르면 아래에 **구간 사용 현황**(이미 발급된 구간 · 빈 Book 구간 · 입력 구간 사용 가능 여부)이 보이고, 빈 구간을 누르면 Start Book 이 그 자리로 간다 |
| `PC-174` SOBP 무겹침 | **N Key · App Key · 서비스 티켓은 SOBP 가 절대 겹칠 수 없다** — 고객사를 가리지 않고 전체 발급분과 비교해 겹치면 발급하지 않는다 |
| `P-12` 공통코드 | 공통코드 보유 고객사는 **사용 고객사를 반드시 지정**. 이력 전용 공통코드는 제외 |
| `P-16` 정산 | 과금 유형 미정 · 유료 · 무료 · 체험. 편집 정산과 별개 |
| 발급 번호 | 삭제해도 **다시 쓰지 않는다** |
| 원장 기준값 | 고객사(대장 기록명) · 발급일시 · 발급인은 바꾸지 않는다 |
| `PC-154` UI 통일 | `TKT-01` 과 같은 조각 — 한쪽만 고치지 않는다 |

| 항목 | 규칙 | 화면 |

| [발급 고객사] | N Key 가 이어진 고객사만(기본, 31곳) | S1 |

#### 4.3 정산 집계 · 필터 `PC-150`

**필터는 전체 발급분에 먼저** 걸고, 그 결과를 왼쪽 고객사 · 가운데 목록이 고객사별로 나눠 보여 준다. 필터가 걸리면 왼쪽에는 **맞는 발급이 있는 고객사만** 남고, 오른쪽 티켓이 결과에서 빠지면 첫 결과로 바뀐다(S3). 검색은 고객사명 · 대장명 · 발급 내용 · 발급인 · 번호를 찾는다.

```
유료 합계   = 고른 고객사 · 필터 결과 중 정산이 '유료' 인 티켓 금액 합(원화 — USD 는 환율 기록이 있는 것만 원화로 환산) `PC-202`
정산 미등록 = 같은 범위에서 정산이 '미정' 인 건수
체험 잔여일 = 체험 만료일 − 오늘 → 0 이상이면 D-{n}, 음수면 (만료)

예) 「전체」 + 필터 [미정] → 발급 티켓 35건 · 정산 미등록 35건 · 고객사 12/31곳
```

#### 4.5 N Key 발급 (오른쪽)

| 단계 | 내용 | 화면 |
|---|---|---|
