## 2. 화면 구성

### 개요

`TKT-01` 계정 목록에서 열리는 **등록**과 **상세·수정** 두 화면이다. **인증 서비스**(이 계정이 우리 서비스 어디에 로그인하나)는 **중복 선택**이며, 서비스마다 지정할 조건이 달라 **탭**으로 나뉜다 `PC-076` — 조건이 아래로 쌓이지 않는다. 고르는 서비스는 **CasterN · 폼솔루션 2종**이고 조건이 정의된 것은 **CasterN 뿐**이다. **아무것도 고르지 않으면 SDK 연동(코드만 할당)** 이라 App Key 만 발급한다. 고객사 관리의 **사용 서비스**(우리가 그 고객사를 어느 서비스로 다루나)와는 다른 값이며, 고객사를 고르면 그 값대로 **자동 체크**된다. App Key 는 **계정당 1개 · 인증 서비스 전체 공통** `PC-050`. 로그인 허용 판정은 PRD §4.6.

### 기능 개요

`TKT-01` 계정 목록에서 열리는 **두 화면**이다.

| 화면 | 주소 | 하는 일 |
|---|---|---|
| **계정 등록** | `/tickets/account/new` | ① 계정 정보 → ② 인증 서비스·권한 을 입력하고 **[계정 추가]** |
| **계정 상세·수정** | `/tickets/account/{email}` | ①② 를 고쳐 **[저장]**, 아래에서 이 계정의 **App Key 발급 내역**을 본다 |

| 항목 | 내용 |
|---|---|
| 권한 | STAFF / ADMIN |
| 진입 | `TKT-01` 의 **[＋ 계정 추가]** / **ID(email)·[상세]** |
| 선행 조건 | 고객사가 `MEM-01`에 등록. **App Key까지 발급하려면** `SOB-02`로 SOBP를 할당받았을 것 |

> **한 계정으로 여러 서비스를 쓸 수 있다.** 인증 서비스는 중복 선택이며, 서비스마다 지정할 조건이 다르다.
> 화면은 **번호 없는 영역 묶음**(계정 정보 · App Key 발급 · 인증 서비스·권한)으로 구성한다 `PC-052` — `TKT-05` 발급 상세와 같은 결이다.
>
> **App Key 는 계정당 1개**이고 그 계정의 **인증 서비스 전체에 공통**으로 쓰인다 `PC-050`. 발급은 선택 사항이라 계정만 등록해 두고 나중에 붙일 수 있다. 발급할 때 **Book Start · Book Volume(권수)** 를 지정한다.

### 화면 흐름 (Flow)

```
TKT-01 계정 목록
   ├─ [＋ 계정 추가] ─▶ TKT-02 등록
   │      ① 계정 정보(고객사·NAME·ID·PWD·ADDR·HOMEPAGE)
   │      ② 인증 서비스 · 권한  ─ 탭: CasterN / 폼솔루션 / SDK 연동
   │            └ CasterN 탭 ─ 사용자 권한 6종
   │      └ ③ App Key 발급(선택) ─▶ 할당 SOBP 범위 + Book Start · Book Volume + 만료일 `PC-050`
   │                                              └─(범위 없음)─▶ SOB-02 로 이동
   │      └─ [계정 추가] ─▶ TKT-01 목록에 노출 (+체크 시 App Key 동시 발급)
   │
   └─ ID(email)·[상세] ─▶ TKT-02 상세·수정
          ├─ [저장] ────────────────────▶ 반영 (App Key 는 인증 서비스와 무관하게 유지)
          ├─ ③ [App Key 발급] ─────────▶ 키 생성 → TKT-03 · LOG-01 기록 (계정당 1개)
          ├─ 발급 내역 [키 삭제] ────────▶ 해당 App Key만 삭제
          └─ [계정 삭제] ─(확인창)───────▶ 계정 + 연동 App Key 삭제 → TKT-01
```

### 정책

| 정책 | 이 화면에서의 적용 |
|---|---|
| `PC-031` 계정 화면 분리 · 권한 | 등록·수정을 목록에서 분리. 서비스별 조건을 계정마다 지정 |
| `PC-029` 고객사당 계정 수 | 제한 없음. ID(email)만 전체에서 **유일** |
| `PC-002` 내부 직원 전용 | 고객이 직접 만들지 않고 **직원이 대신 등록**한다 |
| `P-13` 인증 서비스 | 계정은 **선택한 인증 서비스에서만 로그인**된다. 여러 서비스를 고르면 **한 계정으로 각 서비스에 로그인**하며, 각 서비스는 자기 계정만 관리·인증한다. **0개면 SDK 연동** — 로그인할 우리 서비스가 없고 App Key 로 코드만 쓴다 `PC-076` |
| `PC-076` 두 서비스 값의 구분 | **인증 서비스**(이 화면 · 계정) ≠ **사용 서비스**(`MEM-02` · 고객사). 고객사를 고르면 그 고객사의 **사용 서비스대로 인증 서비스가 자동 체크**되지만, 이후 바꿀 수 있다 |
| `P-05` 무겹침 | App Key는 **이미 할당된 SOBP 범위**에만 연결된다. 좌표(S/O)는 직접 타이핑하지 않고, 그 안에서 **Book Start · Book Volume** 만 지정한다 `PC-050` |
| `PC-050` App Key 단위 | **계정당 1개** · **인증 서비스 전체 공통**. 인증 서비스를 바꿔도 키는 유지된다(옛 「연동 끊김」 규칙 폐지). 범위를 바꾸려면 **키를 삭제한 뒤 다시 발급**한다 |
| `P-02` 코드 종류 | `Code Type` 은 **직접 고른다** — PDS2 · PDS3 · PDS4 · OID `PC-064` |
| 서비스별 조건 | 서비스마다 지정할 항목이 다르다. **현재 조건이 정의된 서비스는 CasterN 뿐**이고 나머지는 준비중이다 |

### 사용법

#### 4.1 ① 계정 정보

| 항목 | 필수 | 규칙 | 수정 화면 |
|---|---|---|---|
| 회사정보(고객사) | ✔ | `MEM-01` 등록 고객사. 고르면 **ADDR이 자동 입력**된다 | **잠금**(변경 불가) |
| NAME(담당자/사용자명) | — | | 수정 가능 |
| ID (EMAIL) | ✔ | **이메일 형식** · 이미 등록된 ID는 쓸 수 없다 | **잠금**(키 연동 기준값) |
| PWD | ✔ | 비밀번호를 요청하지 않는 고객사(SDK)는 **[임의 생성]** 으로 10자리 자동 생성 | 수정 가능 |
| ADDR(주소) | — | 고객사 주소 자동 입력 · 수정 가능 | 수정 가능 |
| HOMEPAGE | — | | 수정 가능 |

#### 4.2 ② 인증 서비스 · 권한 — 탭 구조 `PC-076`

> **인증 서비스 = 외부 고객사가 우리 서비스 어디에 로그인하나.**
> 고객사 관리의 **사용 서비스**(우리가 그 고객사를 어느 서비스로 다루나 · `MEM-02` §4.2)와 **다른 값**이다.
> 우리가 고객사 자료를 편집하는 데는 계정·App Key 가 **필요 없다** — 그래서 편집 프로젝트는 이 값을 보지 않는다.

서비스마다 조건이 달라 **한 번에 한 서비스만** 보여준다. 선택한 서비스의 설정이 아래로 쌓이지 않는다.

**탭 바** — 고르는 서비스 **2종**이 항상 탭으로 있고, **인증 서비스로 선택된 것에는 선택 표시**가 붙는다. 준비되지 않은 서비스에는 **준비중** 표기가 붙는다.

| 서비스 | 선택 | 조건 |
|---|---|---|
| **CasterN** | 가능 | 사용자 권한 6종 `PC-058` |
| **폼솔루션** | 가능 | **준비중** — 조건 항목 없음 |
| *(0개 선택)* | — | **SDK 연동 (코드만 할당)** · 제목 옆에 그대로 표기된다. 오류가 아니라 **정상 상태**이며 App Key 만 발급한다 `PC-076` |

**탭 패널** — 맨 위에 그 서비스의 **사용 여부** 체크가 있고, 켜져 있을 때만 아래 조건이 나온다.

| 상황 | 패널 내용 |
|---|---|
| 인증 서비스로 선택 안 함 | *인증 서비스로 선택하면 이 서비스의 조건을 설정할 수 있습니다.* |
| CasterN 선택 | 사용자 권한 6종 |
| 폼솔루션 선택 | **준비중** — *이 서비스의 권한·설정 항목은 아직 정의되지 않았습니다. 인증 서비스 연동만 등록됩니다.* |

**CasterN 사용자 권한 6종** `PC-031` `PC-058`

| # | 권한 | 설명 |
|---|---|---|
| 1 | 프로젝트 생성 | 편집 프로젝트를 새로 만든다 |
| 2 | 심볼 편집 | 심볼(코드 영역) 편집 |
| 3 | 리소스 편집 | 음원·이미지 등 리소스 편집 |
| 4 | Ncode PDF 내보내기 | Ncode가 입혀진 PDF 출력 |
| 5 | NCP2 내보내기 | NCP2 파일 내보내기 |
| 6 | App용 패키지 내보내기 | App에서 쓰는 패키지 내보내기 |

| 동작 | 결과 |
|---|---|
| 권한 항목 선택 | 개별 on/off |
| [모두 선택] / [모두 해제] | 7개 일괄 · 선택 수에 따라 라벨이 바뀐다 |
| 선택 수 표시 | **선택 {n} / 6** |
| 권한 0개 저장 | 허용. 목록에는 **미지정**으로 표시된다 |
| CasterN 을 새로 켬 | 권한이 **7종 모두 선택**된 상태로 시작한다 |

> 인증 서비스에서 뺀 서비스의 조건은 **저장하지 않는다.**

#### 4.3 App Key 발급 — CasterN 탭 안 (선택)

App Key는 SOBP 범위를 편집툴에 연동하는 키라 **CasterN 인증 서비스에만 해당**한다. 그래서 별도 단계가 아니라 **CasterN 탭의 권한 아래**에 있다. 폼솔루션·SDK 탭에는 나오지 않는다.

| 화면 | 동작 |
|---|---|
| **등록** | **[이 계정에 App Key도 함께 발급합니다]** 체크 → 할당된 SOBP 범위 + 만료일 |
| **상세·수정** | 범위·만료일을 고르고 **[App Key 발급]**. 저장된 인증 서비스에 CasterN 이 있을 때만 발급할 수 있다 |

| 항목 | 규칙 |
|---|---|
| 할당된 SOBP 범위 | 접힘/펼침 목록에서 하나 선택. 순번 + S · O · B · P 값. 범위 없으면 `SOB-02`에서 할당 |
| 만료일(기간) | 기본 **무제한**(날짜 잠김). 체크를 풀면 달력으로 지정 |
| 미체크 시 | **계정만** 등록된다. 키는 상세에서 나중에 발급 |
| CasterN 미선택 | *App Key 는 CasterN 인증 서비스에만 발급됩니다.* 안내만 나온다 |

#### 4.4 상세 · 수정

| 영역 | 내용 |
|---|---|
| 머리말 | **계정 상세 · 수정** + ID(email) + 고객사 |
| ① 계정 정보 | ID·고객사는 잠금, 나머지는 수정 |
| ② 인증 서비스 · 권한 | 탭 구조 동일. CasterN 탭에 App Key 발급이 붙는다 |
| ③ App Key 발급 내역 | 이 계정의 키 목록 — 키 앞부분 · 코드 범위 · 인증 서비스 · 유효 기한 · 생성 일시 · **[키 삭제]**. **조회·삭제만** 하고 발급은 ② CasterN 탭에서 한다 |
| [저장] | 계정 정보·인증 서비스·조건을 함께 저장 |
| [계정 삭제] | 확인창 → 계정 + 연동 App Key 삭제 → `TKT-01` |

**App Key 발급 결과** — 발급하면 **계정 ID · PWD · App Key** 가 나오고 **[전체 복사]** 로 세 값을 한 번에 복사한다. 키는 아래 내역에 줄로 추가된다.

#### 4.5 인증 서비스 변경과 App Key 연동

인증 서비스에서 **CasterN 을 빼면** 그 계정의 App Key는 **연동이 끊긴다.** 키를 지우지는 않는다.

| 상황 | 처리 |
|---|---|
| 저장 시 | 끊기는 키가 있으면 확인을 받는다 |
| 끊긴 키 | 발급 내역에 **연동 끊김** 으로 표시된다. 로그인에는 쓸 수 없다 |
| 다시 CasterN 선택 | 연동이 되살아난다 — 키를 다시 발급할 필요가 없다 |
| 키 삭제 | 담당자가 발급 내역에서 직접 판단해 지운다 |

#### 4.6 로그인 허용 판정

```
그 서비스로 로그인 가능 = 계정의 인증 서비스에 그 서비스가 있다
                        AND 그 서비스용 App Key 가 있다

예) 계정의 인증 서비스 = CasterN · 폼솔루션
    보유 App Key = CasterN 용 1개

    CasterN  로그인 → 인증 서비스 있음 + 키 있음      → 가능
    폼솔루션  로그인 → 인증 서비스 있음 + 키 없음      → 불가
    SDK      로그인 → 인증 서비스 없음               → 불가

예) 위 계정에서 인증 서비스 CasterN 을 제거하면
    CasterN  로그인 → 인증 서비스 없음 → 불가 (키는 남아 있으나 '연동 끊김')
```

### TKT-02: S02 인증 서비스 중복 선택

*화면 정의서 상태 `S2`*

**구분** — 분기

**인증 서비스 = 외부 고객사가 우리 서비스 어디에 로그인하나** `PC-076` — 고객사 관리의 **사용 서비스**(우리가 그 고객사를 어느 서비스로 다루나)와는 다른 값이다. **중복 선택**이며, 여러 서비스를 골라도 조건이 아래로 쌓이지 않고 **탭을 바꿔야** 그 서비스의 조건이 나온다. **0개를 골라도 정상**이다 — 그때는 **SDK 연동 (코드만 할당)** 으로 App Key 만 발급한다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| 탭 바 | 조회 | ✓ CasterN · ✓ 폼솔루션 | 선택 **2 / 2** |
| 탭 클릭 | 클릭 | 해당 서비스 조건 | 한 번에 한 서비스만 보인다 |
| 0개 선택 | — | **SDK 연동 (코드만 할당)** | 제목 옆에 그대로 표기된다 — 오류가 아니라 정상 상태 `PC-076` |
| 로그인 범위 | — | — | **한 계정으로 각 서비스에 로그인**한다 |
| 선택 안 한 서비스 | — | 조건 저장 안 함 | 뺀 서비스의 조건은 버린다 |

### TKT-02: S09 상세 — App Key 발급 완료

*화면 정의서 상태 `S9`*

**구분** — 분기

범위를 고르고 **[App Key 발급]**(범위 선택 전에는 비활성) 하면 결과에 **계정 ID · PWD · App Key** 가 나오고 **[전체 복사]** 로 세 값을 한 번에 복사한다. 키는 아래 내역에 줄로 추가되고 `TKT-03`·`LOG-01` 에 자동 기록된다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| [App Key 발급] | 클릭 | 키 생성 | 범위 선택 전에는 **비활성** |
| Book Start · Volume | 입력 | 발급 범위 확정 | **B{Start}~{Start+Volume−1}** 로 발급된다 `PC-050` |
| 발급 결과 | 표시 | — | 계정 ID · PWD · App Key |
| [전체 복사] | 클릭 | 복사 | **계정·키 정보가 복사되었습니다.** |
| 재발급 | — | **불가** | 계정당 1개 — 범위를 바꾸려면 **키를 삭제한 뒤** 다시 발급한다 |
| 자동 기록 | — | `TKT-03` · `LOG-01` | 발급 이력·활동 로그 |

### TKT-02: S10 이미 발급된 계정 — 재발급 차단

*화면 정의서 상태 `S10`*

**구분** — 차단

App Key 는 **계정당 1개**다 `PC-050`. 이미 키가 있으면 ③ 단계에 발급 폼 대신 **안내**가 나오고, 범위를 바꾸려면 **키를 삭제한 뒤** 다시 발급한다. (인증 서비스를 빼도 키 연동은 끊기지 않는다 — 「연동 끊김」 처리는 폐지)

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| ③ App Key | 표시 | **안내** | **이 계정에는 이미 App Key 가 발급돼 있습니다 — 계정당 1개입니다.** |
| 발급 폼 | — | **표시 안 함** | 범위·Book·만료 입력이 나오지 않는다 |
| [키 삭제] | 클릭 | 발급 폼 복귀 | 삭제 후 새 범위로 다시 발급한다 |
| 사용처 변경 | 저장 | 키 유지 | 키는 인증 서비스 전체 공통이라 영향 없음 |
