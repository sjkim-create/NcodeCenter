## 2. 화면 구성

### 개요

`TKT-01` 계정 목록에서 열리는 **등록**과 **상세·수정** 두 화면이다. 사용처(연동 서비스)는 **중복 선택**이며, 서비스마다 지정할 조건이 달라 **탭**으로 나뉜다 — 조건이 아래로 쌓이지 않는다. 조건이 정의된 서비스는 **CasterN 뿐**이고 나머지는 준비중이다. **App Key 발급은 CasterN 사용처 전용**이라 CasterN 탭 안에 있다. 사용처에서 CasterN 을 빼면 App Key는 **연동이 끊긴다**(삭제되지 않는다). 로그인 허용 판정은 PRD §4.6.

## 3. 상태별 변화

### TKT-02: S01 계정 등록 — 진입

*화면 정의서 상태 `S1`*

**구분** — 기본

등록은 **2단계**다 — ① 계정 정보 → ② 사용처·권한. ⚠ 옛 ③ App Key 단계는 폐기되어 **CasterN 탭 안**으로 들어갔다. 사용처 기본값은 **CasterN** 이고 권한은 **7종 모두 선택**된 상태로 시작한다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| ① 회사정보 | 선택 | ADDR 자동 입력 | `MEM-01` 등록 고객사 |
| ① ID (EMAIL) | 입력 | 이메일 형식 | 전체에서 **유일** |
| ① PWD [임의 생성] | 클릭 | 10자리 자동 | 비밀번호 미요청 고객사 |
| ② 탭 바 | 조회 | 서비스 3종 | 선택된 서비스에 **✓** · 준비중 표기 |
| ② CasterN 권한 | 기본 | **7 / 7** | 모두 선택된 상태 |
| [계정 추가] | 클릭 | `TKT-01` | 목록으로 이동 |
| [목록] · [취소] | 클릭 | `TKT-01` | 계정 목록으로 돌아간다 |
| 사이드바 [Key 관리] | 클릭 | `TKT-03` | 발급·정산 목록 |

### TKT-02: S02 사용처 중복 선택

*화면 정의서 상태 `S2`*

**구분** — 분기

사용처는 **중복 선택**이다. 여러 서비스를 골라도 조건이 아래로 쌓이지 않고 **탭을 바꿔야** 그 서비스의 조건이 나온다. 탭 바에서 선택된 서비스에 **✓** 가 붙어 어느 사용처가 켜져 있는지 한눈에 보인다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| 탭 바 | 조회 | ✓ CasterN · ✓ 폼솔루션 · ○ SDK | 선택 **2 / 3** |
| 탭 클릭 | 클릭 | 해당 서비스 조건 | 한 번에 한 서비스만 보인다 |
| 로그인 범위 | — | — | **한 계정으로 각 서비스에 로그인**한다 |
| 선택 안 한 서비스 | — | 조건 저장 안 함 | 사용처에서 뺀 서비스의 조건은 버린다 |

### TKT-02: S03 CasterN 탭 — 권한 개별 선택

*화면 정의서 상태 `S3`*

**구분** — 분기

권한은 개별로 켜고 끈다. 선택 수가 **선택 {n} / 7** 로 표시되고 버튼 라벨이 **[모두 선택]** ⇄ **[모두 해제]** 로 바뀐다. 권한 0개로 저장해도 되며 목록에는 **미지정**으로 나온다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| 권한 항목 | 클릭 | 개별 on/off | — |
| 선택 수 | 표시 | **선택 3 / 7** | — |
| [모두 선택] | 클릭 | 7개 일괄 | 전부 선택되면 **[모두 해제]** 로 바뀐다 |
| 권한 0개 | 저장 | 허용 | `TKT-01` 목록에 **미지정** |

### TKT-02: S04 폼솔루션 · SDK 탭 — 준비중

*화면 정의서 상태 `S4`*

**구분** — 변형

조건이 정의된 서비스는 **CasterN 뿐**이다. 나머지 탭은 사용처로 선택해도 **준비중** 안내만 나오고 지정할 항목이 없다. 사용처로 선택하지 않은 탭은 **사용처로 선택하면 이 서비스의 조건을 설정할 수 있습니다.** 로 비어 있다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| 폼솔루션 탭 | 조회 | **준비중** | **이 서비스의 권한·설정 항목은 아직 정의되지 않았습니다. 사용처 연동만 등록됩니다.** |
| SDK 탭 | 조회 | 동일 | 준비중 |
| 미선택 탭 | 조회 | — | **사용처로 선택하면 이 서비스의 조건을 설정할 수 있습니다.** |
| App Key | 표시 | **없음** | CasterN 탭에만 있다 |

### TKT-02: S05 App Key 함께 발급 — CasterN 탭

*화면 정의서 상태 `S5`*

**구분** — 분기

App Key 는 SOBP 범위를 편집툴에 연동하는 키라 **CasterN 사용처 전용**이다. 그래서 별도 단계가 아니라 **CasterN 탭의 권한 아래**에 있다. 체크하면 할당된 SOBP 범위와 만료일이 열린다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| [App Key도 함께 발급] | 체크 | 범위·만료 표시 | 선택 사항 |
| 할당된 SOBP 범위 | 선택 | 순번 + S·O·B·P | **직접 입력하지 않는다** |
| 범위 없음 | — | `SOB-02` | 코드 할당 후 재시도 |
| 만료일 | 기본 | **무제한** | 체크를 풀면 달력으로 지정 |
| 미체크 | 저장 | 계정만 등록 | 키는 상세에서 나중에 발급 |

### TKT-02: S06 CasterN 미선택 — App Key 안내

*화면 정의서 상태 `S6`*

**구분** — 차단

사용처에서 CasterN 을 빼면 App Key 발급 자리에 **안내만** 남는다. 폼솔루션·SDK 탭에는 App Key 항목 자체가 나오지 않는다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| CasterN 탭 | 조회 | 사용 여부 해제됨 | 조건이 잠긴다 |
| App Key | 표시 | — | **App Key 는 CasterN 사용처에만 발급됩니다.** |
| 저장 | — | 가능 | 계정은 폼솔루션 사용처로 등록된다 |

### TKT-02: S07 등록 검증 실패

*화면 정의서 상태 `S7`*

**구분** — 검증

검사는 **회사 → ID 형식 → 비밀번호 → 사용처 → 범위 → ID 중복** 순서로 진행하고 하나라도 걸리면 그 자리에서 멈춘다. 메시지는 버튼 아래 한 줄로 나온다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| ① 회사 미선택 | 검증 | 중단 | **회사(고객사)를 선택하세요.** |
| ② ID 형식 | 검증 | 중단 | **계정 ID는 이메일 형식이어야 합니다.** |
| ③ 비밀번호 | 검증 | 중단 | **비밀번호가 필요합니다. (요청 없으면 [임의 생성])** |
| ④ 사용처 | 검증 | 중단 | **사용처(연동 서비스)를 1개 이상 선택하세요.** |
| ⑤ 범위 | 검증 | 중단 | **할당된 SOBP 범위를 선택하세요.** — App Key 함께 발급일 때만 |
| ⑥ ID 중복 | 검증 | 중단 | **이미 등록된 ID(email)입니다.** |

### TKT-02: S08 계정 상세 · 수정

*화면 정의서 상태 `S8`*

**구분** — 기본

ID(email)·고객사는 **잠금**이고 나머지를 고쳐 **[저장]** 한다. ②는 등록과 같은 탭 구조이며, 아래 **③ App Key 발급 내역**은 **조회·삭제만** 한다 — 발급은 ② CasterN 탭에서 한다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| ① ID · 고객사 | 표시 | **잠금** | 키 연동 기준값 |
| ② 탭 구조 | 조회 | 등록과 동일 | CasterN 탭에 App Key 발급 |
| ③ 발급 내역 | 조회 | — | 키 앞부분 · 코드 범위 · 사용처 · 유효 기한 · 생성 일시 · [키 삭제] |
| [저장] | 클릭 | 반영 | **계정 정보가 저장되었습니다.** |
| [계정 삭제] | 클릭 | 확인창 | S11 |
| [목록] · [취소] | 클릭 | `TKT-01` | 계정 목록으로 돌아간다 |
| 사이드바 [Key 관리] | 클릭 | `TKT-03` | 발급·정산 목록 |

### TKT-02: S09 상세 — App Key 발급 완료

*화면 정의서 상태 `S9`*

**구분** — 분기

범위를 고르고 **[App Key 발급]**(범위 선택 전에는 비활성) 하면 결과에 **계정 ID · PWD · App Key** 가 나오고 **[전체 복사]** 로 세 값을 한 번에 복사한다. 키는 아래 내역에 줄로 추가되고 `TKT-03`·`LOG-01` 에 자동 기록된다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| [App Key 발급] | 클릭 | 키 생성 | 범위 선택 전에는 **비활성** |
| 발급 결과 | 표시 | — | 계정 ID · PWD · App Key |
| [전체 복사] | 클릭 | 복사 | **계정·키 정보가 복사되었습니다.** |
| 자동 기록 | — | `TKT-03` · `LOG-01` | 발급 이력·활동 로그 |

### TKT-02: S10 사용처에서 CasterN 제거 — 연동 끊김

*화면 정의서 상태 `S10`*

**구분** — 차단

사용처에서 CasterN 을 빼고 저장하면 그 계정의 App Key는 **연동이 끊긴다**. **키를 지우지는 않는다.** 저장 전에 확인을 받고, 발급 내역에는 **연동 끊김** 표시가 붙는다. 다시 CasterN 을 선택하면 **연동이 되살아난다**.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| [저장] | 클릭 | 확인창 | **사용처에서 빠지는 서비스로 발급된 App Key 2개는 연동이 끊깁니다. 저장할까요?** |
| 끊긴 키 | 표시 | **연동 끊김** | 발급 내역에 표시 · 로그인 불가 |
| 키 삭제 | — | 자동 삭제 안 함 | 담당자가 내역에서 직접 판단 |
| CasterN 재선택 | 저장 | 연동 복구 | 키를 다시 발급할 필요가 없다 |

### TKT-02: S11 계정 삭제 확인

**구분** — 차단
