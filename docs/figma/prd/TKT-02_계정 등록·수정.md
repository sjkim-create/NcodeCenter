## 2. 화면 구성

### 개요

`TKT-01` 계정 목록에서 열리는 **등록**과 **상세·수정** 두 화면이다. 사용처(연동 서비스)는 **중복 선택**이며, 서비스마다 지정할 조건이 달라 **탭**으로 나뉜다 — 조건이 아래로 쌓이지 않는다. 조건이 정의된 서비스는 **CasterN 뿐**이고 나머지는 준비중이다. **App Key 발급은 CasterN 사용처 전용**이라 CasterN 탭 안에 있다. 사용처에서 CasterN 을 빼면 App Key는 **연동이 끊긴다**(삭제되지 않는다). 로그인 허용 판정은 PRD §4.6.

### 기능 개요

`TKT-01` 계정 목록에서 열리는 **두 화면**이다.

| 화면 | 주소 | 하는 일 |
|---|---|---|
| **계정 등록** | `/tickets/account/new` | ① 계정 정보 → ② 사용처·권한 을 입력하고 **[계정 추가]** |
| **계정 상세·수정** | `/tickets/account/{email}` | ①② 를 고쳐 **[저장]**, 아래에서 이 계정의 **App Key 발급 내역**을 본다 |

| 항목 | 내용 |
|---|---|
| 권한 | STAFF / ADMIN |
| 진입 | `TKT-01` 의 **[＋ 계정 추가]** / **ID(email)·[상세]** |
| 선행 조건 | 고객사가 `MEM-01`에 등록. **App Key까지 발급하려면** `SOB-02`로 SOBP를 할당받았을 것 |

> **한 계정으로 여러 서비스를 쓸 수 있다.** 사용처는 중복 선택이며, 서비스마다 지정할 조건이 다르다.
> 화면은 **번호 없는 영역 묶음**(계정 정보 · App Key 발급 · 사용처·권한)으로 구성한다 `PC-052` — `TKT-05` 발급 상세와 같은 결이다.
>
> **App Key 는 계정당 1개**이고 그 계정의 **사용처 전체(CasterN·폼솔루션·SDK)에 공통**으로 쓰인다 `PC-050`. 발급은 선택 사항이라 계정만 등록해 두고 나중에 붙일 수 있다. 발급할 때 **Book Start · Book Volume(권수)** 를 지정한다.

### 화면 흐름 (Flow)

```
TKT-01 계정 목록
   ├─ [＋ 계정 추가] ─▶ TKT-02 등록
   │      ① 계정 정보(고객사·NAME·ID·PWD·ADDR·HOMEPAGE)
   │      ② 사용처 · 권한  ─ 탭: CasterN / 폼솔루션 / SDK 연동
   │            └ CasterN 탭 ─ 사용자 권한 7종
   │      └ ③ App Key 발급(선택) ─▶ 할당 SOBP 범위 + Book Start · Book Volume + 만료일 `PC-050`
   │                                              └─(범위 없음)─▶ SOB-02 로 이동
   │      └─ [계정 추가] ─▶ TKT-01 목록에 노출 (+체크 시 App Key 동시 발급)
   │
   └─ ID(email)·[상세] ─▶ TKT-02 상세·수정
          ├─ [저장] ────────────────────▶ 반영 (App Key 는 사용처와 무관하게 유지)
          ├─ ③ [App Key 발급] ─────────▶ 키 생성 → TKT-03 · LOG-01 기록 (계정당 1개)
          ├─ 발급 내역 [키 삭제] ────────▶ 해당 App Key만 삭제
          └─ [계정 삭제] ─(확인창)───────▶ 계정 + 연동 App Key 삭제 → TKT-01
```

#### 4.2 ② 사용처 · 권한 — 탭 구조

서비스마다 조건이 달라 **한 번에 한 서비스만** 보여준다. 선택한 서비스의 설정이 아래로 쌓이지 않는다.

**탭 바** — 서비스 3종이 항상 탭으로 있고, **사용처로 선택된 서비스에는 선택 표시**가 붙는다. 준비되지 않은 서비스에는 **준비중** 표기가 붙는다.

| 서비스 | 사용처 선택 | 조건 |
|---|---|---|
| **CasterN** | 가능 (기본 선택) | 사용자 권한 7종 |
| **폼솔루션** | 가능 | **준비중** — 조건 항목 없음 |
| **SDK 연동** | 가능 | **준비중** — 조건 항목 없음 |

**탭 패널** — 맨 위에 그 서비스의 **사용 여부** 체크가 있고, 켜져 있을 때만 아래 조건이 나온다.

| 상황 | 패널 내용 |
|---|---|
| 사용처로 선택 안 함 | *사용처로 선택하면 이 서비스의 조건을 설정할 수 있습니다.* |
| CasterN 선택 | 사용자 권한 7종 + App Key 발급 |
| 폼솔루션·SDK 선택 | **준비중** — *이 서비스의 권한·설정 항목은 아직 정의되지 않았습니다. 사용처 연동만 등록됩니다.* |

**CasterN 사용자 권한 7종** `PC-031`

| # | 권한 | 설명 |
|---|---|---|
| 1 | 프로젝트 생성 | 편집 프로젝트를 새로 만든다 |
| 2 | 심볼 편집 | 심볼(코드 영역) 편집 |
| 3 | 리소스 편집 | 음원·이미지 등 리소스 편집 |
| 4 | Ncode PDF 내보내기 | Ncode가 입혀진 PDF 출력 |
| 5 | NCP2 내보내기 | NCP2 파일 내보내기 |
| 6 | App용 패키지 내보내기 | App에서 쓰는 패키지 내보내기 |
| 7 | App 페이지 설정 | App 페이지 구성·설정 |

| 동작 | 결과 |
|---|---|
| 권한 항목 선택 | 개별 on/off |
| [모두 선택] / [모두 해제] | 7개 일괄 · 선택 수에 따라 라벨이 바뀐다 |
| 선택 수 표시 | **선택 {n} / 7** |
| 권한 0개 저장 | 허용. 목록에는 **미지정**으로 표시된다 |
| CasterN 을 새로 켬 | 권한이 **7종 모두 선택**된 상태로 시작한다 |

> 사용처에서 뺀 서비스의 조건은 **저장하지 않는다.**

#### 4.3 App Key 발급 — CasterN 탭 안 (선택)

App Key는 SOBP 범위를 편집툴에 연동하는 키라 **CasterN 사용처에만 해당**한다. 그래서 별도 단계가 아니라 **CasterN 탭의 권한 아래**에 있다. 폼솔루션·SDK 탭에는 나오지 않는다.

| 화면 | 동작 |
|---|---|
| **등록** | **[이 계정에 App Key도 함께 발급합니다]** 체크 → 할당된 SOBP 범위 + 만료일 |
| **상세·수정** | 범위·만료일을 고르고 **[App Key 발급]**. 저장된 사용처에 CasterN 이 있을 때만 발급할 수 있다 |

| 항목 | 규칙 |
|---|---|
| 할당된 SOBP 범위 | 접힘/펼침 목록에서 하나 선택. 순번 + S · O · B · P 값. 범위 없으면 `SOB-02`에서 할당 |
| 만료일(기간) | 기본 **무제한**(날짜 잠김). 체크를 풀면 달력으로 지정 |
| 미체크 시 | **계정만** 등록된다. 키는 상세에서 나중에 발급 |
| CasterN 미선택 | *App Key 는 CasterN 사용처에만 발급됩니다.* 안내만 나온다 |

#### 4.4 상세 · 수정

| 영역 | 내용 |
|---|---|
| 머리말 | **계정 상세 · 수정** + ID(email) + 고객사 |
| ① 계정 정보 | ID·고객사는 잠금, 나머지는 수정 |
| ② 사용처 · 권한 | 탭 구조 동일. CasterN 탭에 App Key 발급이 붙는다 |
| ③ App Key 발급 내역 | 이 계정의 키 목록 — 키 앞부분 · 코드 범위 · 사용처 · 유효 기한 · 생성 일시 · **[키 삭제]**. **조회·삭제만** 하고 발급은 ② CasterN 탭에서 한다 |
| [저장] | 계정 정보·사용처·조건을 함께 저장 |
| [계정 삭제] | 확인창 → 계정 + 연동 App Key 삭제 → `TKT-01` |

**App Key 발급 결과** — 발급하면 **계정 ID · PWD · App Key** 가 나오고 **[전체 복사]** 로 세 값을 한 번에 복사한다. 키는 아래 내역에 줄로 추가된다.

#### 4.5 사용처 변경과 App Key 연동

사용처에서 **CasterN 을 빼면** 그 계정의 App Key는 **연동이 끊긴다.** 키를 지우지는 않는다.

| 상황 | 처리 |
|---|---|
| 저장 시 | 끊기는 키가 있으면 확인을 받는다 |
| 끊긴 키 | 발급 내역에 **연동 끊김** 으로 표시된다. 로그인에는 쓸 수 없다 |
| 다시 CasterN 선택 | 연동이 되살아난다 — 키를 다시 발급할 필요가 없다 |
| 키 삭제 | 담당자가 발급 내역에서 직접 판단해 지운다 |

#### 4.6 로그인 허용 판정

```
그 서비스로 로그인 가능 = 계정 사용처에 그 서비스가 있다
                        AND 그 서비스용 App Key 가 있다

예) 계정 사용처 = CasterN · 폼솔루션
    보유 App Key = CasterN 용 1개

    CasterN  로그인 → 사용처 있음 + 키 있음      → 가능
    폼솔루션  로그인 → 사용처 있음 + 키 없음      → 불가
    SDK      로그인 → 사용처 없음               → 불가

예) 위 계정에서 사용처 CasterN 을 제거하면
    CasterN  로그인 → 사용처 없음 → 불가 (키는 남아 있으나 '연동 끊김')
```

## 3. 상태별 변화

### TKT-02: S01 계정 등록 — 진입

*화면 정의서 상태 `S1`*

**구분** — 기본

등록은 **2단계**다 — ① 계정 정보 → ② 사용처·권한. ⚠ 옛 ③ App Key 단계는 폐기되어 **CasterN 탭 안**으로 들어갔다. 사용처 기본값은 **CasterN** 이고 권한은 **7종 모두 선택**된 상태로 시작한다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| ① 회사정보 | 선택 | ADDR 자동 입력 | `MEM-01` 등록 고객사 |
| ① ID (EMAIL) | 입력 | 이메일 형식 | 전체에서 **유일** |
| ① PWD [임의 생성] | 클릭 | 10자리 자동 | 비밀번호 미요청 고객사 |
| ② 탭 바 | 조회 | 서비스 3종 | 선택된 서비스에 **✓** · 준비중 표기 |
| ② CasterN 권한 | 기본 | **7 / 7** | 모두 선택된 상태 |
| [계정 추가] | 클릭 | `TKT-01` | 목록으로 이동 |
| [목록] · [취소] | 클릭 | `TKT-01` | 계정 목록으로 돌아간다 |
| 사이드바 [Key 관리] | 클릭 | `TKT-03` | 발급·정산 목록 |

### TKT-02: S02 사용처 중복 선택

*화면 정의서 상태 `S2`*

**구분** — 분기

사용처는 **중복 선택**이다. 여러 서비스를 골라도 조건이 아래로 쌓이지 않고 **탭을 바꿔야** 그 서비스의 조건이 나온다. 탭 바에서 선택된 서비스에 **✓** 가 붙어 어느 사용처가 켜져 있는지 한눈에 보인다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| 탭 바 | 조회 | ✓ CasterN · ✓ 폼솔루션 · ○ SDK | 선택 **2 / 3** |
| 탭 클릭 | 클릭 | 해당 서비스 조건 | 한 번에 한 서비스만 보인다 |
| 로그인 범위 | — | — | **한 계정으로 각 서비스에 로그인**한다 |
| 선택 안 한 서비스 | — | 조건 저장 안 함 | 사용처에서 뺀 서비스의 조건은 버린다 |

### TKT-02: S03 CasterN 탭 — 권한 개별 선택

*화면 정의서 상태 `S3`*

**구분** — 분기

권한은 개별로 켜고 끈다. 선택 수가 **선택 {n} / 7** 로 표시되고 버튼 라벨이 **[모두 선택]** ⇄ **[모두 해제]** 로 바뀐다. 권한 0개로 저장해도 되며 목록에는 **미지정**으로 나온다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| 권한 항목 | 클릭 | 개별 on/off | — |
| 선택 수 | 표시 | **선택 3 / 7** | — |
| [모두 선택] | 클릭 | 7개 일괄 | 전부 선택되면 **[모두 해제]** 로 바뀐다 |
| 권한 0개 | 저장 | 허용 | `TKT-01` 목록에 **미지정** |

### TKT-02: S04 폼솔루션 · SDK 탭 — 준비중

*화면 정의서 상태 `S4`*

**구분** — 변형

조건이 정의된 서비스는 **CasterN 뿐**이다. 나머지 탭은 사용처로 선택해도 **준비중** 안내만 나오고 지정할 항목이 없다. 사용처로 선택하지 않은 탭은 **사용처로 선택하면 이 서비스의 조건을 설정할 수 있습니다.** 로 비어 있다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| 폼솔루션 탭 | 조회 | **준비중** | **이 서비스의 권한·설정 항목은 아직 정의되지 않았습니다. 사용처 연동만 등록됩니다.** |
| SDK 탭 | 조회 | 동일 | 준비중 |
| 미선택 탭 | 조회 | — | **사용처로 선택하면 이 서비스의 조건을 설정할 수 있습니다.** |
| App Key | 표시 | **없음** | CasterN 탭에만 있다 |

### TKT-02: S05 ③ App Key 함께 발급

*화면 정의서 상태 `S5`*

**구분** — 분기

App Key 는 그 계정의 **사용처 전체에 공통**으로 쓰이고 **계정당 1개**다 `PC-050`. 그래서 탭 안이 아니라 **③ 단계**로 따로 둔다. 체크하면 할당된 SOBP 범위와 **Book Start · Book Volume(권수)** · 만료일이 열린다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| [App Key도 함께 발급] | 체크 | 범위·Book·만료 표시 | 선택 사항 |
| 할당된 SOBP 범위 | 선택 | 순번 + S·O·B·P | **직접 입력하지 않는다** |
| Book Start | 입력 | 숫자 | 할당 범위 안에서만 `PC-050` |
| Book Volume (권수) | 입력 | 숫자 | 발급 권수 — **Book End = Start + Volume − 1** 로 계산해 아래에 보여 준다 |
| 범위 없음 | — | `SOB-02` | 코드 할당 후 재시도 |
| 만료일 | 기본 | **무제한** | 체크를 풀면 달력으로 지정 |
| 미체크 | 저장 | 계정만 등록 | 키는 상세에서 나중에 발급 |

### TKT-02: S06 사용처를 바꿔도 App Key 는 그대로

*화면 정의서 상태 `S6`*

**구분** — 변형

App Key 는 **사용처 전체 공통**이라 사용처 구성을 바꿔도 키는 영향을 받지 않는다 `PC-050`. 예전의 「CasterN 전용 · 연동 끊김」 처리는 **폐지**했다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| 사용처 구성 | 변경 | App Key 영향 없음 | 키는 계정 단위로 붙는다 |
| ③ App Key | 표시 | **항상 노출** | 탭과 무관한 단계다 |
| 저장 | — | 가능 | 계정은 고른 사용처로 등록된다 |

### TKT-02: S07 등록 검증 실패

*화면 정의서 상태 `S7`*

**구분** — 검증

검사는 **회사 → ID 형식 → 비밀번호 → 사용처 → 범위 → ID 중복** 순서로 진행하고 하나라도 걸리면 그 자리에서 멈춘다. 메시지는 버튼 아래 한 줄로 나온다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |

| ③ 비밀번호 | 검증 | 중단 | **비밀번호가 필요합니다. (요청 없으면 [임의 생성])** |

### TKT-02: S08 계정 상세 · 수정

*화면 정의서 상태 `S8`*

**구분** — 기본

ID(email)·고객사는 **잠금**이고 나머지를 고쳐 **[저장]** 한다. ②는 등록과 같은 탭 구조이며, 아래 **③ App Key 발급 내역**은 **조회·삭제만** 한다 — 발급은 ② CasterN 탭에서 한다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| ① ID · 고객사 | 표시 | **잠금** | 키 연동 기준값 |
| ② 탭 구조 | 조회 | 등록과 동일 | CasterN 탭에 App Key 발급 |
| ③ 발급 내역 | 조회 | — | 키 앞부분 · 코드 범위 · 사용처 · 유효 기한 · 생성 일시 · [키 삭제] |

### TKT-02: S09 상세 — App Key 발급 완료

*화면 정의서 상태 `S9`*

**구분** — 분기

범위를 고르고 **[App Key 발급]**(범위 선택 전에는 비활성) 하면 결과에 **계정 ID · PWD · App Key** 가 나오고 **[전체 복사]** 로 세 값을 한 번에 복사한다. 키는 아래 내역에 줄로 추가되고 `TKT-03`·`LOG-01` 에 자동 기록된다.

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| [App Key 발급] | 클릭 | 키 생성 | 범위 선택 전에는 **비활성** |
| Book Start · Volume | 입력 | 발급 범위 확정 | **B{Start}~{Start+Volume−1}** 로 발급된다 `PC-050` |
| 발급 결과 | 표시 | — | 계정 ID · PWD · App Key |
| [전체 복사] | 클릭 | 복사 | **계정·키 정보가 복사되었습니다.** |
| 재발급 | — | **불가** | 계정당 1개 — 범위를 바꾸려면 **키를 삭제한 뒤** 다시 발급한다 |
| 자동 기록 | — | `TKT-03` · `LOG-01` | 발급 이력·활동 로그 |

### TKT-02: S10 이미 발급된 계정 — 재발급 차단

*화면 정의서 상태 `S10`*

**구분** — 차단

App Key 는 **계정당 1개**다 `PC-050`. 이미 키가 있으면 ③ 단계에 발급 폼 대신 **안내**가 나오고, 범위를 바꾸려면 **키를 삭제한 뒤** 다시 발급한다. (사용처를 빼도 키 연동은 끊기지 않는다 — 「연동 끊김」 처리는 폐지)

| 요소 | 액션 | 결과 · 이동 | 메시지 · 비고 |
|---|---|---|---|
| ③ App Key | 표시 | **안내** | **이 계정에는 이미 App Key 가 발급돼 있습니다 — 계정당 1개입니다.** |
| 발급 폼 | — | **표시 안 함** | 범위·Book·만료 입력이 나오지 않는다 |
| [키 삭제] | 클릭 | 발급 폼 복귀 | 삭제 후 새 범위로 다시 발급한다 |
| 사용처 변경 | 저장 | 키 유지 | 키는 사용처 전체 공통이라 영향 없음 |
