# NcodeCenter — 동작 흐름 (Flow)

> **한 장으로 보는 동작 지도.** ①에서 전체를 보고, ②~⑥에서 각 단계를 펼친다.
> 화면 목록·경로는 [IA](NcodeCenter-IA.md), 화면별 명세는 [PRD](prd/README.md), 규칙 근거는 [운영 정책](NcodeCenter-Operations-Policy.md).
> 정본: 메뉴 = `web/lib/menu.ts` · 라우트 = `web/app/**`.
> **반영 기준: 운영 정책 `PC-374` 까지 (2026-11-26)** — 기능 · 정책이 바뀌면 이 문서도 함께 점검한다 `PC-372`.
>
> **Figma 로 옮길 때** — [`NcodeCenter-Flow.html`](NcodeCenter-Flow.html) 을 브라우저로 열고 그림마다 **[SVG 복사]** → Figma 에서 `Ctrl+V`.
> 벡터 그룹으로 들어오고 글자는 편집 가능한 텍스트 레이어다. **이 MD 를 고쳤으면 `python docs/screens/_gen/mkflow.py` 를 다시 돌린다.**

```mermaid

    subgraph NC["NcodeCenter — 내부 직원 전용 (Admin / Staff)"]
        direction TB
        S1["① 고객사 등록<br/>MEM-01 목록 · MEM-02 등록·수정<br/>편집 단가 · 서비스 계정 · 공통코드 · 확장 언어"]
        SUB["공통코드 사용 고객사 (하위)<br/>코드 할당 없이 상위 고객사 코드를 함께 쓴다"]
        S2["② 코드 할당<br/>SOB-01 지도 → SOB-02 직접 코드 할당<br/>Section·Owner 를 한 고객사가 통째로 점유<br/>확장 Owner 는 확장 언어 그룹에 연결"]
```

> **③ 과 ④ 는 배타가 아니다.** 같은 고객사 코드라도 우리가 편집해 주면서(계정 불필요) 동시에 그 고객사에 키를 발급할 수 있다. 갈라지는 건 **누가 그 코드를 다루느냐**다.

**읽는 법 4가지**

| 원칙 | 뜻 |
|---|---|
| 내부 직원만 조작한다 | 고객이 직접 등록·요청하지 않는다. 직원이 대신 등록·할당한다 `PC-002` |
| 주인은 ②에서만 정해진다 | 코드의 소유 고객사가 확정되는 유일한 지점이 `SOB-02` 다 |
| 성격은 ①에서, 종류는 ③에서 | 사용 서비스 = 서비스 계정의 서비스(`MEM-02`) — **계정 권한일 뿐 편집 대상과는 무관**하다 `PC-138` `PC-187` · 코드 종류 = 발급 시점 지정 `PC-076` `PC-074` |
| 하위 고객사는 할당하지 않는다 | 공통코드를 함께 쓰는 고객사는 `MEM-02` 에서 **하위로 등록**만 한다 — 코드는 상위 고객사 것을 쓰고, 편집 프로젝트 · 티켓에서 하위 고객사로 다룬다 `PC-077` |
| 확장 언어는 그룹으로 | 고객사당 **기본 코드 1개**로 **확장 언어 그룹**(`MEM-02` §4.12)을 만들고 지정한 Owner 만 확장 — 나머지는 단독(전용) 코드 `PC-373`. **공용 코드는 기본으로만** — 확장으로는 넣지 않는다 `PC-374`. 하위 고객사는 상위 고객사의 그룹을 그대로 승계한다. 확장 Owner 는 `SOB-02` 에서 그 그룹에 연결해 할당한다 — 확장 Owner 는 교재를 올리는 코드가 아니라 **언어 슬롯**이다 `PC-357` |
| **티켓은 고객사용이다** | **사내에서 편집할 때는 계정도 App Key 도 필요 없다** `PC-076`. 티켓은 고객사가 우리 서비스에 로그인하거나 오프라인 툴을 쓸 때만 발급한다 |

## ② 코드 할당 — SOB-01 → SOB-02

```mermaid
flowchart TD
    A["SOB-01 SOBP 맵<br/>Section · Owner 선택"] --> B["＋ 직접 코드 할당<br/>SOB-02 창 열기"]
    B --> C{"고객사가<br/>MEM-01 에 있나"}
    C -- 없음 --> C1["MEM-02 고객사 등록"] --> C
    C -- 있음 --> D["고객사 선택<br/>기존 보유 코드 표시<br/>사용 서비스는 읽기 전용 표시"]

    D --> G1{"무겹침 · P-05<br/>이미 다른 고객사의 S/O 인가"}
    G1 -- 겹침 --> X["🔒 할당 잠금<br/>안내 후 중단"]
    G1 -- 통과 --> G2{"공유(커먼) 코드면<br/>고객사 관리에서 그 코드의<br/>사용 고객사로 체크됐나 · P-12"}
    G2 -- 아니오 --> X
    G2 -- 예 --> G3{"그 S/O 를 이미<br/>다른 코드 종류가 쓰고 있나 · OID 제외"}
    G3 -- 예 --> X
    G3 -- 아니오 --> G4{"이 고객사에 같은 Section 의<br/>확장 언어 그룹이 있나"}
    G4 -- "없음 · 연결 안 함" --> E["S/O 전체 점유 → [할당]<br/>Book · Page = 쓸 수 있는 코드 타입 중 넓은 쪽 전체"]
    G4 -- "있음 · [연결할 그룹] 선택" --> EX["확장 Owner 개수 · 방향 고르기<br/>→ [할당] · 이미 쓰는 좌표면 [그룹에 넣기]"]

    EX --> R4["MEM-02 확장 언어 그룹<br/>할당한 Owner 가 그 그룹의 다음 확장으로"]

    E --> R1["SOB-01 지도 갱신"]
    E --> R2["PRJ-01 코드발급 프로젝트 생성"]
    E --> R3["LOG-01 활동 로그 기록"]

    classDef gate fill:#fff6e5,stroke:#c98a12,color:#3a2a00;
    classDef stop fill:#ffecec,stroke:#c04a4a,color:#5a1010;
    class G1,G2,G3,G4,C gate;
    class X stop;
```

- **할당 단위 = S/O**. Owner 전체를 그 고객사가 점유한다. 빈 자리가 남아도 다른 프로젝트가 재활용하지 않는다 `P-07`.
- **연속성**: 연속 페이지가 모자라면 **book 을 분리**하고 book 안에서만 page 를 잇는다. 조각을 합치지 않는다.
- **자동 추천 없음** `PC-028` — 발급 좌표는 사람이 `SOB-01` 에서 고른다.
- **할당에는 코드 타입을 정하지 않는다** `PC-279` — Book · Page 는 그 S/O 를 쓸 수 있는 코드 타입(PDS2 · PDS3 · PDS4) 중 넓은 쪽 전체로 잡고, 코드 타입은 편집 · 키 발급에서 정한다.
- **확장 언어 그룹** `PC-357` — 그룹은 `MEM-02` 에서 **기본 코드를 골라** 만든다. `SOB-02` 는 그룹을 만들지 않고, [연결할 그룹] 을 골라 **확장 Owner 를 할당**만 한다(그 그룹의 다음 확장 순서로). 그룹이 없으면 *🌐 확장 언어 그룹 없음* 과 고객사 관리 링크만 나온다.

| 공통 | 이미 **할당된 범위 안에서만** 발급 · 다른 발급분과 SOBP 겹침 불가(겹치면 그 티켓 링크) `PC-174` `PC-225` · 수정은 발급과 같은 폼 `PC-226` · **하위 고객사 줄은 상위 공유 SOBP 만, 단독 줄은 자기 범위만** `PC-311` `PC-318` | | |

> **서비스 티켓은 편집 교재의 「사용 고객사」 를 정한다** `PC-289` — 편집 교재에서 사용 고객사를 고르지 않고, 그 교재의 S/O/B 를 덮는 서비스 티켓의 고객사 이름이 자동으로 뜬다(없으면 *티켓 없음*).

### 편집량이 들어오는 경로 3가지

## 정리 — 한 줄 흐름

여기까지가 공통이고,

```
고객사 등록(MEM) → 좌표 점유(SOB)
```

그 다음은 **누가 그 코드를 다루느냐로 갈린다.**

```
고객사가 직접 쓴다  → 키 · 티켓 발급(TKT · 서비스 티켓) → 고객사 서비스 이용 ┐
사내에서 편집한다   → 편집 프로젝트(PRJ) · 계정·키 불필요            ┘ → 집계·감사(DSH · LOG)
```

각 단계의 **선행 조건**만 기억하면 된다.

1. `SOB-02` 할당 전에 **고객사가 등록**돼 있어야 한다. 공통코드를 함께 쓰는 고객사는 할당하지 않고 `MEM-02` 에서 **하위로 등록**한다 `PC-077`.
2. `TKT-02` · `TKT-01` 발급과 서비스 티켓 지정 전에 **SOBP 가 할당**돼 있어야 한다. 단 **사내 편집에는 티켓이 필요 없다** `PC-076`.
3. `PRJ-02` 편집 관리 대상은 **고객사 관리에 등록된 고객사 전부**다 — 사용 서비스(casterN) 체크와 무관하다 `PC-187`.
4. 편집 데이터를 **장부가 못 잡으면** `PRJ-05`(고객사) · `PRJ-04`(교재) 로 **직접 등록·수정**한다.
5. 확장 언어를 쓰려면 `MEM-02` 에서 **기본 코드 1개를 골라 확장 언어 그룹**을 만들고(고객사당 하나), 확장 Owner 는 `SOB-02` 에서 그 그룹에 연결해 할당한다 `PC-357` `PC-373`. 지정하지 않은 코드는 단독(전용) 코드로 남고, 하위 고객사는 상위 그룹을 승계한다.
