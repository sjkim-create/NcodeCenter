S1Code Info · Section별 발급 범위기본
좌측 메뉴 [Ncode 정보]로 진입하면 이 Code Info 탭이 기본이다. 탭은 칩이 아니라 밑줄 탭이며 활성 탭만 파란 글씨 + 2px 밑줄이다. 표는 Section 하나당 4행(owner · bookcode · page · length)이고 SECTION 칸이 rowspan=4로 묶인다. 참조 전용 · 기능 없음 — 검증·오류 메시지가 없다. 기준: web/components/InfoView.tsx

length(판형)의 의미
  • length는 코드를 입힐 수 있는 최대 크기(판형)를 나타냅니다. (length ≒ 판형 크기)
  • 신규 프로젝트 시작 시 향후 발매 예정 콘텐츠의 판형까지 고려해 큰 사이즈가 필요하면, 그에 맞는 섹션·오너를 발행해 드립니다.
  • 초반에 작은 판형만 쓰다가 이후 큰 판형 교구에 코드 적용이 필요해지면, 신규 섹션의 코드를 발행해 펌웨어 혹은 서비스 프로그램에 추가하여 작업합니다.
  • 따라서 최대 적용 크기(판형=length)와 페이지 수를 모두 고려해야 하며, 판형 크기에 따라 섹션이 달라집니다.
※ Section 1은 테스트/개발 전용(상용 미출시).
※ Section 44 = PDS4(S-code) — owner 0~4095 · bookcode 0~255 · page 0~255 · xy 0~255 로 관리합니다 PC-042. PDS4 는 판형(length) 대신 xy 값을 가지므로 표의 마지막 행이 xy 입니다.

Ncode 코드 체계·구분 참조. (출처: 오너코드_발급리스트 + 운영 정리)

코드 종류 — 좌표(SOBP)의 속성

좌표(SOBP)가 먼저입니다. Section·Owner·Book·Page 로 코드를 지정하고, 그 좌표가 어떤 체계인지를 코드 종류로 구분합니다. 좌표는 유일하므로 코드 중복은 성립하지 않고, 해당 좌표가 PDS2·PDS3·PDS4·OID 중 무엇인지만 가리면 됩니다.

표기약칭설명
PDS3 (N3C6)NcodeN3C6의 N을 따서 Ncode. 현행 주력 코드.
PDS2 (G3C6)GcodeG3C6의 G를 따서 Gcode. 구형/호환 코드.
PDS4 (S-code)ScodeSection 44 로 발급된 좌표를 PDS4(S-code)로 구분합니다. 범위는 owner 0~4095 · book 0~255 · page 0~255 · xy 0~255 PC-042.
OID인덱스index만 갖는 코드 — 외부 코드를 우리 펜으로 읽을 목적으로 만든 방식. 좌표(SOBP) 관리 대상이 아니며 업체+index 대장(OID-01)에서 관리합니다.
IDS (A)이력초창기 A코드 — 이력 조회 전용.
신규 발급은 같은 S/O 에 한 종류만 씁니다 PC-041. 과거 혼용 이력은 그대로 표시합니다.
OID 는 index 전용이라 좌표로 관리하지 않고 업체 + index 대장(OID-01)에서 관리합니다 — 펜으로 찍으면 코드 값 1개, 총량 약 6만 개, 분량이 적으면 book 미분할.
펜 구분(소리펜 NSP · 필기펜 NWP)도 좌표 속성이며 지도·목록에서 필터로 가릅니다.

  • 필기펜 nproj는 심볼 갯수가 늘수록 서버 저장 용량도 증가 → 필기펜도 심볼 갯수 파악이 현황 확인에 도움.
  • 재무팀은 이미 편집 단가 협상 미팅을 완료해 산출 기준을 알고 있습니다.
